# 后续研究：从实验问题到方法改进

[核心实验](experiments.md)表明：局部换码有潜力，但新编码未必被生成模型学会，更新也可能影响原本表现稳定的 item。以下是待实现或待验证的方案，尚不计入当前成绩。

SID 是 item 的离散语义编码；前缀是两个任务共享的部分，后缀是各自专属的部分。当前每个任务使用两个后缀 token（模型逐个生成的符号）。相关术语也在各节就地解释。

| 改进方向 | 现有实验暴露的问题 | 要验证的收益 |
| --- | --- | --- |
| 一个 token 的任务后缀 | 第二个后缀是否必要尚未验证，同前缀组内 item 数较少 | 保留任务信息，同时减少生成步骤与编码迁移负担 |
| 教师指导学生的新旧编码兼容训练 | 旧教师只熟悉旧码；重复对齐与推荐专用附加参数未解决稳定目标退化 | 在同一 item 含义上迁移知识，并允许真实偏好适应 |
| 根据收益决定是否换码 | 漂移选择未稳定超过交互量规则，强制换码可能退化 | 只发布值得迁移的新编码，必要时保持原码 |
| 编码训练加入排序目标 | 更好的重构或更少碰撞未明确带来更好的排序 | 让编码优化更接近最终搜索/推荐效果 |

## 1. 将每个任务的后缀缩为一个 token

### 想改变什么，为什么？

保留两任务各自的后缀，将长度从两个 token 缩为一个：

```text
搜索 SID = [P1, P2 | S]
推荐 SID = [P1, P2 | R]
```

P1、P2 是共享前缀位置；S、R 分别是搜索和推荐符号。方案减少一次后缀生成决策，并使每个任务的换码集中在一个位置。它不要求两个任务共用同一个后缀。

2026-10-17 对发布映射的统计显示：MovieLens 的 18,191 个 item 分布在 12,144 个前缀组中，最大组有 16 个 item，95% 的组不超过 3 个。一个大小为 256 的后缀码本具备组内区分容量；码本是将向量表示映射到离散符号的一组中心。

但容量足够不保证任务信息充分，也不保证量化后自动没有碰撞。当前搜索后缀还分别承担查询相关性与 item 身份区分，两者合并可能损失信息。

### 怎样比较？

先只简化推荐后缀、保留搜索分支，以隔离影响；再检查两个任务都简化。

| 对照 | 检验什么 |
| --- | --- |
| 当前双层 256×256 | 已验证的基点，两层各有 256 个符号 |
| 单层 256 / 512 / 1024 | 短序列与码本容量的取舍 |
| 双层 16×16 vs 单层 256 | 名义后缀组合数均为 256，辅助区分层次结构与容量的影响 |
| 仅用前缀做诊断 | 后缀究竟提供多少额外信息；同前缀含多个 item 时须报告歧义 |

固定前缀、数据划分与训练预算，重新训练后缀编码器和初始生成模型，再走相同的时序更新流程。不能直接删掉旧编码最后一位就作为新模型比较。

检查整体与换码目标排序、稳定目标保持、碰撞和符号使用情况，并实测训练/解码时间。编码从四个 token 变成三个，不代表总延迟必然降低 25%。

### 实现需要改哪里？

当前推荐量化器接受可变层数，但保留旧码的分配脚本显式访问第二层；搜索的相关性/身份量化也要求两层。因此需调整分配、SID 导出及有效编码的前缀树约束，再检查所有 item 能否被唯一识别。这里的“前缀树”用于禁止生成不存在的编码路径。

### 参考论文与可操作的指引

**[CapsID: Soft-Routed Variable-Length Semantic IDs for Generative Recommendation](https://arxiv.org/abs/2605.05096v1)**（2026-05，预印本；重点读 §3.2、§3.3）。

- **论文做什么：** 根据编码置信度和剩余未解释信息决定何时停止增加 token，并将适合组合的相邻 token 合并，研究不同 item 是否需要不同编码长度。
- **本项目可借鉴：** 不只看同前缀组有几个 item，还要检查第一个后缀之后是否仍有重要的任务信息没有被表达。
- **差别与边界：** 它研究整个 SID 的自适应长度，不是固定共享前缀下的单任务后缀，也不直接验证时序换码。它支持研究“长度如何分配”，不能作为单后缀最优的证据。
- **第一步实验：** 先完成上面的固定单/双后缀对照，按前缀组大小、item 交互量和重构误差分组检查损失。若损失集中在少数复杂组，再考虑“多数一个后缀、少数保留两个”的扩展；需额外处理可变长度路径与唯一性。

**[Generating Long Semantic IDs in Parallel for Recommendation（RPG）](https://arxiv.org/abs/2506.05781v1)**（KDD 2025；[官方代码](https://github.com/facebookresearch/RPG_KDD2025)）。

- **论文做什么：** 用并行预测多个 token 的方式表达较长 SID，并通过图结构辅助解码，探索保留更多信息同时降低逐步生成开销。
- **本项目可借鉴：** 将“编码表达能力”和“需要多少次串行模型计算”分开评价，不能仅凭 token 更少就判断系统更好。
- **差别与边界：** 它改变了编码及解码方式，不能作为当前 T5 下删去一个 token 的直接对照，也没有解决新旧 SID 的迁移。
- **第一步实验：** 在当前 T5 下实测单/双后缀的质量、完整请求延迟和吞吐；若双后缀明显保留更多排序信息，再把并行后缀预测作为后续替代路线，单独报告架构变化。

## 2. 教师怎样指导使用新 SID 的学生？

以下设计均未实现或验证。优先修正监督对象和输入兼容性，再比较 KL 方向与是否使用学生生成路径。

### 当前实现与问题

更新前的 T5 是教师，更新中的 T5 是学生。交叉熵要求学生预测数据中的正确答案；蒸馏要求它保留教师的概率分布。当前实现用温度 T=2 的 forward KL，即 `KL(teacher || student)`，权重为 `0.1 × T²`，只在保留蒸馏的样本有效 token 上求平均。

教师与学生目前读取相同编码输入，按正确标签前缀预测下一个 token。目标或推荐历史涉及换码时，关闭整条请求的蒸馏。它没有学生自行生成轨迹的环节，因此尚不是 on-policy distillation（OPD，沿学生实际生成路径进行指导）。

这有两个局限：教师不一定理解新码；按整条请求关闭约束又可能丢掉仍有价值的旧知识。更重要的是，编码变化与偏好变化是不同维度，不能直接用“是否换码”决定旧教师是否可靠。

### 方案一：教师读旧历史，学生读新历史

对同一段用户行为建立两份输入：教师使用旧映射，学生使用新映射。例如历史中的电影 B 换码，两者仍在处理同一部电影，而不是不同上下文。

输出 SID 完全兼容的位置，可以比较 token 分布；涉及已变化后缀时，需要先建立语义对应，不能直接要求学生保持旧 token 概率。即使前缀不变，真实偏好变化也可能使教师的候选分布过时，因此保留前缀约束同样需要验证。

### 方案二：按同一 item 蒸馏，避免旧新 token 冲突

假设电影 A 的旧推荐码为 `[12,83,7,35]`，新码为 `[12,83,8,35]`。教师支持 token 7、学生学习 token 8，不一定意味着它们对电影 A 的判断不同。

可以改为在相同的小候选集合 C 中评分：

```text
教师：旧历史 → 每个候选 item 的旧 SID 序列分数
学生：新历史 → 同一候选 item 的新 SID 序列分数

Q_C = 教师分数在 C 中归一化得到的 item 分布
P_C = 学生分数在 C 中归一化得到的 item 分布
候选蒸馏目标 = KL(Q_C || P_C)
```

序列分数可由 SID 各 token 的 log probability 相加得到。候选集合、温度、终止符处理与归一化规则需一致；首轮固定当前 SID 长度，不同时加入单后缀修改。

这约束“教师和学生如何看待同一个 item”，而不是要求新码保留旧写法。它只是候选集合内的近似分布，不是全目录 KL；需比较候选覆盖、不同集合大小和额外计算成本。

### 方案三：区分编码迁移与真实偏好适应

即使按 item 比较，旧教师仍可能过时。例如用户确实不再喜欢 A，强蒸馏会把学生拉回旧偏好。候选策略应区分：

| 编码变化 | 行为关系变化 | 待验证的监督策略 |
| --- | --- | --- |
| 不变 | 较稳定 | 保留较强的教师约束 |
| 变化 | 较稳定 | 主要学习同一 item 的新写法，采用旧新映射后的 item 蒸馏 |
| 不变 | 明显变化 | 当前行为监督为主，减弱旧教师约束 |
| 变化 | 明显变化 | 同时学习新码与新偏好，教师只提供有限参照 |

行为变化必须由历史与当前数据估计，不能把下一测试窗口的真实变化当作已知。上述分组用于训练和诊断，不能根据未知正确目标决定线上推理路径。

一个可比较的训练顺序是：先做短暂迁码训练，将同一批历史行为重新编码，建立 item 与新 SID 的对应；再用当前交互适应新偏好，对变化明显的关系降低蒸馏权重。额外迁码训练必须计入预算，并与等预算的一阶段训练比较。

### 方案四：再让学生提出候选，借鉴 OPD

[GKD / On-Policy Distillation](https://arxiv.org/abs/2306.13649)用学生自生成序列覆盖其实际可能走到的路径。对本项目，先验证以下较易解释的版本：

```text
学生用新 SID 体系采样有效候选
        → 完整 SID 映射回 item
        → 教师使用这些 item 的旧 SID 评分
        → 在共同 item 集合上指导学生
```

它首先是“学生生成候选上的 item 蒸馏”，不能直接称为严格逐 token OPD：教师评分时走的是候选 item 的旧 SID 路径。如果用 beam 取候选，应描述为学生候选/难例挖掘，不能声称是无偏的 on-policy 采样。

旧教师过时的问题仍然存在，需要与方案三配合。forward / reverse KL 和 on-policy / 数据标签路径是两个独立选择：换 KL 方向不会自动成为 OPD。先在语义已对应的 item 空间保留 forward KL，再补方向消融，避免同时改变监督对象和散度。

### 首轮对照：固定 SID，只改下游训练

| 对照组 | 改动 | 要回答的问题 |
| --- | --- | --- |
| 不蒸馏 | 仅当前监督，保留相同训练数据与辅助任务 | 蒸馏是否提供额外价值 |
| 当前方案 | 同输入、整样本开关的 token KL | 复现现有基点 |
| 双输入视图 | 教师旧历史、学生新历史，在兼容输出位置保留 token KL | 输入兼容性是否重要 |
| 双视图 + item 蒸馏 | 在相同候选 item 上比较旧新 SID 分数 | 输出编码冲突是否是瓶颈 |
| 再加学生候选 | 在上一组上使用学生生成候选 | 覆盖学生实际预测是否有价值 |

分阶段检验，而不是一次叠加全部模块。先固定候选构造规则，再比较稳定性权重与训练顺序；KL 方向在监督语义对应后单独消融。

初始化、数据、SID 映射、优化步骤和 checkpoint 选择规则保持一致，额外教师前向与学生采样成本单独报告。分别检查全体推荐/搜索、换码目标、未换码目标，以及目标/历史四类受影响样本；尤其防止“换码目标改善、稳定目标却下降”。新方案只能在当前窗口内部验证与选择，然后进入未用于开发的未来窗口。

### 参考论文与可操作的指引

**[Universal Cross-Tokenizer Distillation via Approximate Likelihood Matching（ALM）](https://arxiv.org/abs/2503.20083v4)**（NeurIPS 2025；[官方代码 TokenKit](https://github.com/bminixhofer/tokenkit)；重点读 §3）。

- **论文做什么：** 教师与学生使用不同文本分词器时，将表达相同文本片段的 token 组合对应起来，比较片段的似然，而不是直接逐词表位置匹配概率。
- **本项目可借鉴：** 对齐监督应先找到共同含义。对本项目，共同对象可以是同一个 item：旧教师对旧 SID 评分，新学生对新 SID 评分，再在共同候选集合中比较。
- **差别与边界：** 文本片段可通过字符或字节建立对应，SID 的数字符号没有这种关系，必须使用保存的旧新 item 映射。上面的候选 item KL 是借鉴后的新提案，不是 ALM 的原始算法。
- **第一步实验：** 固定同一批候选、SID 长度和训练预算，比较 token 蒸馏与 item 蒸馏；逐步增加候选数量，检查排序保持、候选覆盖及教师评分成本。先排除输出含义错位，再考虑 KL 方向。

**[Rethinking Cross-Tokenizer On-Policy Distillation: From Alignment Coverage to Supervision Reliability](https://arxiv.org/abs/2610.08448v1)**（2026-10，预印本；重点读 §3–5）。

- **论文做什么：** 在学生生成文本上，比较只监督严格对应的位置与补充不匹配片段监督。所测设置中，更广的监督覆盖未必更好；额外片段监督可能与原有监督产生梯度冲突。其严格位置目标使用 reverse KL，即 `KL(student || teacher)`。
- **本项目可借鉴：** 不必从“整条关闭蒸馏”直接跳到“所有位置都蒸馏”。可以先保留含义可靠的约束，再检查新增监督究竟帮助还是干扰当前行为学习。
- **差别与边界：** 该文测试的是文本任务，没有处理推荐偏好随时间变化的问题。SID 中相同 token 数字也不保证含义仍相同；不能照搬其共享词表筛选或 top-16 设置，更不能由此断定本项目应该改用 reverse KL。
- **第一步实验：** 在同一监督空间内比较可靠位置约束、加入 item 蒸馏及稳定性权重，记录蒸馏与当前交叉熵的梯度方向、相对大小；固定其余因素后再比较 forward/reverse KL，最后才加入学生采样候选。

上文 [GKD](https://arxiv.org/abs/2306.13649)（ICLR 2024）保留为理解 OPD 的基础阅读；近期两篇分别帮助思考“怎样对应新旧编码”和“哪些教师监督可靠”，并不消除旧教师偏好过时的问题。

## 3. 换码前，估计排序收益是否值得迁移

现在选择候选主要看行为变化和交互量；最终分配主要限制无必要切换与编码碰撞。它们没有直接回答“有限下游训练后，新码能否带来收益”。

待验证的决策目标为：

```text
换码价值 = 估计的排序收益
           − 编码迁移成本
           − 对稳定样本的负面影响
```

仅在价值足够高、预算与唯一性约束满足时发布新码，允许整个窗口不更新。成本还应考虑该 item 在目标和历史中出现的次数，以及是否反复换码，而不只统计换了几个 item。

收益估计可以用当前窗口内部留出的验证数据和小预算训练；下一测试窗口不能用于挑选。比较旧、新候选时需给同等适配预算，避免旧模型熟悉旧码造成偏置。额外试训成本也要计入总成本。

KuaiSAR 已做过保守过滤实验，避免了退化，但目标覆盖太少，未证明上述完整策略的正向收益。[现有结果](experiments.md)

### 参考论文与可操作的指引

**[Drift-Aware Continual Tokenization for Generative Recommendation（DACT）](https://arxiv.org/abs/2603.29705v1)**（2026-03，预印本；[官方代码](https://github.com/HomesAmaranta/DACT)；重点读 §3.1–3.2）。

- **论文做什么：** 学习 item 的协同行为漂移置信度，区别优化变化与稳定 item，再通过分层重分配限制不必要的编码变化。
- **本项目可借鉴：** 把“判断哪些 item 变化”和“最终怎样分配新码”分别做对照，并检查稳定 item 是否被保护，而不只统计换码数量。
- **差别与边界：** 漂移置信度不等于有限适配预算下的排序净收益。该文按高置信度选择 top-K item，不能直接当作允许整个窗口不更新的收益门槛。
- **第一步实验：** 固定选择预算和下游训练预算，先比较当前规则、交互量规则与 DACT；再单独增加基于当前验证数据的收益过滤，判断优势来自漂移检测还是发布决策。记录选择数、实际换码数与过滤成本。

**[Mitigating Collaborative Semantic ID Staleness in Generative Retrieval](https://arxiv.org/abs/2604.13273v1)**（SIGIR 2026；重点读 §3.2、§4.3）。

- **论文做什么：** 从近期日志刷新协同 SID，依据共同 item 上的新旧 token 对应关系，使用贪心或匈牙利匹配重新命名新 token，再从旧生成模型继续训练；同时进行严格时间顺序和重复更新评价。
- **本项目可借鉴：** 将“SID 结构真的变化”与“仅仅换了 token 名字”分开处理，降低无必要的迁移，并建立充分训练的刷新对齐基线。
- **差别与边界：** 保持词表兼容不等于所有 item 的 SID 不变，也不等于已经解决教师蒸馏或逐 item 的发布收益。其逐码本 token 匹配，与本项目同前缀组内的 item 编码分配，匹配对象不同。
- **第一步实验：** 加入“刷新 SID → token 对齐 → 旧模型继续训练”基线，对比固定 SID、完整重训及选择性发布。既给等预算结果，也画适配预算曲线，检查收益能否覆盖刷新和对齐成本。

## 4. 让编码学习更直接地服务排序

重构目标检查编码能否还原输入向量；拓扑目标检查 item 邻近关系是否保留；它们并不直接检查“给定用户历史，正确目标能否排得更靠前”。

优先固定当前共享前缀与搜索分支，在推荐后缀中比较：

1. 加入根据历史区分正确/错误目标的排序或对比监督。
2. 分开训练、少量交替训练，以及可微量化近似之间的取舍。
3. 正确前缀是否已进入生成候选；若此前缀被过早排除，仅改后缀无法补救。

需要同时检查符号是否集中到少数中心、稳定 item 是否被迫换码。面向下游目标的 SID 已有 [DIGER](https://arxiv.org/abs/2601.19711) 等研究；OneRec 的偏好对齐也提供目标层面的启发，但并不自动解决新旧 SID 兼容问题。[背景与研究联系](background.md)

前缀结构变体的实验同样需要解释：共识前缀（历史名 P2）减少任务信息进入前缀后出现退化，因此先诊断融合权重与正确前缀覆盖率，再决定是否改共享结构。具体变体见[方法](method.md)。

### 参考论文与可操作的指引

**[Generative Recommender with End-to-End Learnable Item Tokenization（ETEGRec）](https://arxiv.org/abs/2409.05546v3)**（SIGIR 2025，首版预印本为 2024 年；[官方代码](https://github.com/RUCAIBox/ETEGRec)；重点读 §3.3–3.4）。

- **论文做什么：** 让用户历史表示与目标 item 在编码分布上对应，让生成模型的偏好表示与 item 语义表示对应，并交替更新编码器和推荐模型，以缓解两阶段训练的目标脱节。
- **本项目可借鉴：** 不必一开始就让所有参数同时变化。可以先在固定前缀下，让推荐后缀接收来自用户历史与目标 item 的监督，再交替训练后缀和 T5。
- **差别与边界：** 它主要解决编码器与推荐器如何一起学好，并非围绕已发布 SID 的局部迁移设计；交替训练本身也不保证稳定 item 的编码不变。
- **第一步实验：** 比较当前重构/拓扑目标、增加历史条件对齐、再增加少量交替训练三组；固定搜索分支，分别测编码排序价值、发布换码量和 T5 适配后的收益。

**[Differentiable Semantic ID for Generative Recommendation（DIGER）](https://arxiv.org/abs/2601.19711v3)**（SIGIR 2026；[官方代码](https://github.com/junchen-fu/DIGER)；重点读 §4.1–4.3）。

- **论文做什么：** 用可微的软分配让推荐训练梯度影响 SID 学习，通过 Gumbel 随机扰动促进早期探索，再逐渐减小扰动，缓解码本只使用少数符号的塌缩。
- **本项目可借鉴：** 对比“辅助对齐目标影响后缀”和“最终推荐损失直接影响后缀”两条路线，同时监控符号使用与训练、推理时编码是否一致。
- **差别与边界：** 其联合优化并不自动满足本项目共享前缀冻结、未选 item 保持原码及跨任务稳定要求；直接全量更新码本可能扩大迁移范围。
- **第一步实验：** 先仅对推荐后缀尝试可微近似，固定共享前缀与搜索分支；与等预算交替训练比较，报告码本使用、碰撞、稳定 item 换码量、排序和额外开销，再决定是否放开更多参数。

## 5. 怎样区分“换码更好”与“训练对齐更好”？

| 对照组 | 编码选择与发布 | 下游对齐训练 | 要回答的问题 |
| --- | --- | --- | --- |
| 当前方法 | 当前方案 | 当前方案 | 建立可复现基点 |
| 仅改对齐 | 当前方案 | 改进方案 | 新旧编码兼容训练是否有效 |
| 仅改换码决策 | 按收益与迁移成本选择 | 当前方案 | 编码决策是否有效 |
| 同时改两者 | 改进方案 | 改进方案 | 两者能否互补 |

在冻结推荐码本与允许码本刷新两条路线上分别验证，保持数据、候选池、初始化和预算一致。它们在原文件中名为 TASR-A/B；TASR 是未定义英文全称的历史系列代号，[组件差异](method.md)以具体实现为准。

单后缀属于结构实验，应先独立验证，再与上述训练改进组合，避免一次改太多因素。新规则固定后，进入尚未用于开发的未来窗口测试。

**文献怎样用于这组实验：** [协同 SID 对齐更新](https://arxiv.org/abs/2604.13273v1)提供“先消除 token 命名错位，再继续训练”的对照；[DIGER](https://arxiv.org/abs/2601.19711v3)提供“让下游目标改变编码学习”的对照。两者处理不同环节，因此要分别测试，再验证组合效果，不能将组合收益全部归因于换码规则。

## 6. 需要补充的实验

| 顺序 | 实验 | 核心要求 |
| --- | --- | --- |
| 首先 | 关键结果复现 | 独立 Linux 环境、固定数据与模型版本、明确运行步骤，重跑静态和时序结果 |
| 首先 | 更完整的公平基线 | 固定编码、随机选择、按交互量选择、完整刷新、[刷新后 token 对齐](https://arxiv.org/abs/2604.13273v1)，以及 [DACT 持续编码](https://arxiv.org/abs/2603.29705v1)；统一时间划分与训练预算 |
| 首先 | 独立未来窗口 | 固定选择与发布规则；多个连续窗口，区分首次换码与重复换码 |
| 首先 | 新旧编码训练消融 | 比较教师输入、样本开关、逐位置约束，以及按 token 或按 item 对齐 |
| 随后 | 完整随机性 | 分别重训表示、SID 和初始生成模型；当前三个增量种子只覆盖最后更新阶段 |
| 随后 | 漂移强度与预算曲线 | 无漂移到强漂移；控制选择数、实际换码数、对齐与回放预算 |
| 随后 | 更充分的自然日志 | 时间跨度长、同一 item 跨窗重复充分，优先真实联合搜推；区分合成搜索与真实搜索 |
| 随后 | 全目录排序与规模 | 在 99/999 个负候选之外评估全目录召回与排序、有效编码比例和生成开销 |
| 随后 | 全流程效率 | 分列表示、检测、编码训练、映射发布、下游训练与推理的时间/显存，而非只报小模块时间 |
| 机制明确后 | 前缀结构 | 检查任务信息是否保留、融合权重是否失效、正确前缀是否进入候选，再比较结构修改 |

“完整刷新”基线需要合理的下游适配预算；近全目录换码后只给极少训练的失败，不能替代充分训练的性能上界。

**优先参考的实验协议：** [协同 SID 对齐更新](https://arxiv.org/abs/2604.13273v1)的 §4.3 按“当前时间块更新、下一时间块测试”研究重复适配；[DACT](https://arxiv.org/abs/2603.29705v1)的 §4 可用于构建持续编码对照。复用到本项目时，仍需额外区分真实/合成搜索、稳定/换码集合，以及两个任务的相互影响。

## 7. 以什么判断改进成立？

同时报告整体搜索/推荐、同一换码目标集合和稳定集合、碰撞、反复换码、无变化窗口保持，以及全部新增成本。子集收益、另一任务保持和整体收益需要分别测量。

在开发窗口预先固定主要指标和允许退化范围，并估计样本层面的不确定性。当前 26.46% 的受控搜索子集增益与 0.12% 的自然推荐整体增益来自不同实验，不能混合成一个方法提升数字。

**阅读后的评价重点：** 结合 [RPG](https://arxiv.org/abs/2506.05781v1)对表达能力与生成效率的研究，以及[协同 SID 对齐更新](https://arxiv.org/abs/2604.13273v1)对刷新后持续适配的研究，同时评价“效果、迁移、推理”三方面。本项目的稳定集合、两任务保持和全流程成本要求，是面向当前问题补充的评价设计，不是这些论文已经证明的结论。

### 建议的推进顺序

先完成第 2 节的旧新输入与 item 蒸馏对照，因为它可以固定 SID，直接检查“新码未被下游学会”是否是瓶颈；同时建立第 3 节的 DACT 与刷新对齐基线。在此基础上验证收益过滤，再研究第 4 节的编码排序目标。第 1 节的单后缀可以作为独立结构实验并行安排，但与其他改进组合前，应先确认自身的效果与成本。这一顺序是依据当前实验瓶颈提出的项目建议，不是论文给出的统一结论。
