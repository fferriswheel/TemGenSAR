# 后续研究：从实验问题到方法改进

[核心实验](experiments.md)表明：局部换码有潜力，但新编码未必被生成模型学会，更新也可能影响原本表现稳定的 item。以下是待实现或待验证的方案，尚不计入当前成绩。

SID 是 item 的离散语义编码；前缀是两个任务共享的部分，后缀是各自专属的部分。当前每个任务使用两个后缀 token（模型逐个生成的符号）。相关术语也在各节就地解释。

| 改进方向 | 现有实验暴露的问题 | 要验证的收益 |
| --- | --- | --- |
| 一个 token 的任务后缀 | 第二个后缀是否必要尚未验证，同前缀组内 item 数较少 | 保留任务信息，同时减少生成步骤与编码迁移负担 |
| 教师指导学生的新旧编码兼容训练 | 旧教师只熟悉旧码；重复对齐与推荐专用附加参数未解决稳定目标退化 | 在同一 item 含义上迁移知识，并允许真实偏好适应 |
| 根据收益决定是否换码 | 漂移选择未稳定超过交互量规则，强制换码可能退化 | 只发布值得迁移的新编码，必要时保持原码 |
| 编码训练加入排序目标 | 更好的重构或更少碰撞未明确带来更好的排序 | 让编码优化更接近最终搜索/推荐效果 |

### 从已有问题中筛选可验证的方法

候选方案有两类来源：一类是当前实验暴露的问题，例如稳定目标退化、强制换码无收益；另一类是论文或技术报告中可以迁移的具体机制。选择参考工作的标准是能否导出明确的实现与对照实验。以下按方法组织，只在实际借用机制处注明来源；相关模块仍待实现或验证。

| 候选方法 | 为什么值得尝试 | 来源与适用程度 |
| --- | --- | --- |
| 教师读旧历史、学生读新历史，在相同 item 上蒸馏 | 保留同一 item 的知识，同时允许其 SID 写法改变 | 当前实现问题导出的提案；跨分词器蒸馏提供间接启发 |
| 区分迁码训练与新偏好学习 | 旧教师可能知道旧码，却不再代表当前偏好 | 本项目的时序适配假设，需要独立验证 |
| 先消除纯 token 重命名，再评估是否发布新码 | 减少无语义收益的迁移，把预算留给有价值的变化 | token 对齐可直接借鉴已有 SID 更新方法；收益过滤是本项目提案 |
| 交替更新推荐后缀与生成模型 | 让编码接收下游监督，又避免两个模块同时剧烈变化 | 可借鉴 ETEGRec 的训练机制，需增加局部发布约束 |
| 对推荐后缀尝试可微量化 | 检验最终推荐损失直接影响编码是否更有效 | 可借鉴 DIGER；实现复杂度与编码稳定性风险较高 |
| 单后缀与双后缀对照 | 检查当前结构是否存在冗余 | 来自组内 item 数与当前编码结构的项目假设，先做消融 |

## 1. 将每个任务的后缀缩为一个 token

### 想改变什么，为什么？

保留两任务各自的后缀，将长度从两个 token 缩为一个：

```text
搜索 SID = [P1, P2 | S]
推荐 SID = [P1, P2 | R]
```

P1、P2 是共享前缀位置；S、R 分别是搜索和推荐符号。方案减少一次后缀生成决策，并使每个任务的换码集中在一个位置。它不要求两个任务共用同一个后缀。

2026-10-17 对发布映射的统计显示：MovieLens 的 18,191 个 item 分布在 12,144 个前缀组中，最大组有 16 个 item，95% 的组不超过 3 个。一个大小为 256 的后缀码本具备组内区分容量；码本是将向量表示映射到离散符号的一组中心。

但容量足够不保证任务信息充分，也不保证量化后自动没有碰撞。当前搜索后缀还分别承担查询相关性与 item 身份区分，两者合并可能损失信息。

### 怎样比较？

先只简化推荐后缀、保留搜索分支，以隔离影响；再检查两个任务都简化。

| 对照 | 检验什么 |
| --- | --- |
| 当前双层 256×256 | 已验证的基点，两层各有 256 个符号 |
| 单层 256 / 512 / 1024 | 短序列与码本容量的取舍 |
| 双层 16×16 vs 单层 256 | 名义后缀组合数均为 256，辅助区分层次结构与容量的影响 |
| 仅用前缀做诊断 | 后缀究竟提供多少额外信息；同前缀含多个 item 时须报告歧义 |

固定前缀、数据划分与训练预算，重新训练后缀编码器和初始生成模型，再走相同的时序更新流程。不能直接删掉旧编码最后一位就作为新模型比较。

检查整体与换码目标排序、稳定目标保持、碰撞和符号使用情况，并实测训练/解码时间。编码从四个 token 变成三个，不代表总延迟必然降低 25%。

### 实现需要改哪里？

当前推荐量化器接受可变层数，但保留旧码的分配脚本显式访问第二层；搜索的相关性/身份量化也要求两层。因此需调整分配、SID 导出及有效编码的前缀树约束，再检查所有 item 能否被唯一识别。这里的“前缀树”用于禁止生成不存在的编码路径。

### 这一步的定位与后续决策

单后缀首先是结构消融：用更简单的结构检查第二个后缀是否提供有效信息。它的依据是当前前缀组规模与实际实验，不预设单后缀更优。除总体结果外，按前缀组大小、item 交互量和量化重构误差分组检查信息损失。

若单后缀保留排序效果且降低实测成本，再进入时序换码实验；若明显损害排序，先定位损失集中在哪些 item，再决定保留双后缀或研究按需增加编码长度。暂不同时引入可变长度或并行解码，以保持结论可解释。

## 2. 教师怎样指导使用新 SID 的学生？

以下设计均未实现或验证。优先修正监督对象和输入兼容性，再比较 KL 方向与是否使用学生生成路径。

### 当前实现与问题

更新前的 T5 是教师，更新中的 T5 是学生。交叉熵要求学生预测数据中的正确答案；蒸馏要求它保留教师的概率分布。当前实现用温度 T=2 的 forward KL，即 `KL(teacher || student)`，权重为 `0.1 × T²`，只在保留蒸馏的样本有效 token 上求平均。

教师与学生目前读取相同编码输入，按正确标签前缀预测下一个 token。目标或推荐历史涉及换码时，关闭整条请求的蒸馏。它没有学生自行生成轨迹的环节，因此尚不是 on-policy distillation（OPD，沿学生实际生成路径进行指导）。

这有两个局限：教师不一定理解新码；按整条请求关闭约束又可能丢掉仍有价值的旧知识。更重要的是，编码变化与偏好变化是不同维度，不能直接用“是否换码”决定旧教师是否可靠。

### 方案一：教师读旧历史，学生读新历史

对同一段用户行为建立两份输入：教师使用旧映射，学生使用新映射。例如历史中的电影 B 换码，两者仍在处理同一部电影，而不是不同上下文。

输出 SID 完全兼容的位置，可以比较 token 分布；涉及已变化后缀时，需要先建立语义对应，不能直接要求学生保持旧 token 概率。即使前缀不变，真实偏好变化也可能使教师的候选分布过时，因此保留前缀约束同样需要验证。

### 方案二：按同一 item 蒸馏，避免旧新 token 冲突

假设电影 A 的旧推荐码为 `[12,83,7,35]`，新码为 `[12,83,8,35]`。教师支持 token 7、学生学习 token 8，不一定意味着它们对电影 A 的判断不同。

可以改为在相同的小候选集合 C 中评分：

```text
教师：旧历史 → 每个候选 item 的旧 SID 序列分数
学生：新历史 → 同一候选 item 的新 SID 序列分数

Q_C = 教师分数在 C 中归一化得到的 item 分布
P_C = 学生分数在 C 中归一化得到的 item 分布
候选蒸馏目标 = KL(Q_C || P_C)
```

序列分数可由 SID 各 token 的 log probability 相加得到。候选集合、温度、终止符处理与归一化规则需一致；首轮固定当前 SID 长度，不同时加入单后缀修改。

这约束“教师和学生如何看待同一个 item”，而不是要求新码保留旧写法。它只是候选集合内的近似分布，不是全目录 KL；需比较候选覆盖、不同集合大小和额外计算成本。

### 方案三：区分编码迁移与真实偏好适应

即使按 item 比较，旧教师仍可能过时。例如用户确实不再喜欢 A，强蒸馏会把学生拉回旧偏好。候选策略应区分：

| 编码变化 | 行为关系变化 | 待验证的监督策略 |
| --- | --- | --- |
| 不变 | 较稳定 | 保留较强的教师约束 |
| 变化 | 较稳定 | 主要学习同一 item 的新写法，采用旧新映射后的 item 蒸馏 |
| 不变 | 明显变化 | 当前行为监督为主，减弱旧教师约束 |
| 变化 | 明显变化 | 同时学习新码与新偏好，教师只提供有限参照 |

行为变化必须由历史与当前数据估计，不能把下一测试窗口的真实变化当作已知。上述分组用于训练和诊断，不能根据未知正确目标决定线上推理路径。

一个可比较的训练顺序是：先做短暂迁码训练，将同一批历史行为重新编码，建立 item 与新 SID 的对应；再用当前交互适应新偏好，对变化明显的关系降低蒸馏权重。额外迁码训练必须计入预算，并与等预算的一阶段训练比较。

### 方案四：再让学生提出候选，借鉴 OPD

[GKD / On-Policy Distillation](https://arxiv.org/abs/2306.13649)用学生自生成序列覆盖其实际可能走到的路径。对本项目，先验证以下较易解释的版本：

```text
学生用新 SID 体系采样有效候选
        → 完整 SID 映射回 item
        → 教师使用这些 item 的旧 SID 评分
        → 在共同 item 集合上指导学生
```

它首先是“学生生成候选上的 item 蒸馏”，不能直接称为严格逐 token OPD：教师评分时走的是候选 item 的旧 SID 路径。如果用 beam 取候选，应描述为学生候选/难例挖掘，不能声称是无偏的 on-policy 采样。

旧教师过时的问题仍然存在，需要与方案三配合。forward / reverse KL 和 on-policy / 数据标签路径是两个独立选择：换 KL 方向不会自动成为 OPD。先在语义已对应的 item 空间保留 forward KL，再补方向消融，避免同时改变监督对象和散度。

### 首轮对照：固定 SID，只改下游训练

| 对照组 | 改动 | 要回答的问题 |
| --- | --- | --- |
| 不蒸馏 | 仅当前监督，保留相同训练数据与辅助任务 | 蒸馏是否提供额外价值 |
| 当前方案 | 同输入、整样本开关的 token KL | 复现现有基点 |
| 双输入视图 | 教师旧历史、学生新历史，在兼容输出位置保留 token KL | 输入兼容性是否重要 |
| 双视图 + item 蒸馏 | 在相同候选 item 上比较旧新 SID 分数 | 输出编码冲突是否是瓶颈 |
| 再加学生候选 | 在上一组上使用学生生成候选 | 覆盖学生实际预测是否有价值 |

分阶段检验，而不是一次叠加全部模块。先固定候选构造规则，再比较稳定性权重与训练顺序；KL 方向在监督语义对应后单独消融。

初始化、数据、SID 映射、优化步骤和 checkpoint 选择规则保持一致，额外教师前向与学生采样成本单独报告。分别检查全体推荐/搜索、换码目标、未换码目标，以及目标/历史四类受影响样本；尤其防止“换码目标改善、稳定目标却下降”。新方案只能在当前窗口内部验证与选择，然后进入未用于开发的未来窗口。

### 从跨编码蒸馏中提炼的方法

[ALM：Universal Cross-Tokenizer Distillation via Approximate Likelihood Matching](https://arxiv.org/abs/2503.20083v4)（NeurIPS 2025，§3；[官方代码](https://github.com/bminixhofer/tokenkit)）先找到表示同一文本片段的 token 组合，再比较其似然。可迁移的原则是：**先建立共同含义，再决定怎样匹配概率。**

由此可以形成上面的方案二：将旧新 SID 都还原到同一 item 身份，在共同候选集合中蒸馏。这是对当前问题的改造，不是直接复现 ALM；SID 没有可供字符对齐的文本含义，必须使用旧新 item 映射，也不需要照搬其片段损失。

首轮实现可限定为：教师旧历史、学生新历史；候选包括当前监督目标、教师高分项、学生高分项及少量随机项，去重后让两者对完全相同的 item 集合评分。比较同容量的随机候选与混合候选，并逐步增加候选数，检查覆盖和成本。候选只由训练数据与当前模型构建；“学生高分项”仍是候选挖掘，真正的学生采样放在后续独立实验。

如果 item 蒸馏仍阻碍新偏好学习，再验证方案三的两阶段训练与蒸馏权重。权重由历史和当前窗口的行为稳定性估计，并与固定权重、无蒸馏比较。先不增加复杂的教师打分器；出现冲突时，可用蒸馏与当前监督的梯度方向和相对大小辅助诊断。这部分是本项目的适配假设，需要未来窗口结果支持。

## 3. 换码前，估计排序收益是否值得迁移

现在选择候选主要看行为变化和交互量；最终分配主要限制无必要切换与编码碰撞。它们没有直接回答“有限下游训练后，新码能否带来收益”。

待验证的决策目标为：

```text
换码价值 = 估计的排序收益
           − 编码迁移成本
           − 对稳定样本的负面影响
```

仅在价值足够高、预算与唯一性约束满足时发布新码，允许整个窗口不更新。成本还应考虑该 item 在目标和历史中出现的次数，以及是否反复换码，而不只统计换了几个 item。

收益估计可以用当前窗口内部留出的验证数据和小预算训练；下一测试窗口不能用于挑选。比较旧、新候选时需给同等适配预算，避免旧模型熟悉旧码造成偏置。额外试训成本也要计入总成本。

KuaiSAR 已做过保守过滤实验，避免了退化，但目标覆盖太少，未证明上述完整策略的正向收益。[现有结果](experiments.md)

### 可直接借用：先对齐 token 名字，再计算迁移量

码本刷新后，一部分变化可能只是中心编号互换，未必代表 item 之间的语义关系真的改变。[Mitigating Collaborative Semantic ID Staleness in Generative Retrieval](https://arxiv.org/abs/2604.13273v1)（SIGIR 2026，§3.2）提供了具体机制：统计共同 item 上新旧 token 的共现，逐编码位置做一对一匹配，再用旧 token 名字重写新码，从旧生成模型继续训练。

对本项目可以先在允许推荐码本刷新的分支中验证：固定共享前缀与搜索分支，只对推荐后缀做这种重新命名，比较匹配前后的换码数和等预算下游效果。命名映射需对相应位置全局一致；若它与未选 item 必须保持原码的发布约束冲突，先作为独立刷新基线，不直接并入当前发布流程。它匹配的是 token，不是当前同前缀组内的 item 编码分配。

### 本项目进一步提出：有证据收益时才发布

在当前窗口内部按时间留出验证段，从同一旧模型出发，对原码和候选新码分别给予相同的小预算适配。先做最简单的发布规则：候选新码在主要指标上有足够改善，且稳定集合和搜索侧没有越过预设退化范围，才继续发布；覆盖不足或无法区分时保持原码。收益门槛在开发窗口固定，全部试训开销计入成本。

第一轮先检验一个窗口是否值得更新，避免用少量 item 的稀疏验证收益直接训练复杂预测器。验证规则有效后，再研究组级收益估计与分配预算。这是由当前实验导出的方案，已有论文不构成其有效性证明。

[DACT](https://arxiv.org/abs/2603.29705v1)（2026-03，预印本，§3.1–3.2；[官方代码](https://github.com/HomesAmaranta/DACT)）学习漂移置信度并区别优化变化/稳定 item，适合作为检测与持续编码的对照。其 top-K 漂移选择与上述收益发布门槛回答不同问题，需分开比较。

## 4. 让编码学习更直接地服务排序

重构目标检查编码能否还原输入向量；拓扑目标检查 item 邻近关系是否保留；它们并不直接检查“给定用户历史，正确目标能否排得更靠前”。

优先固定当前共享前缀与搜索分支，在推荐后缀中比较：

1. 加入根据历史区分正确/错误目标的排序或对比监督。
2. 分开训练、少量交替训练，以及可微量化近似之间的取舍。
3. 正确前缀是否已进入生成候选；若此前缀被过早排除，仅改后缀无法补救。

需要同时检查符号是否集中到少数中心、稳定 item 是否被迫换码。初期只选择一种方式把下游监督引入推荐后缀，并明确辅助对齐、生成目标与真正的候选排序损失之间的差别。

前缀结构变体的实验同样需要解释：共识前缀（历史名 P2）减少任务信息进入前缀后出现退化，因此先诊断融合权重与正确前缀覆盖率，再决定是否改共享结构。具体变体见[方法](method.md)。

### 优先尝试：后缀与生成模型交替训练

[ETEGRec](https://arxiv.org/abs/2409.05546v3)（SIGIR 2025，§3.3–3.4；[官方代码](https://github.com/RUCAIBox/ETEGRec)）将用户历史和目标 item 的编码分布对齐，将生成模型的偏好表示与 item 语义表示对齐，再交替优化编码器与推荐器。可借鉴的是这种连接目标与训练顺序。

对本项目，先固定前缀与搜索分支，从当前 T5 提取用户历史表示，与目标 item 的推荐后缀软分配建立对应；软分配表示 item 选择各后缀符号的概率。第一阶段固定 T5，只训练后缀，使它既保留原有表示信息，也更符合历史条件下的目标；第二阶段固定候选 SID，训练 T5 适应这些编码。先只做一轮交替，与无对齐、仅增加对齐目标比较。

这仍需改造：ETEGRec 没有替本项目约束未选 item 的部署编码。训练结束后仍要经过唯一性和保持原码的发布规则，并在最终固定映射上完成下游适配；若收益在受约束发布后消失，就不能只报告自由更新时的成绩。额外阶段与对齐目标都必须计入训练预算。

### 后续备选：让推荐损失直接影响量化选择

[DIGER](https://arxiv.org/abs/2601.19711v3)（SIGIR 2026，§4.1–4.3；[官方代码](https://github.com/junchen-fu/DIGER)）通过可微软分配传递推荐训练梯度，早期用 Gumbel 扰动探索符号，后期减小扰动以趋向稳定。这给出了比辅助对齐更直接的路线。

若上一种方案显示编码目标确实是瓶颈，再仅在推荐后缀尝试软分配与扰动衰减，前缀和搜索分支保持固定。比较等预算交替训练和可微训练；同时记录符号使用、碰撞、训练/推理编码差异，以及发布约束后的排序收益。若全量码本更新使未选 item 大量换码，应先限制更新范围或停止放开更多参数。该路线复杂度更高，不作为首轮实验的必选模块。

## 5. 怎样区分“换码更好”与“训练对齐更好”？

| 对照组 | 编码选择与发布 | 下游对齐训练 | 要回答的问题 |
| --- | --- | --- | --- |
| 当前方法 | 当前方案 | 当前方案 | 建立可复现基点 |
| 仅改对齐 | 当前方案 | 改进方案 | 新旧编码兼容训练是否有效 |
| 仅改换码决策 | 按收益与迁移成本选择 | 当前方案 | 编码决策是否有效 |
| 同时改两者 | 改进方案 | 改进方案 | 两者能否互补 |

在冻结推荐码本与允许码本刷新两条路线上分别验证，保持数据、候选池、初始化和预算一致。它们在原文件中名为 TASR-A/B；TASR 是未定义英文全称的历史系列代号，[组件差异](method.md)以具体实现为准。

单后缀属于结构实验，应先独立验证，再与上述训练改进组合，避免一次改太多因素。新规则固定后，进入尚未用于开发的未来窗口测试。

## 6. 需要补充的实验

| 顺序 | 实验 | 核心要求 |
| --- | --- | --- |
| 首先 | 关键结果复现 | 独立 Linux 环境、固定数据与模型版本、明确运行步骤，重跑静态和时序结果 |
| 首先 | 更完整的公平基线 | 固定编码、随机选择、按交互量选择、完整刷新、[刷新后 token 对齐](https://arxiv.org/abs/2604.13273v1)，以及 [DACT 持续编码](https://arxiv.org/abs/2603.29705v1)；统一时间划分与训练预算 |
| 首先 | 独立未来窗口 | 固定选择与发布规则；多个连续窗口，区分首次换码与重复换码 |
| 首先 | 新旧编码训练消融 | 比较教师输入、样本开关、逐位置约束，以及按 token 或按 item 对齐 |
| 随后 | 完整随机性 | 分别重训表示、SID 和初始生成模型；当前三个增量种子只覆盖最后更新阶段 |
| 随后 | 漂移强度与预算曲线 | 无漂移到强漂移；控制选择数、实际换码数、对齐与回放预算 |
| 随后 | 更充分的自然日志 | 时间跨度长、同一 item 跨窗重复充分，优先真实联合搜推；区分合成搜索与真实搜索 |
| 随后 | 全目录排序与规模 | 在 99/999 个负候选之外评估全目录召回与排序、有效编码比例和生成开销 |
| 随后 | 全流程效率 | 分列表示、检测、编码训练、映射发布、下游训练与推理的时间/显存，而非只报小模块时间 |
| 机制明确后 | 前缀结构 | 检查任务信息是否保留、融合权重是否失效、正确前缀是否进入候选，再比较结构修改 |

“完整刷新”基线需要合理的下游适配预算；近全目录换码后只给极少训练的失败，不能替代充分训练的性能上界。

## 7. 以什么判断改进成立？

同时报告整体搜索/推荐、同一换码目标集合和稳定集合、碰撞、反复换码、无变化窗口保持，以及全部新增成本。子集收益、另一任务保持和整体收益需要分别测量。

在开发窗口预先固定主要指标和允许退化范围，并估计样本层面的不确定性。当前 26.46% 的受控搜索子集增益与 0.12% 的自然推荐整体增益来自不同实验，不能混合成一个方法提升数字。

### 建议的推进顺序

先完成第 2 节的旧新输入与 item 蒸馏对照，固定同一候选 SID 映射，直接检查“新码未被下游学会”是否是瓶颈；同时建立第 3 节的 DACT 与刷新对齐基线。在此基础上验证简单的收益发布规则，再研究第 4 节的后缀交替训练。只有前面实验显示有必要，才引入更复杂的学生采样或可微量化。第 1 节的单后缀独立验证，确认自身效果与成本后再组合。

每一步都应回答一个具体问题；若简单方案已解决该问题，就不因存在相关论文而继续增加模块。
