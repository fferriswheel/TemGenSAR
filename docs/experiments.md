# 核心实验：从静态编码到时序适应

核心问题是：**搜索和推荐共用一个生成模型时，如何更新已经过时的 item 编码，既改善当前排序，又保住原有能力？**

实验围绕这个问题逐步展开：先验证编码结构，再验证更新策略，接着定位收益与失败原因，最后检查它在自然变化的数据上是否成立。这里按研究问题组织实验；完整配置、逐 seed 数值和统计检验集中在[实验细节](experiment-details.md)，历史记录中的方法代号见[术语与名称对照](glossary.md)。

## 阅读前：三个必要概念

**SID 是 item 的离散编码。** 当前方法给每个 item 分配“两个共享前缀 token + 两个任务后缀 token”。搜索和推荐使用相同前缀、不同后缀。例如，同一部电影的搜索编码为 `[P1,P2,S1,S2]`，推荐编码为 `[P1,P2,R1,R2]`。

**换码是改变 item 的 SID。** 行为变化后，可以只改推荐后缀、保留搜索编码。下游生成模型也必须适应新编码；否则表示更新了，模型仍可能生成不出正确 item。

**主要看两种效果。** H@10 衡量正确 item 是否进入前十；nDCG@10 还奖励更靠前的位置，二者越大越好。因此 nDCG 提升而 H@10 不变，表示主要改善了已有命中的排序位置。下文搜索/推荐 nDCG 均指 nDCG@10；百分比为相对变化，不是百分点。

所有“固定 SID”对照都要结合具体协议理解：时序实验中，它们同样用新数据更新下游模型，只是不改 SID。这样才能区分收益来自继续训练，还是来自编码更新。实验结果截至 2026-09-08，本次文档重组没有新增训练。

## 1. 首先验证：共享前缀与任务后缀是否值得采用？

### 做了什么

在 Amazon Electronics 的 19,999 个 item 上，比较两套 SID：

- **复现的 GenSAR 编码**：已有联合生成式搜推方法的编码，作为基线。
- **多视图共享前缀 + 任务专属后缀**：本项目的静态编码，原始记录名为 v13b。前缀融合内容、行为与搜索信息，两个任务保留各自后缀。

两组使用相同的 T5-small 生成模型、六类训练任务和训练轮数，也采用相同类型的碰撞处理。表示只用训练数据构建；每个任务在相同用户上取相邻的未来事件作为验证与测试，分别测试 10,000 条样本。

### 结果如何

| 编码方案 | 推荐 H@10 | 推荐 nDCG | 搜索 H@10 | 搜索 nDCG |
| --- | ---: | ---: | ---: | ---: |
| 复现的 GenSAR 编码 | 0.0374 | 0.01946 | 0.0534 | 0.02980 |
| 共享前缀 + 任务后缀 | **0.0791** | **0.05034** | **0.1240** | **0.07740** |

在这个静态协议中，新编码的搜索、推荐四项指标均更高，说明该结构值得作为时序研究的起点。这里比较的是本仓库中的一次训练复现结果，尚未覆盖多次独立初始化，不能直接当作对原论文指标或最新方法的全面优势。

**接下来的问题是：静态表现好，不代表行为变化后继续沿用这些编码仍然合适。**

## 2. 行为变化后：应该更新全部 item，还是只更新一部分？

### 做了什么

早期大范围重算推荐编码产生了大量不必要的换码，排序也没有稳定改善。因此改为先检测哪些 item 的行为关系发生变化，再仅允许这些 item 更换推荐后缀，固定共享前缀和搜索编码。

在 Amazon 的一个季度更新后、下一个季度测试，比较三种策略：

| 策略 | 改什么 | 用来回答什么问题 |
| --- | --- | --- |
| 固定编码 | 不改 SID，只更新下游模型 | 仅继续训练是否已经足够 |
| 随机局部更新 | 用相同选择预算随机选 item，允许其换码 | 收益是否只是任意更新一批 item 带来的 |
| 漂移驱动局部更新 | 根据行为变化选 item，限制无必要的编码切换 | 选对更新对象是否有价值 |

三组使用相同初始模型、时间划分与对齐训练预算；固定编码和漂移选择组还使用相同的 12 个辅助对齐 item。用三个随机种子重复增量训练，均值如下；随机种子控制初始化、采样等随机过程，本组仍共用同一初始模型。

### 结果如何

| 策略 | 推荐 nDCG | 搜索 nDCG |
| --- | ---: | ---: |
| 固定编码 + 下游更新 | 0.028642 | 0.035637 |
| 随机局部更新 | 0.027443 | 0.034550 |
| 漂移驱动局部更新 | **0.030931** | **0.035676** |

按漂移选择相对固定编码，推荐 nDCG 约 **+7.99%**，三个种子都正向；搜索基本保持。推荐 H@10 没有提高，因此主要收益仍是排序改善。

随后另做了一个效率实验：把编码 adapter（学习任务表示的小模块）的梯度训练范围从全目录缩到 **63 个漂移 item + 126 个低变化 item**。后者提供旧关系参照，约束更新不要破坏稳定表示，这称为样本回放（replay）。该单随机种子对照中，推荐 nDCG 为 0.03179 → 0.03148，核心 SID 训练时间为 180.2 秒 → 5.8 秒；它说明局部训练可行，但尚不足以宣称效果完全等价或全流程加速 31 倍。

**这一阶段确立了“选择更新对象、限制实际换码”的路线。下一步需要知道：收益是否确实发生在换码 item 上，以及能否用于搜索任务。**

[来源：公平三 seed 对照与局部 adapter 训练](../Search_Reconmendation/files/PhaseSummary/阶段6_R1d_ThreeSeed与SelectiveAdapter_2026-09-02.md)

## 3. 换码究竟帮助了谁？在搜索任务中检查局部收益

### 做了什么

自然数据没有触发足够的搜索漂移，因此构造一个可控实验：在相同前缀组内交换部分 item 的主要 query，让 query–item 关系持续变化，同时保持推荐事件不变。

共注入 75 个 item 的搜索变化。检测器选中 122 个候选，仅更新搜索 adapter，最终 **15 个 item 实际更换搜索 SID**。仍比较固定编码、同预算随机更新和漂移驱动更新，使用相同下游训练配置，用三个随机种子重复增量训练。

评价分成两个范围：

- **全体搜索样本**：下一窗口的 5,000 条测试请求。
- **换码目标子集**：其中 119 条请求的正确目标属于实际换码的 15 个 item。各方法在这同一个子集上比较，避免评估对象不同。

### 结果如何

| 评估范围 | 固定编码 nDCG | 漂移驱动更新 nDCG | 相对变化 |
| --- | ---: | ---: | ---: |
| 全体搜索，5,000 条 | 0.04112 | **0.04148** | 约 +0.88% |
| 换码目标子集，119 条 | 0.12625 | **0.15965** | **约 +26.46%** |

换码子集在三个种子上分别提升约 31.34%、24.25%、24.12%。全体搜索的收益小得多：直接涉及换码目标的请求仅占 119/5,000，即 2.38%。推荐 nDCG 为 0.02600 → 0.02597，基本保持。

这组结果支持：**更新少量搜索编码，可以明显改善相关目标的排序；局部收益不会自动变成同等幅度的整体收益。** 26.46% 是受控搜索漂移下的子集结果，不是整体搜推提升，也不是后面 MovieLens 模型的成绩。随机更新的全体搜索 nDCG 为 0.03918，低于漂移驱动更新的 0.04148。

**不过，选中变化 item 可能只是选中了更活跃的 item。接下来需要更强的对照，检验检测器本身的价值。**

[来源：搜索局部更新与三 seed 结果](../Search_Reconmendation/files/PhaseSummary/阶段6_R1S_SearchSelectiveAdapter_2026-09-02.md) · [单 seed 子集统计](../Search_Reconmendation/stage3/results/temporal_search_r1s_subgroups/subgroup_metrics.csv)

## 4. 加入更强对照：漂移检测是否优于“只更新热门 item”？

### 做了什么

在 Amazon 推荐序列中，对一部分用户的行为做同类别 item 替换，构造已知强度的推荐关系变化。选择策略同时考虑 **漂移程度和当前交互量**，只选 51 个 item；这是历史记录中的 V3-K51。

增加一个重要基线：**按当前交互量选前 51 个 item**，即 SupportTopK。它不检测漂移，用来排除“只是更新了更活跃 item”这一解释。

先在中期窗口检验三个增量训练种子，再固定策略与预算，在更晚窗口做单 seed 留出验证。中期和晚期分别是第 6、9 个更新窗口，原记录写作 W6、W9；各自在下一窗口测试。

### 结果如何

| 选择策略 | 中期窗口：推荐 nDCG，三 seed 均值 | 晚期留出：推荐 nDCG，单 seed |
| --- | ---: | ---: |
| 固定编码 + 下游更新 | 0.019476 | 0.018533 |
| 按当前交互量选择 | 0.019914 | **0.019477** |
| 按漂移与交互量共同选择 | **0.020050** | 0.019464 |

相对固定编码，漂移选择在中期约 **+2.95%**，晚期约 **+5.02%**。但相对交互量基线，优势很弱：中期三个种子只有两个更好，晚期还略低。因此，现有证据支持局部更新优于固定编码，**尚未证明复杂检测器稳定优于简单的活跃度选择**。

晚期还暴露出更关键的问题：漂移选择独有的 19 个换码 item，在下一窗口对应 83 条目标样本，所有对照方法的 nDCG 都是 0。检测到变化、甚至覆盖更多变化目标，并不保证下游模型能正确生成新编码。

**因此，下一阶段转向“新编码如何被下游模型学会”。**

[来源：推荐漂移、活跃度对照与晚期留出](../Search_Reconmendation/files/PhaseSummary/阶段12_ControlledRecDrift_W6W9完整评估_2026-09-04.md)

## 5. 新编码学不会：增加对齐监督或局部参数，能解决吗？

### 做了什么

先审计训练信号：换码 item 并非没有当前交互，每个 item 却通常只有一条“item→SID”和一条“SID→item”的直接对齐样本。这两类辅助任务用于把 item 与它的新编码联系起来。

围绕这个问题做了两个实验，固定同一套新 SID：

1. **重复换码 item 的对齐样本。** 总训练预算保持不变，提高换码 item 的占比，相应减少普通 item。
2. **只增加推荐专用 LoRA（Low-Rank Adaptation，低秩适配）。** 冻结基础生成模型，只训练小型附加参数；推荐时启用，搜索时关闭，尝试隔离跨任务干扰。

### 结果如何

| 对齐方式 | 全体推荐 nDCG | 全体搜索 nDCG | 换码目标 nDCG |
| --- | ---: | ---: | ---: |
| 每个换码 item 对齐一次 | **0.020111** | **0.021585** | 0.062610 |
| 每个换码 item 对齐两次 | 0.019889 | 0.020529 | **0.063624** |
| 在“一次对齐”模型上增加推荐专用 LoRA | 0.019736 | 0.021585 | 0.062610 |

重复对齐使局部目标略有改善，但全体推荐下降，搜索也下降约 4.9%。继续重复四次、八次，局部收益没有进一步增长。推荐专用 LoRA 确实保持了搜索效果，却没有改善换码目标，还降低了未换码推荐目标的效果。

**直接增加监督不能消除共享模型的干扰；按任务隔离参数，也不能解决推荐任务内部“该变与不该变”的区分。** 这将改进重点指向旧新编码兼容、受影响样本识别，以及对稳定能力的保持，而不只是增加训练次数。

[来源：换码监督审计、重复对齐与推荐专用 LoRA](../Search_Reconmendation/files/PhaseSummary/阶段13_换码Item下游对齐诊断_2026-09-05.md)

## 6. 回到自然变化：局部收益能否在真实时间序列中成立？

### 先在 KuaiSAR 检查“是否应该换码”

KuaiSAR 包含真实搜索与推荐日志，但观察时间约九天，所选 item 在下一窗口作为目标重复出现得很少。强制更新后，98 条换码目标样本的推荐 nDCG 从 **0.07520 降到 0.04466**。

随后加入保守门控：只有估计有收益的候选才换码。它避免了明显退化，但最好总体增益只有 +0.000049；下一窗口只有一个被选 item 出现为目标，共五条请求，且该子集各方法结果相同。这个数据上的结果说明：**应允许不更新；当前覆盖不足以验证正向收益。**

[来源：KuaiSAR 自然漂移与门控诊断](../Search_Reconmendation/files/PhaseSummary/阶段15_KuaiSAR自然Rec漂移实验_2026-09-05.md)

### 再用 MovieLens 检查更长时间跨度的推荐变化

在 MovieLens-25M 的固定 18,191 个 item 上，使用真实时间序列中的推荐行为变化。搜索使用固定 query/tag bank 构造控制任务，用来测量推荐更新是否损害搜索能力。

比较两种编码更新力度，并保留仅更新下游模型的对照。原实验用 TASR 作为系列代号，未定义英文全称；A/B 对应以下两种实现：

| 方法 | 含义 | 实际换码 item |
| --- | --- | ---: |
| 固定编码 + 下游更新 | SID 不变，生成模型继续用新数据训练 | 0 |
| 冻结码本的局部更新（TASR-A） | 只更新推荐 adapter，码本与解码器冻结 | 25 |
| 刷新码本后对齐（TASR-B） | 更新推荐 adapter、码本和解码器，对齐新旧 token，再只发布局部换码 | 67 |

码本是把连续表示映射到离散 token 的向量集合。允许码本变化提供更大的调整空间，也需要额外处理新旧 token 对应关系。三组都固定共享前缀和搜索编码，使用相同数据、对齐池与训练预算，从同一初始模型出发，重复三个增量训练种子。

| 方法 | 全体推荐 nDCG | 全体搜索 nDCG | 换码目标并集 nDCG |
| --- | ---: | ---: | ---: |
| 固定编码 + 下游更新 | 0.286285 | **0.460273** | 0.029864 |
| 冻结码本的局部更新 | 0.286483 | 0.460248 | **0.031412** |
| 刷新码本后对齐 | **0.286628** | 0.460220 | 0.031397 |

全体推荐有 2,015 条测试请求；“换码目标并集”指两种更新方案所改 item 在测试中对应的相同 326 条请求。

刷新码本方案相对固定编码，全体推荐约 **+0.12%**，三个种子均正向，保存结果中的两类统计检验也通过。H@10 没有变化，搜索基本保持。在换码并集上约 **+5.13%**，但样本层面的置信区间仍包含 0，因此该子集收益还不能宣称显著；两种更新方案之间的差异也不显著。

当前自然漂移实验支持的是：**局部更新可保持另一任务，并带来小幅整体排序改善；尚未出现受控实验中那样强的局部收益。** 这也是目前发布到 [Hugging Face](model-selection.md) 的模型系列。

### 补充：Amazon 连续更新能否保持单窗口收益？

早期推荐单窗口约 +7.99% 的收益，并未自动延续到长期。修正数据物化口径后的九窗口联合更新，搜索使用持续人工变化，推荐使用自然时间变化；三组每轮都继续训练下游 T5，再评估下一窗口。

| 策略 | 九窗口平均推荐 nDCG@10 | 九窗口平均搜索 nDCG@10 |
| --- | ---: | ---: |
| 固定编码 + 持续下游训练 | **0.024352** | 0.031124 |
| 选择性更新两任务后缀 | 0.024321 | **0.031977** |

相对固定编码，推荐约 −0.13%、搜索约 +2.74%，因此联合平均改善主要来自搜索。这是同一随机种子的连续轨迹，九个相关窗口不能替代九次独立训练。后续三个代表窗口的多种子检查与稳定性修正，也没有消除推荐相对固定编码的退化。

## 7. 这些实验怎样引出下一步改进？

| 已观察到的问题 | 下一步研究 |
| --- | --- |
| 换码 item 有当前行为，但新编码仍可能生成不出来 | 让旧模型看旧 SID、新模型看新 SID，研究跨编码的 item 对齐 |
| 重复对齐损害稳定样本，推荐专用 LoRA 也未解决任务内部干扰 | 按目标/历史是否受影响分组，保留稳定部分的蒸馏约束 |
| 漂移选择未稳定超过活跃度选择，强制换码可能退化 | 将预期排序收益和迁移成本纳入发布决策，允许不更新 |
| 更好的重构或更少的碰撞未必改善下游排序 | 在 SID 学习中验证下游排序监督，补充有解释性的结构消融 |
| 当前两个后缀 token 是否都有必要尚未验证 | **单 token 任务后缀**：先只简化推荐后缀，再检查两任务都简化 |

单后缀方向已有容量诊断：当前 MovieLens 的 18,191 个 item 分布在 12,144 个前缀桶中，最大桶只有 16 个 item，一个大小为 256 的后缀码本具备桶内区分容量。这是 2026-10-17 的资产统计，尚不是训练结果；能否保留任务信息、降低换码负担，需要重新训练比较。

此外，MovieLens 的前缀结构实验发现，压缩为更强调内容为主、搜索与推荐共性为辅的前缀反而使效果下降；加入残差重构约束、再增加时序邻域信息，也没有明确超过原方案。这些消融提醒：结构简化与表示优化都需要以排序收益检验，详细解释见[补充结构实验](experiment-details.md)。

## 结果应如何解读

各节是不同数据、划分和候选规模下的独立实验，不能把指标连接成同一模型的连续学习曲线。前几组 Amazon 实验每个正例配 999 个负候选，MovieLens 配 99 个；目前主要证据仍是采样候选排序。三个增量训练种子共用初始表示与模型，尚未覆盖完整端到端随机性。

目前最明确的两类证据是：受控搜索漂移的换码目标子集约 +26.46%，以及自然推荐漂移下全体推荐约 +0.12%。它们分别回答局部适应潜力与当前自然场景效果，不能合并为一个提升数字。完整协议、计时范围、方差、统计检验与原始文件入口见[实验细节](experiment-details.md)。
