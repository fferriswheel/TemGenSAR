# 背景与相关工作

本项目建立在生成式推荐、生成式检索和联合搜推的研究基础上。这里先说明这些方向分别解决什么，再引出本项目关注的“行为变化后，编码与生成模型如何共同适应”。

## 1. 生成式推荐：从预测 item 到直接生成推荐结果

传统推荐系统通常先从大量 item（商品、视频或电影）中召回候选，再用排序模型选出最终结果。**生成式推荐**把推荐目标表示为可生成的离散符号，模型根据用户历史逐步输出目标 item 的编码，或者进一步输出一组推荐结果。

[TIGER：Recommender Systems with Generative Retrieval](https://arxiv.org/abs/2305.05065) 是这一方向的基础工作之一：它为 item 构造 Semantic ID（SID，语义编码），再用序列生成模型根据历史 item 的 SID 预测下一 item 的 SID。它说明编码设计会直接影响推荐模型的预测空间：item 的离散表示不只是存储编号，也是模型学习对象之间关系的方式。

### OneRec：统一召回与排序，并对齐用户偏好

[OneRec：Unifying Retrieve and Rank with Generative Recommender and Iterative Preference Alignment](https://arxiv.org/abs/2502.18965) 将目标从生成候选进一步推进到统一召回与排序。其编码器读取用户行为，解码器生成会话中的推荐列表；同时使用奖励模型与直接偏好优化，让模型更偏向用户可能喜欢的结果。

OneRec 对本项目的启发有两点：一是生成结果最终要服务推荐效果，编码重构得更好不一定等于排序更好；二是生成模型需要与实际偏好目标对齐。后续 [OneRec-V2](https://arxiv.org/abs/2508.20900) 继续研究可扩展的生成架构，以及利用真实用户反馈进行偏好对齐。

本项目目前使用 T5-small 做搜索/推荐目标 SID 预测，尚未实现 OneRec 式的整组推荐列表生成或其偏好优化流程。因此，OneRec 是推荐范式与目标对齐方面的重要基础，不是当前已经完成复现的实验基线。

## 2. 生成式检索与联合搜推：两个任务怎样共享编码？

生成式检索根据 query（查询）等上下文生成目标文档或 item 的标识。生成式推荐则主要根据用户行为历史生成推荐对象。二者都可以采用 SID，但所需信息不同：搜索强调“这个 item 是否符合查询”，推荐强调“这个用户是否可能喜欢它”。

[GenSAR：Unifying Balanced Search and Recommendation with Generative Retrieval](https://doi.org/10.1145/3705328.3748071) 通过共享与任务相关的编码、多任务生成训练联合建模搜索与推荐，其[官方实现](https://github.com/TengShi-RUC/GenSAR)是本项目下游生成模型的代码基础。[Semantic IDs for Joint Generative Search and Recommendation](https://arxiv.org/abs/2508.10478) 则研究跨任务表示与统一 SID 空间。

这引出本项目的结构问题：**哪些信息适合由搜索和推荐共享，哪些信息应该保留在各自任务中？** 当前实现用共享前缀表示两任务共用的信息，用搜索后缀和推荐后缀分别保留任务差异。前缀、后缀就是 SID 的前后两段，具体例子见[方法](method.md)。

## 3. 从静态效果到时序变化：旧编码为什么会成为问题？

行为感知的编码依赖训练时的交互关系。时间推移后，同一电影可能被不同兴趣的人群观看，同一商品也可能对应新的搜索需求；旧 SID 所组织的关系可能随之过时。

但改编码会产生另一种成本。假设某 item 的推荐 SID 从 `[p1,p2,r1,r2]` 改为 `[p1,p2,r1,r3]`，生成模型原先学会的是旧编码，现在既要预测新目标，也要读懂历史中出现的新编码。即使只改推荐后缀，共享生成模型的参数更新仍可能影响搜索或其他推荐目标。

已有研究已从不同角度处理这些问题：

| 方向与代表工作 | 主要解决什么 | 与本项目的联系 |
| --- | --- | --- |
| [CLEVER](https://arxiv.org/abs/2308.14968)：持续生成式检索 | 新文档不断进入时，增量建立标识，并保持旧文档的检索能力 | 提供持续编码与知识保持的基础 |
| [DACT](https://arxiv.org/abs/2603.29705)：漂移感知的持续编码 | 区分变化与稳定的 item，限制不必要的 token 变化 | 是选择性换码的重要比较对象，此处按预印本引用 |
| [Mitigating Collaborative Semantic ID Staleness in Generative Retrieval](https://arxiv.org/abs/2604.13273)：协同 SID 更新 | 将刷新后的 token 对应到旧 token，支持从旧模型继续训练 | 与本项目“刷新码本后对齐”的更新路线直接相关 |
| [DIGER](https://arxiv.org/abs/2601.19711)：可微 SID | 把推荐目标纳入编码优化，缩小编码训练与最终任务之间的差别 | 为后续面向排序目标的 SID 学习提供参照 |

因此，研究缺口需要具体到联合搜推的任务隔离、更新决策和新旧编码兼容性，不能只以“动态更新 SID”作为贡献。当前尚未完成上表方法在统一协议下的系统实验比较。

## 4. TemGenSAR 研究什么，目前怎样做？

核心问题是：**一个任务发生变化时，能否只更新需要变化的编码，并让生成模型学会新编码，同时保留稳定 item 和另一任务的效果？**

当前实现分为四步：

1. **先拆分共享信息与任务信息。** 用内容、行为和查询相关表示学习共享前缀，再分别生成搜索与推荐后缀。
2. **只训练需要适应的部分。** 根据历史与当前交互选择变化较大的 item；训练时混入少量低变化 item，并约束其表示接近旧值，帮助保留稳定关系。这一操作在代码中称为 replay（回放）。
3. **限制真正发布的换码。** 未选 item 保持原 SID；候选的新编码还要满足碰撞检查或保持旧码的约束。碰撞指两个不同 item 被赋予相同完整 SID。
4. **让生成模型适应新编码。** 用新数据和 item↔SID 辅助样本继续训练；对未受换码影响的样本，要求新模型的预测接近旧模型，降低遗忘。这种用旧模型约束新模型的训练称为蒸馏。

这里存在两种不同的“对齐”：**token 对齐**解决刷新码本后新旧符号的对应问题；**下游训练对齐**让生成模型真正学会 item 与新编码的关系。OneRec 中的偏好对齐则让生成结果更符合用户偏好，三者目标不同。

目前，受控搜索漂移实验在换码目标子集上观察到明显排序改善；MovieLens 自然推荐漂移下的整体改善较小。重复换码后性能不稳定、增加对齐训练会影响稳定样本，说明新旧编码兼容仍需改进。[实验主文](experiments.md)按问题逐步说明这些证据。

后续研究包括缩短任务后缀、改进新旧编码之间的训练，以及在决定换码前估计排序收益能否覆盖迁移成本。这些均为[待验证方向](roadmap.md)。
