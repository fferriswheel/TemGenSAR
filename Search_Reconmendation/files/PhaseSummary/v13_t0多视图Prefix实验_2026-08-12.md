# v13 t0 多视图 Prefix 实验（2026-08-12）

## 1. 实验目的

在静态 `t0` 快照下验证以下设计：先用初始公共、Search、Rec 信息训练 shared prefix，随后冻结 prefix，仅训练任务私有 suffix。时序更新暂不进入本轮实验。

所有 v13 SID 均为：

```text
Search SID = [shared prefix x2 | Search suffix x2]
Rec SID    = [shared prefix x2 | Rec suffix x2]
codebook   = [256, 256 | 256, 256]
```

## 2. 两个版本

### v13a-match

Prefix 输入为 `BGE(title + description)` 与 `UniSAR-faithful collaborative embedding`，与 GenSAR faithful baseline 的主要输入 view 对齐。两路表示经独立 MLP encoder、softmax gating 和两层 RQ 量化得到固定 prefix。

### v13b-full

在 v13a 的两路输入上增加显式 query-derived Search view。三路表示经独立 encoder、gating 和两层 RQ 量化得到固定 prefix。

两版 suffix 均沿用 v12 的层级结构：Search 拆为 query relevance code 与 item identity code，Rec 使用两层 residual code；末层训练使用 direct Sinkhorn VQ，不做 post-hoc unique reassignment。

## 3. SID 统计

| 方法 | Prefix unique | Search raw duplicate | Rec raw duplicate |
|---|---:|---:|---:|
| v12 | 2,286 | 20.28% | 23.28% |
| v13a-match | 11,639 | 4.39% | 1.65% |
| v13b-full | 11,034 | 5.04% | 1.69% |

v13 的低 collision 不完全来自 prefix。对同一 prefix 内的 suffix 做随机打乱后，多 item prefix 上的重构 cosine 明显下降：

| 方法 | Search full-prefix gain | Search in-prefix shuffle drop | Rec full-prefix gain | Rec in-prefix shuffle drop |
|---|---:|---:|---:|---:|
| v13a-match | +0.0332 | 0.0061 | +0.0097 | 0.0093 |
| v13b-full | +0.0320 | 0.0052 | +0.0101 | 0.0103 |

v13a/v13b 分别有约 98%/98% 的 Search 多 item prefix、99%/99.5% 的 Rec 多 item prefix 被 suffix 进一步拆分。因此 suffix 确实提供了组内 item discrimination，但 prefix 已吸收较多 Rec 信息，Rec 的全局重构增益相对较小。

## 4. 下游协议

下游使用同一份 GenSAR faithful 20K 数据和 T5-small pipeline：

```text
train tasks = SeqRecWithSrcHis, PerSrcWithRecHis, QGenWithRecHis,
              AdHocSrc_Doc2Query, Item2Index, Index2Item
epochs      = 3
seed        = 2024
selection   = validation ndcg@5
```

faithful 数据中有 353 个 Search item 在三个 split 中均无 query。为使 `AdHocSrc_Doc2Query` 覆盖完整 `src_item_set`，三组实验共享同一个回退文件：优先使用 title，title 为空时使用 description。该回退影响约 1.8% item，不随 SID 方法变化。

## 5. Fast 筛选

每任务采样 5,000，validation/test 各任务 200，199 negatives，beam 10。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR faithful | 0.040 | 0.0303 | 0.015 | 0.0053 |
| v13a-match raw | 0.075 | 0.0597 | 0.150 | **0.0900** |
| v13b-full raw | **0.105** | **0.0717** | **0.155** | 0.0867 |

v13b 综合最好，因此进入主实验。

## 6. 主实验

每个任务参数均设为采样 20,000，validation/test 各任务 1,000，999 negatives，beam 10。native 与 v13b 在该实验内部使用相同协议，仅 SID 文件不同。

但这不是 faithful GenSAR 的任务采样比例。`Item2Index` 和 `Index2Item` 的 dataset 长度会在配置采样数上各乘 2，因此实际 160,000 条训练样本的构成为：

```text
SeqRecWithSrcHis       20,000
PerSrcWithRecHis       20,000
QGenWithRecHis         20,000
AdHocSrc_Doc2Query     20,000
Item2Index             40,000
Index2Item             40,000
```

直接 Rec/Search 任务只占 25%，两个 index 辅助任务占 50%。官方 `run_amazon.py` 使用的是 `0,100000,1000,1000,1000,1000`，并非六任务等量采样。因此下表只能说明 v13b 在“辅助任务高权重”协议下优于 native，不能作为 faithful GenSAR baseline 的最终对比。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR faithful | 0.007 | 0.0025 | 0.001 | 0.0010 |
| v13b-full raw | **0.085** | **0.0502** | **0.075** | **0.0370** |

native 在 6-task 主实验中显著弱于它此前的 2-task 结果，主要嫌疑是当前错误的任务采样比例造成负迁移。格式检查排除了 native/v13b 之间的辅助任务采样不对称：两组均有 shared prefix，`Item2Index` 和 `Index2Item` 均对 Search/Rec SID 各生成一次样本。

## 7. 当前结论与限制

1. v13 同时显著改善 raw collision，并在辅助任务高权重的 6-task 协议下显著优于 native，且不依赖 post-hoc 强制 unique。
2. v13b 在 Rec 和综合指标上优于 v13a；v13a 的 Search nDCG 略高，显式 Search view 的具体贡献仍需 ablation。
3. suffix shuffle 证明 suffix 有效，但 prefix-suffix NMI 仍高，后续应继续观察 prefix 是否吸收过多 task-private 信息。
4. 当前 6-task 结果不能替代 faithful GenSAR baseline。应先在原有 2-task 协议下直接比较 native 与 v13b，隔离 SID 的作用。
5. full-task 实验应按官方任务比例重构缩放版，避免 Item2Index/Index2Item 因 dataset 内部乘 2 而占据 50% 样本。
6. 协议修正后再增加 seed 2025/2026；当前不应继续增加 collision 约束。

## 8. 修正后的 2-task 公平对照

为隔离 SID 本身的作用，使用此前 GenSAR-faithful 完全相同的 2-task 协议补跑 v13b：

```text
tasks              = SeqRecWithSrcHis + PerSrcWithRecHis
train              = 20,000 samples per task
validation/test    = 1,000 samples per task
epochs             = 3
effective batch    = 128 (32 x gradient accumulation 4)
negatives          = 999
beam size          = 10
seed               = 2024
```

这里的 baseline 是 `GenSAR-faithful`：BGE semantic embedding、UniSAR-faithful collaborative embedding、GenSAR collision-aware SID。历史运行目录中的 `native` 只是旧命名残留，不代表另一套 baseline。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.077 | 0.0481 | 0.079 | 0.0453 |
| v13b-full raw | **0.103** | **0.0661** | **0.094** | **0.0589** |

相对 GenSAR-faithful，v13b 的绝对提升为：Rec H@10 `+0.026`、Rec nDCG@10 `+0.0179`、Search H@10 `+0.015`、Search nDCG@10 `+0.0136`。该对照中数据、任务、采样、模型、训练超参、候选集和评估完全一致，仅 SID 不同，因此这是当前最可信的 SID 效果证据。

结果仍为单 seed。下一步应先补 seed 2025/2026，再决定是否进入按官方比例缩放的 full-task 实验。

## 9. Unique-target 严格评估

为排除重复 SID 使生成指标偏乐观的可能，从原 1,000 条测试样本中构造双方共同的 target-unique 子集：只有当目标 item 在 GenSAR-faithful 和 v13b 两套 SID 下都不存在 collision 时才保留。

```text
Rec:    964 / 1000 retained
Search: 928 / 1000 retained
```

候选集、beam 和已训练模型保持不变。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.0799 | 0.0499 | 0.0841 | 0.0484 |
| v13b-full raw | **0.1006** | **0.0631** | **0.0916** | **0.0594** |

过滤后 v13b 的绝对优势为 Rec H@10 `+0.0207`、Rec nDCG@10 `+0.0131`、Search H@10 `+0.0075`、Search nDCG@10 `+0.0110`。四项指标仍领先，因此提升并非完全来自 collision；Search H@10 差距有所缩小，说明原始评估确实受到一定 collision 影响。

## 10. Collision 处理差异

v13b 当前包含训练期 direct Sinkhorn VQ：Search identity codebook 与 Rec 最后一层 codebook 使用 `epsilon=0.003, iterations=50`。但最终导出使用 raw argmin：

```text
export_sinkhorn_rounds = 0
Search changed from raw = 0
Rec changed from raw    = 0
```

GenSAR-faithful 的处理更完整：

1. RQ-VAE 训练时在配置层使用 Sinkhorn，并按 validation collision rate 保存 `best_collision_model`。
2. 导出时先关闭 shared 层 Sinkhorn，仅对 semantic/collaborative 最后一层开启 Sinkhorn。
3. 只针对当前完整 SID collision groups 重新分配，循环至无 collision 或达到 20 轮。

因此，GenSAR-faithful 的低 collision 不仅来自表示和训练，还来自显式的导出期 collision-group reassignment；v13b 当前没有对应的 post-hoc 步骤。

## 11. v13b + Collision-group Sinkhorn

为与 GenSAR-faithful 的导出策略对齐，在 v13b raw SID 上增加 collision-group Sinkhorn。每轮只处理当前完整 SID 冲突组，并保持已有层级语义不变：

```text
Search: 固定 [shared prefix, relevance code]，仅重分配 identity code
Rec:    固定 [shared prefix, first Rec suffix]，仅重分配最后一层 Rec code
epsilon = 0.003, Sinkhorn iterations = 100, max rounds = 20
```

### 11.1 Collision

| SID | Search duplicate | Search collided items | Search groups | Rec duplicate | Rec collided items | Rec groups |
|---|---:|---:|---:|---:|---:|---:|
| v13b raw | 5.035% | 9.045% | 802 | 1.685% | 3.100% | 283 |
| v13b + CG-Sinkhorn | **0.320%** | **0.600%** | **56** | **0.040%** | **0.080%** | **8** |
| GenSAR-faithful | 0.460% | - | - | 0.220% | - | - |

CG-Sinkhorn 改写了 `9.065%` 的 Search item 和 `3.115%` 的 Rec item。处理后 v13b 的两项 duplicate rate 均已达到与 GenSAR-faithful 相同量级，并略低于该 baseline；这一步没有增加 codebook 或 SID 长度，也没有强制加入唯一 item token。

### 11.2 相同 2-task 协议下游结果

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.077 | 0.0481 | 0.079 | 0.0453 |
| v13b raw | **0.103** | 0.0661 | 0.094 | **0.0589** |
| v13b + CG-Sinkhorn | 0.100 | **0.0670** | **0.102** | 0.0536 |

相对 raw v13b，CG-Sinkhorn 的变化为：Rec H@10 `-0.003`、Rec nDCG@10 `+0.0009`、Search H@10 `+0.008`、Search nDCG@10 `-0.0053`。相对 GenSAR-faithful，CG 版本四项仍全部领先：Rec H@10 `+0.023`、Rec nDCG@10 `+0.0189`、Search H@10 `+0.023`、Search nDCG@10 `+0.0083`。

该结果表明 collision-group Sinkhorn 显著降低了标识歧义，但不是无损后处理。Search 需要重写约 9.1% item，H@10 的覆盖有所改善，但相关 item 的相对排序被扰动，导致 nDCG@10 回落。现阶段应同时保留 raw 与 CG 两套结果：raw 用于衡量表示本身，CG 用于和带导出期 collision 处理的 GenSAR-faithful 做工程口径对齐。后续不应继续追求 collision 接近 0，而应研究减少重分配比例、在训练阶段让末层距离 margin 与 CG 导出目标一致。

## 12. Faithful-full 与官方 task 比例实验

### 12.1 全量数据口径

在 20K 筛选规则不变的前提下放宽 item 上限，得到完整 Search/Rec overlap universe：

```text
items                    = 62,851
users                    = 192,403
Search interactions      = 1,280,323
Rec interactions         = 1,688,404
items with both signals  = 62,851
```

两种方法共享同一份 `BGE(title + description)` 和在全部 `2,391,518` 个行为训练事件上学习的 `UniSAR-faithful` embedding。codebook 均保持 `[256,256 | 256,256]`。

### 12.2 全量 SID collision

| SID | Search before CG | Search after CG | Rec before CG | Rec after CG |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 未单独导出统计 | **0.436%** | 未单独导出统计 | **0.041%** |
| v13b | 10.733% | 1.753% | 1.569% | 0.0445% |

GenSAR-faithful checkpoint 的训练期联合 collision 为 `5.260%`，但导出日志没有分别保存 Search/Rec 的 pre-CG duplicate，因而不把该联合值误作两项 raw collision。两者均使用最多 20 轮 collision-group Sinkhorn。v13b CG 改写 `18.466%` 的 Search item 和 `2.881%` 的 Rec item。Rec collision 已与 GenSAR-faithful 对齐；Search 仍高约 4 倍，且 raw Search collision pairs 中 `98.73%` 共享 query，说明 query 同质性与 identity suffix 区分不足仍是主要瓶颈。

### 12.3 下游 task 比例

使用 GenSAR 官方 `train_data_sample_num=0,100000,1000,1000,1000,1000`，实际训练组成如下：

```text
SeqRecWithSrcHis       1,111,195  (全部可用 Rec train rows)
PerSrcWithRecHis         100,000
QGenWithRecHis             1,000
AdHocSrc_Doc2Query         1,000
Item2Index                  2,000  (dataset 内部 Search/Rec 各生成一次)
Index2Item                  2,000  (dataset 内部 Search/Rec 各生成一次)
total                   1,217,195
```

这复现的是官方 task 比例，不是官方 200-epoch 训练预算。为隔离 SID，两组继续采用相同的受控协议：T5-small、3 epochs、effective batch 128、learning rate `1e-3`、cosine scheduler、seed 2024、999 negatives、beam 10。validation/test 各任务固定采样 1,000 条，且两组样本和候选集完全相同。

### 12.4 下游测试结果

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.033 | 0.0182 | 0.037 | 0.0223 |
| v13b + CG-Sinkhorn | **0.053** | **0.0233** | **0.058** | **0.0269** |

v13b 的绝对提升为 Rec H@10 `+0.020`、Rec nDCG@10 `+0.0051`、Search H@10 `+0.021`、Search nDCG@10 `+0.0046`。相对提升分别约为 `60.6%`、`27.9%`、`56.8%` 和 `20.8%`。两组 best checkpoint 都在 epoch 3（global step 28,530），选择规则均为两个 validation task 的平均 nDCG@5。

需要注意，v13b 的 Rec/Search H@1 分别为 `0.004/0.007`，低于 GenSAR-faithful 的 `0.005/0.008`；主要优势出现在 rank 6-10，而不是 top-1。测试绝对值也明显低于 validation，这是全量 per-user chronological split 中最后一次行为比 validation 的倒数第二次行为更难造成的共同现象，不影响两套 SID 的同样本相对比较。

### 12.5 当前判断

1. v13b 的优势从 20K 2-task 实验扩展到了 62,851-item faithful-full 和官方 task 比例，四个主指标均领先，说明此前结果不是小数据或等量多任务采样的偶然现象。
2. v13b Search collision 明显高于 GenSAR-faithful，但 Search H@10/nDCG@10 仍领先，进一步说明 collision 不是下游质量的充分条件；不能为了追求接近 0 而继续做更强 post-hoc 改派。
3. 当前仍是单 seed 和 1,000-test controlled evaluation。论文主表前应补 seed 2025/2026，并在资源允许时扩大 test sample；不应立即重新修改 v13b 结构。

## 13. 20K strict train-only 公平对照

### 13.1 为什么重跑

前述全量实验中，SID representation 使用了下游 validation/test 时段的行为；此外，GenSAR 与 v13b 的 SID 文件实际出现 token 数不同，使 T5 自动扩展出的 embedding 参数量相差约 44 万。虽然两者都没有直接使用测试 label 训练下游模型，但这两个因素不满足严格的 representation-level temporal split 和等参数容量要求，因此全量结果只保留为探索性证据。

本轮回到 19,999-item 数据集，并采用以下严格控制：

```text
SID representation behavior = temporal train period only
Rec train targets            = 279,046
Search train targets         = 248,341
downstream train total       = 385,046
validation                   = Rec 1,000 + Search 1,000
test                         = Rec 5,000 + Search 5,000
codebooks                    = [256,256 | 256,256]
CG-Sinkhorn                  = epsilon 0.003, iterations 50, max rounds 20
T5 trainable parameters      = 61,280,256 for both methods
optimization steps           = 9,027 for both methods
```

UniSAR collaborative embedding 只用 temporal-train 行为重新训练。v13b query view 只聚合 `src_train.pkl`；Doc2Query 也重建为 `item2query_trainonly_nq20.pkl`，不再读取 validation/test query。静态 `BGE(title + description)` 可复用，因为不含时序行为。

下游 loader 新增 `complete_sid_vocab=True`：从每层 SID token stem 推断 codebook，并显式注册每层 `0..255` 全部 token。这样即使某方法有未使用 code，两边仍拥有相同的 1,536 个 SID token 容量和完全相同的模型参数量。实现位于 GenSAR 的 `finetune/modules/arguments.py` 与 `finetune/modules/data.py`，默认关闭，不改变原始行为。

### 13.2 SID collision

| SID | Search duplicate | Search collided items | Rec duplicate | Rec collided items |
|---|---:|---:|---:|---:|
| GenSAR-faithful + native CG | 0.515% | 0.780% | 0.230% | 0.440% |
| v13b raw | 5.440% | 9.570% | 2.655% | 4.890% |
| v13b + matched CG | **0.275%** | **0.465%** | **0%** | **0%** |

v13b 的 raw Search collision pairs 中 96.7% 具有相同训练期 query，剩余问题主要是同 query item 的细粒度 identity 区分。matched CG 后两者均处于低碰撞量级，没有加入 unique item token，也没有延长 SID。

完整测试中，共同 target-unique 覆盖为 Rec `4,986/5,000`、Search `4,956/5,000`；分别只排除 0.28% 和 0.88% 的样本，因此 collision target 覆盖差异不足以解释下游的大幅差距。

### 13.3 严格下游结果

两组均使用 GenSAR 六任务比例：`0,100000,1000,1000,1000,1000`，T5-small、3 epochs、effective batch 128、learning rate `1e-3`、cosine scheduler、seed 2024、999 negatives、beam 10。唯一方法变量是 Search/Rec SID assignment。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful train-only | 0.0496 | 0.0321 | 0.0686 | 0.0417 |
| v13b train-only + CG | **0.0946** | **0.0657** | **0.1966** | **0.1206** |

v13b 相对 GenSAR 的倍数约为 Rec H@10 `1.91x`、Rec nDCG@10 `2.05x`、Search H@10 `2.87x`、Search nDCG@10 `2.89x`。完整词表控制前的诊断版也得到同方向结果，说明优势不是额外 216 个 observed SID token 参数造成的。

最佳 checkpoint：GenSAR 为 epoch 2（step 6,018），v13b 为 epoch 3（step 9,027）；两者都按 Rec/Search validation `nDCG@5` 的平均值选择。每个运行目录只保留一个 best checkpoint。

### 13.4 当前结论与限制

1. 在严格 temporal-train representation、相同辅助数据、相同 token 容量、相同下游 pipeline 和完整 5,000+5,000 test 下，v13b 的优势仍然显著，当前可以排除已识别的主要工程混杂因素。
2. 这是“同一可访问训练数据下的完整系统比较”，不是“相同输入 view 的纯量化器比较”：v13b 显式建模 train-only query view，这是方法设计的一部分，也是 Search 提升的重要来源。
3. 当前仍只有 seed 2024。论文主表前必须补至少 3 seeds，并报告均值、标准差与显著性；还需增加去掉 explicit query view、去掉 CG、仅 observed token vocab 等 ablation。
4. 本轮 20K 结果应作为当前主要受控证据；第 12 节全量结果因 representation temporal leakage 风险，不应直接进入论文主表。
