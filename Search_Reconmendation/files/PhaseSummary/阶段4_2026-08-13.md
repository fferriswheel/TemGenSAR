# 阶段4：共享 Prefix、任务私有 Suffix 与静态 t0 基准（2026-08-13）

## 1. 阶段目标与最终产出

本阶段从最初的 TF-IDF SID sanity pipeline 出发，完成了以下工作：

1. 建立 Search/Rec 共用 prefix、任务私有 suffix 的完整 SID 生成与下游训练链路；
2. 将 item representation 从稀疏文本统计逐步升级为 BGE 语义表示、query-derived Search 表示和 UniSAR-faithful 行为表示；
3. 系统研究 RQ-VAE、LoRA/low-rank task adapter、prefix locking、collision regularization、topology preservation 与 collision-group Sinkhorn；
4. 将实验从 200-item sanity 扩展到 5K、20K 和 62,851-item 全量 Search/Rec overlap 数据；
5. 迁移 GenSAR pipeline，建立 GenSAR-faithful baseline，并统一下游模型、训练任务、SID token 容量和候选集评估；
6. 构造严格 train-only representation、paired leave-two-out 的 20K 数据，用于排除未来行为泄漏和 validation/test 用户错位。

本阶段最终主模型定为：

```text
M7b-v13b-full + matched collision-group Sinkhorn
简称：v13b + CG-Sinkhorn
```

阶段结论是：在目前所有 SID 以外因素相同的受控比较中，v13b 的 Rec 与 Search 下游结果均优于 GenSAR-faithful。下一阶段不再继续以静态 collision 调参为主，而是进入 temporal drift 下的 SID 局部更新实验。

## 2. 问题定义

对同一个 item `i`，生成两套共享前缀的任务 SID：

```text
Search SID_i = [P_i1, P_i2 | S_i1, S_i2]
Rec SID_i    = [P_i1, P_i2 | R_i1, R_i2]
```

其中：

- `P_i1, P_i2` 表示 t0 时刻 Search 与 Rec 共用的粗粒度 item state；
- `S_i1, S_i2` 表示 Search 私有的 query relevance 与 item discrimination；
- `R_i1, R_i2` 表示 Rec 私有的协同/序列行为结构；
- 最终正式实验采用 `[256,256 | 256,256]`，SID 总长度为 4；
- 后续若单一任务发生漂移，目标是保持 prefix 和另一任务 suffix 不变，只更新发生漂移的 suffix。

需要强调：当前 v13b prefix 是 **t0 multi-view anchor**，不是严格只含时不变信息。它吸收了 t0 的 common、Search 和 Rec 三类信息，但后续被锁定，用作稳定坐标系。下一阶段需要检验这种近似是否足以承受可控 temporal drift。

## 3. 最终模型结构

### 3.1 三类输入表示

对每个 item 构造以下 view：

```text
x_common = BGE(title + description)
x_search = BGE(该 item 在 temporal-train 中关联的聚合 pseudo-query)
x_rec    = UniSAR-faithful item collaborative embedding
```

具体含义：

- `x_common` 使用冻结的 `BAAI/bge-base-en-v1.5` 提取静态 item 文本语义；
- `x_search` 最多聚合每个 item 的 20 个训练期 query，用同一 BGE encoder 映射到语义空间；
- `x_rec` 由 Search/Rec 历史行为共同训练的 UniSAR-faithful encoder 产生，核心目标包括行为 retrieval、query-item relevance 和跨任务 alignment；
- 严格实验中，`x_search` 与 `x_rec` 只使用 downstream temporal-train 时段行为，不读取 validation/test 时段行为；
- BGE 作为冻结特征提取器，不参与 SID 训练。

### 3.2 Stage A：Multi-View Anchor Prefix RQ-VAE

三个 view 先通过独立 MLP 投影到 64 维 latent：

```text
h_common = Enc_common(x_common)
h_search = Enc_search(x_search)
h_rec    = Enc_rec(x_rec)
```

随后由可学习 gating 融合：

```text
alpha_i = softmax(Gate([h_common, h_search, h_rec]))
z_i^anchor = LayerNorm(
    alpha_common * h_common
  + alpha_search * h_search
  + alpha_rec    * h_rec
)
```

`z_i^anchor` 进入两层 RQ-VAE，得到固定 prefix：

```text
q_i^anchor, [P_i1, P_i2] = RQ_prefix(z_i^anchor)
```

三个 decoder 分别重构 common、Search 和 Rec view。Prefix 阶段的核心损失为：

```text
L_prefix = mean(
    L_cos(common_recon, x_common),
    L_cos(search_recon, x_search),
    L_cos(rec_recon, x_rec)
  )
  + lambda_commit * L_commit
  + lambda_balance * L_code_usage
  + lambda_gate * L_gate_diversity
```

正式配置：MLP hidden 256、latent 64、两层 256 codebook、10 epochs continuous warmup、100 epochs 总训练。严格 20K 模型的三路平均 gate 权重约为 `0.336 / 0.328 / 0.336`，没有出现单一 view 完全支配。

### 3.3 Stage B：冻结 Prefix，训练任务私有 Suffix

Prefix 训练完成后冻结：

```text
Enc_common / Enc_search / Enc_rec = frozen
Gate                              = frozen
prefix codebooks                  = frozen
[P_i1, P_i2]                      = fixed
```

Search 与 Rec 分别使用独立的 low-rank private adapter。Adapter 同时接收 frozen anchor 与任务 view，不直接重新训练 prefix。

#### Search suffix

Search private latent 显式拆成两部分：

```text
z_i^search = [z_i^rel, z_i^id]
```

- `z_i^rel` 学习 item 与相关 query prototype 的 relevance；
- `z_i^id` 使用 common item residual、anchor quantization residual 和 Search 条件化信息，在共享 query 的 item 之间继续区分；
- 第一层 suffix code `S_i1` 量化 relevance；
- 第二层 suffix code `S_i2` 在固定 `[P_i1,P_i2,S_i1]` route 内量化 identity。

#### Rec suffix

Rec adapter 从 `[z_i^anchor, x_i^rec]` 产生 64 维 private latent，使用两层 RQ 量化得到 `[R_i1,R_i2]`。其目标是保留 item-specific collaborative topology，而不是预测 next item；next-item 预测只属于后续 T5 下游任务。

#### Suffix 训练目标

最终实现保留的主要目标是：

```text
L_suffix = L_residual_reconstruction
         + L_full_view_reconstruction
         + L_query_item_contrast
         + L_search_identity_reconstruction
         + L_in_prefix_topology
         + L_commit + L_code_usage
```

其中 full-view reconstruction 使用 frozen prefix reconstruction 与 suffix reconstruction 的组合去恢复 Search/Rec target；suffix 并不是单独预测下一个 item。训练期还保留轻量 conditional Sinkhorn/assignment 约束，避免同一 prefix route 内所有 item 塌缩到同一个末层 code。

### 3.4 Stage C：Matched Collision-Group Sinkhorn

为与 GenSAR-faithful 的导出策略公平对齐，最终 v13b 也使用 collision-group Sinkhorn：

```text
Search: 固定 [P1,P2,S1]，只重分配 S2
Rec:    固定 [P1,P2,R1]，只重分配 R2
epsilon = 0.003
iterations = 50
max rounds = 20
```

该步骤只处理完整 SID collision group，不改变 prefix、任务 route、codebook size 或 SID 长度，也不追加 unique item token。正式结果同时保留 raw SID 统计，以区分 representation 自然可分性与导出修复效果。

### 3.5 下游生成模型

最终下游沿用 GenSAR 的 T5-small generative pipeline：

```text
SeqRecWithSrcHis
PerSrcWithRecHis
QGenWithRecHis
AdHocSrc_Doc2Query
Item2Index
Index2Item
```

正式 6-task 采样数为：

```text
0, 100000, 1000, 1000, 1000, 1000
```

其中 `0` 表示使用全部可用 Rec train rows。两种 SID 均将 4 个 code 注册为专用 token，在相同 T5-small、相同完整 SID vocab、相同 optimizer、batch、seed 和候选集上直接训练。checkpoint 依据 Rec/Search validation mean nDCG@5 选择。

## 4. Baseline：GenSAR-faithful

最终 baseline 不是早期简化的 `GenSAR-native`，而是迁移后的 `GenSAR-faithful`：

```text
semantic embedding      = BGE(title + description)
collaborative embedding = UniSAR-faithful behavior embedding
SID model               = GenSAR shared/specific RQ-VAE
Search SID              = shared code x2 + semantic code x2
Rec SID                 = shared code x2 + collaborative code x2
export                  = collision-group Sinkhorn
```

公平比较中，两者共享：

- 相同 item universe 和 temporal split；
- 相同 BGE 与 UniSAR 输入 embedding；
- 相同 `[256,256 | 256,256]` SID 容量；
- 相同 T5-small 参数量 `61,280,256`；
- 相同 6-task 数据、采样比例、训练超参、seed 和评估候选集；
- 相同级别的 collision-group Sinkhorn。

因此最终严格实验中，两者的主要变量是 SID representation 与层级组织方式。

## 5. 数据集与规模扩展

| 数据集 | Item 数 | 主要用途 | 下游规模/评估 |
|---|---:|---|---|
| 200-item sanity | 200 | 跑通 TF-IDF、RQ-VAE、prefix/suffix 与 T5 链路 | train/val/test = 16K/2K/2K；小 codebook `[8,4|32,8]` |
| GenSAR-Lite-5K | 5,000 | M7b 结构、collision 与 3-seed 消融 | 每任务 5K train，1K test，99 negatives |
| GenSAR-Lite-20K | 19,999 | 长尾规模扩展、codebook 消融 | Search 470,454；Rec 589,626；3-seed 2-task |
| 20K faithful | 19,999 | GenSAR-faithful 与 v13b 主对照 | 6-task；5K test/任务；999 negatives |
| 20K strict paired | 19,999 | 最严格无未来行为、相邻时序评估 | Rec train 153,981；Search train 90,929；val/test 各 10K/任务 |
| Faithful-full | 62,851 | 检验全量 item universe 扩展性 | 1,217,195 下游样本；1K test/任务；999 negatives |

20K item 是从 62,851 个同时具有 Search 和 Rec 信号的 Electronics item 中，按 head/middle/tail 活跃度分层采样得到。与 5K 相比，20K 的 Search/Rec per-item 中位交互数从 `82/103` 降至 `10/13`，明显更长尾。

严格 paired 20K 进一步要求每个评估用户同时具有 Rec 与 Search history，且任务内至少有 3 个有效时序目标：倒数第二个作为 validation、最后一个作为 test。每个任务的 val/test 使用相同的 10,000 名用户。

## 6. 不同规模上的模型与 Baseline 对比

### 6.1 早期结构筛选：5K，3 seeds

以下结果用于结构选择，不是最终 v13b；协议为 2-task、99 negatives、每任务 1,000 test。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-native | 0.1433 +/- 0.0276 | 0.0730 +/- 0.0146 | 0.1913 +/- 0.1200 | 0.1038 +/- 0.0732 |
| M7b-v3d | **0.1657 +/- 0.0119** | 0.0713 +/- 0.0057 | **0.2030 +/- 0.0541** | 0.1262 +/- 0.0368 |
| M7b-v5-B raw | 0.1593 +/- 0.0110 | 0.0708 +/- 0.0050 | 0.1753 +/- 0.0430 | **0.1291 +/- 0.0253** |

这一步确定了两点：固定 prefix + task-private adapter 是可行主线；collision 越低不等于下游越好，必须同时保持局部 semantic/behavior topology。

### 6.2 早期规模扩展：20K，3 seeds

以下仍是 v5-B 与简化 GenSAR-native 的阶段性结果，协议为 2-task、99 negatives、1,000 test/任务：

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-native p128 | 0.1583 +/- 0.0074 | 0.0794 +/- 0.0055 | 0.1073 +/- 0.0396 | 0.0498 +/- 0.0214 |
| M7b-v5-B p128 raw | **0.1950 +/- 0.0060** | **0.1003 +/- 0.0069** | **0.3090 +/- 0.0345** | **0.2019 +/- 0.0121** |

该实验说明方法主线能扩展到更长尾的 20K item，但 baseline 和 representation 尚不够 faithful，因此不能作为最终论文主表。

### 6.3 最终结构的 20K train-only 对照

该实验使用 train-only behavior representation、6-task、每任务完整 5,000 test、999 negatives、beam 10。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.0496 | 0.0321 | 0.0686 | 0.0417 |
| **v13b + CG-Sinkhorn** | **0.0946** | **0.0657** | **0.1966** | **0.1206** |

v13b raw Search/Rec duplicate 为 `5.44% / 2.66%`；matched CG 后为 `0.275% / 0%`。

### 6.4 20K all-behavior 控制实验

只将 representation 从 train-only 换为 all-behavior，其余配置不变：

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.0446 | 0.0309 | 0.0530 | 0.0362 |
| **v13b + CG-Sinkhorn** | **0.1108** | **0.0747** | **0.2210** | **0.1326** |

all-behavior 改善了 v13b，但没有改善 GenSAR。这说明 representation 信息量与 SID topology 是否易于 T5 生成是两个不同问题。由于它使用未来行为，该实验只能作为 transductive 诊断，不能用于下一阶段 temporal drift 主结论。

### 6.5 62,851-item 全量对照

全量实验使用 1,217,195 条 6-task 训练样本、每任务 1,000 test、999 negatives、beam 10：

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.033 | 0.0182 | 0.037 | 0.0223 |
| **v13b + CG-Sinkhorn** | **0.053** | **0.0233** | **0.058** | **0.0269** |

两组均只训练 3 epochs；GenSAR validation 仍持续改善，因此这组结果证明的是 v13b 能扩展到全量 item universe，而不是充分收敛后的最终差距。全量 v13b raw Search collision `10.73%`，CG 后仍为 `1.75%`，说明 Search identity 在更大规模上仍是主要瓶颈。

### 6.6 最严格 paired leave-two-out 对照

这是本阶段最终采用的公平性最高实验：strict-train-only representation、相同 paired 用户、val/test 相邻时序目标、6-task、每任务 10,000 test、999 negatives、beam 10。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.0374 | 0.01946 | 0.0534 | 0.02980 |
| **v13b + CG-Sinkhorn** | **0.0791** | **0.05034** | **0.1240** | **0.07740** |

相对 GenSAR-faithful：

```text
Rec HR@10       +111.5%
Search HR@10    +132.2%
Rec nDCG@10     +158.7%
Search nDCG@10  +159.7%
```

严格 20K 的 collision：

| SID | Search duplicate | Rec duplicate | Search unique | Rec unique |
|---|---:|---:|---:|---:|
| GenSAR-faithful + CG | 0.435% | 0.375% | 19,912 | 19,924 |
| v13b raw | 5.305% | 3.620% | 18,938 | 19,275 |
| v13b + matched CG | **0.225%** | **0.000%** | **19,954** | **19,999** |

因此最终下游优势不能简单归因于 v13b collision 更高或候选合并；matched CG 后其 collision 已不高于 baseline。

## 7. 关于评估口径的校准

GenSAR 论文推荐表使用 `1 positive + 99 random negatives`，而本阶段主要严格实验使用 `1 + 999`。在相同 20K train-only best checkpoint 上改用 99 negatives、beam 30 后：

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-faithful | 0.1862 | 0.1020 | 0.2370 | 0.1175 |
| **v13b + CG-Sinkhorn** | **0.3566** | **0.2422** | **0.5538** | **0.3682** |

这解释了论文表格绝对值明显更高的主要原因。不同 negative 数量、beam、test size、task 比例和 representation 时段的结果不能直接横向比较。

## 8. 本阶段得到的关键认识

1. **共享 prefix 与多任务训练并不冲突。** Prefix/suffix 是 SID 结构，6-task 是下游训练方式；共享结构可以直接使用 GenSAR 多任务 pipeline。
2. **Suffix 重构的不是 next item。** Rec suffix 表示当前 item 的行为 view；历史到 next-item 是下游 SeqRec 任务，二者目标层级不同。
3. **单层 code usage 均衡不保证完整 SID 唯一。** Collision 来自层间条件相关性和同 route item discrimination，不只由 codebook 容量决定。
4. **追求 collision=0 不是正确目标。** 强 instance separation 或大比例 post-hoc reassignment 会破坏局部 topology，导致 nDCG 下降。
5. **Representation 与 quantization 必须共同设计。** 简单提高 embedding 质量并不会自动让 SID 更容易生成；v13b 的收益来自 multi-view anchor、任务分解与层级 route 的组合。
6. **Search 比 Rec 更难。** 大量 item 共享相同 pseudo-query，Search relevance 容易形成 prototype；需要 identity code 在同 query route 内继续区分。
7. **严格时序切分是下一阶段的前提。** all-behavior representation 会混入未来状态，无法用于评估 drift 后只更新一个 suffix 是否有效。

## 9. 当前限制

- 最终严格 paired 对照仍只有 seed 2024；正式论文需要至少 3 seeds 和显著性检验。
- 全量 62.8K 实验只训练 3 epochs 且测试每任务 1,000 条，未证明充分收敛。
- v13b prefix 含 t0 Search/Rec 信息，因此“prefix 永远不需要更新”目前只是待验证假设。
- CG-Sinkhorn 仍是导出期处理；虽然 matched 后公平，但下一阶段必须记录漂移更新导致的 code changed rate，不能靠全局重新分配掩盖更新成本。
- 当前 pseudo-query 是构造信号，不等于真实商业搜索日志；结论应限定在现有 Amazon Electronics/GenSAR-faithful 数据构造内。

## 10. 下一阶段：Temporal Drift 与 SID 局部更新

下一阶段记为阶段5，核心问题从“t0 SID 是否有效”转为：

> 当 Search 或 Rec 信号从 t0 漂移到 t1/t2 时，固定 shared prefix 与未漂移任务 suffix，仅用新时段数据更新发生漂移任务的 low-rank adapter、suffix codebook 或 code assignment，能否以较小更新成本维持下游性能？

初步实验轴如下：

```text
drift type:
  Rec-only drift
  Search-only drift
  coupled Search+Rec drift

update strategy:
  no update
  full SID retraining
  task suffix code reassignment only
  task adapter/LoRA update + frozen suffix codebook
  task adapter/LoRA update + suffix codebook update

evaluation:
  downstream HR/nDCG retention
  prefix changed rate
  unaffected suffix changed rate
  affected suffix changed rate
  SID collision and topology drift
  update time, trainable parameters and replay requirement
```

阶段5首先应在 20K strict 数据上按时间构造 `t0 -> t1 -> t2`，分别模拟 Search-only 与 Rec-only drift；在确认更新协议无泄漏且能稳定复现后，再扩展到 coupled drift 和 62.8K 全量数据。
