# 阶段0_2026-07-09：生成式 Search-Recommendation 中动态部分共享 SID 的选题梳理

## 1. 本阶段讨论目标

本阶段围绕一个初始想法展开：

> 在生成式搜索与推荐中，现有方法通常为每个 item 生成一套 Semantic ID。是否可以设计一套“共享前缀 + 差异化后缀”的 SID，使 search 和 recommendation 共享通用 item 语义，同时保留任务特定语义？

经过讨论后，初始想法被进一步收束为：

> 面向统一生成式 Search-Recommendation 的动态、可诊断、可局部刷新的部分共享 Semantic ID。

更具体地说，不再把“shared prefix + task-specific suffix”本身作为核心创新，而是将其作为结构基础，研究其在 temporal drift、task conflict 和 SID refresh 场景下的价值。

---

## 2. 初始 Prefix/Suffix SID 想法的创新性判断

初始方案为：

```text
SID_i^search = [shared prefix_i | search suffix_i]
SID_i^rec    = [shared prefix_i | rec suffix_i]
```

其中：

- shared prefix 表示 item 的通用内容语义或稳定身份语义；
- search suffix 表示 query-item relevance；
- rec suffix 表示 collaborative behavior、co-occurrence、sequential transition 等推荐语义。

本阶段判断：

1. 这个结构本身有直觉合理性。
2. 但如果仅将其作为静态 SID 结构创新，创新性不足。
3. 已有 joint search-recommendation 论文中已经出现非常接近的 shared/specific 或 prefix-share 设计。
4. 更有潜力的方向是把这种结构用于动态维护、局部更新、任务冲突诊断和抗漂移。

因此，后续不建议使用如下表述作为论文主贡献：

```text
We propose shared-prefix and task-specific-suffix Semantic IDs.
```

更合理的表述是：

```text
We study drift- and conflict-aware modular Semantic ID refresh for unified generative search and recommendation.
```

## 3. 关键已有工作与边界

### 3.1 GenSAR: Unified Generative Search and Recommendation

论文链接：https://arxiv.org/abs/2504.05730

GenSAR 是目前与初始想法最接近的已有工作之一。其核心思想是统一 search 和 recommendation，并为 item 构造 dual-purpose identifiers。

它认为：

- search 更依赖 semantic relevance；
- recommendation 更依赖 collaborative signals；
- 单一 item representation 容易造成 search/rec trade-off。

其 SID 设计包含：

```text
shared codebooks
semantic-specific codebooks
collaborative-specific codebooks
```

大致流程为：

```text
semantic embedding + collaborative embedding
        ↓
shared codebooks 生成 shared codes
        ↓
semantic residual / collaborative residual
        ↓
semantic-specific codes
collaborative-specific codes
```

最终 item 可以拥有：

```text
semantic identifier: shared codes + semantic-specific codes
collaborative identifier: shared codes + collaborative-specific codes
```

这说明“共享部分 + 任务特定部分”的静态结构已经有人做过。

GenSAR 还设计了多任务训练：

- next recommendation item prediction；
- next search query prediction；
- next search item prediction；
- Desc2ID；
- ID2Desc。

GenSAR 的局限是：

- 主要关注静态统一建模；
- 没有系统研究 temporal drift；
- 没有研究 SID refresh；
- 没有研究更新 rec identifier 是否破坏 search，或更新 search identifier 是否破坏 rec。

这为后续选题留下空间。

### 3.2 Semantic IDs for Joint Generative Search and Recommendation

论文链接：https://arxiv.org/abs/2508.10478

这是 Spotify / RecSys 2025 LBR 工作，重点是系统比较 unified generative S&R 中不同 SID 构造策略。

其 benchmark：

```text
MovieLens-25M + Gemini-2.0-flash 生成的 synthetic search queries
```

核心 SID 策略包括：

- Search-based ID；
- Rec-based ID；
- Separate；
- Prefix-share；
- Fused concat；
- Fused SVD；
- Multi-task。

其中 Prefix-share 的形式与初始想法非常接近：

```text
shared codebook
search-specific codebook
recommendation-specific codebook
```

最终：

```text
SID_i^search = shared tokens + search-specific tokens
SID_i^rec    = shared tokens + rec-specific tokens
```

该论文的重要结论是：

- Search-based ID 在 search 上好，在 rec 上差；
- Rec-based ID 在 rec 上好，在 search 上差；
- Prefix-share 静态效果较差；
- Multi-task / Fused SVD 等 embedding-level fusion 方法表现更稳；
- RQ-KMeans 在该设置下优于 RQ-VAE。

这篇工作对本课题有两个重要启发：

1. 不能只做 naive prefix-share。
2. 需要解释为什么已有 Prefix-share 静态效果不好，而新的方法在 dynamic drift 场景下仍有价值。

### 3.3 Dynamic / Stale SID 相关工作

已有若干工作开始关注 recommendation-only 场景中的 dynamic SID 或 SID staleness。

重要相关工作包括：

- Mitigating Collaborative Semantic ID Staleness in Generative Retrieval  
  https://arxiv.org/abs/2604.13273

- ChronoSID / time-aware SID 相关工作  
  https://arxiv.org/abs/2607.03918

- SSRLive: Live Streaming Recommendation with Dynamic Semantic ID  
  https://arxiv.org/abs/2606.06970

这些工作说明：

- 纯 recommendation 场景中的 dynamic SID 已经开始变热；
- “静态 SID 会 stale，需要刷新”这个问题本身不再足够新；
- 但这些工作主要不处理 joint search-recommendation；
- 也不处理 partially shared SID 在 search/rec 两个任务间的动态维护与冲突诊断。

因此，本课题不能写成：

```text
Dynamic Semantic IDs for Generative Recommendation
```

更合理的差异化是：

```text
Dynamic maintenance of partially shared Semantic IDs for unified generative search and recommendation.
```

## 4. Prefix-share 与 Multi-task 的区别和可结合性

本阶段明确了 Prefix-share 与 Multi-task 并不是互斥方案。

### 4.1 Prefix-share

Prefix-share 是 SID 结构层面的设计：

```text
SID_i^search = [shared prefix_i | search suffix_i]
SID_i^rec    = [shared prefix_i | rec suffix_i]
```

其共享发生在：

```text
token / codebook structure
```

优点：

- 显式区分共享语义和任务特定语义；
- 可解释性较强；
- 天然适合局部更新；
- 可以只刷新 rec suffix 或 search suffix。

缺点：

- 静态效果不一定好；
- 如果没有约束，shared prefix 和 suffix 可能信息重复；
- 生成模型需要学习更复杂的 task-specific ID space。

### 4.2 Multi-task

Multi-task 是 embedding 学习阶段的训练方式：

```text
L = L_search + L_rec
```

它训练一个统一 item embedding，使其同时吸收 query-item relevance 和 user-item interaction / item-item co-occurrence，然后量化成单一 SID：

```text
SID_i = Quantize(e_i)
```

其共享发生在：

```text
representation learning
```

优点：

- 每个 item 只有一套 SID；
- 静态 benchmark 上通常更稳；
- search 和 rec token 知识完全共享。

缺点：

- search/rec 冲突被压进同一个 embedding；
- 不容易诊断哪个任务导致退化；
- 行为分布漂移时可能需要整体刷新；
- 更新 rec 信号可能破坏 search 语义，反之亦然。

### 4.3 二者可以结合

一个更合理的方向是：

```text
multi-task learned shared prefix
+
task-residual suffix
```

也就是：

```text
z_i^shared = f_shared(item)
z_i^search = f_search(item, search signals)
z_i^rec    = f_rec(item, rec signals)

P_i = Q_shared(z_i^shared)
S_i = Q_search(z_i^search residual)
R_i = Q_rec(z_i^rec residual)
```

最终：

```text
SID_i^search = [P_i | S_i]
SID_i^rec    = [P_i | R_i]
```

该组合可以同时利用：

- Multi-task 的静态性能优势；
- Prefix-share 的结构可解释性；
- suffix 的局部刷新能力；
- prefix 的稳定语义锚点作用。

## 5. 避免 Prefix 和 Suffix 信息重复

这是本阶段讨论中非常重要的技术点。

如果不加约束，prefix/suffix 容易退化为形式上的拆分：

```text
prefix 编码了 search/rec 特定信息
suffix 又重复编码 item 内容语义
```

这样会导致：

- 可解释性消失；
- 局部刷新意义变弱；
- suffix refresh 可能仍然破坏 shared semantics；
- prefix-share 静态性能可能不稳定。

### 5.1 Spotify Prefix-share 是否做了去冗余

本阶段判断：Spotify RecSys 2025 LBR 的 Prefix-share 方法没有显式做 prefix/suffix 去冗余或 disentanglement。

它主要是结构上使用：

```text
shared codebook + search-specific codebook + rec-specific codebook
```

但没有明确使用：

- orthogonality loss；
- mutual information minimization；
- adversarial disentanglement；
- residual learning；
- prefix/suffix role constraints。

这可能是其 Prefix-share 静态表现较差的原因之一。

### 5.2 可采用的去冗余方法

#### 方法一：Residual Learning

先让 shared prefix 学公共信息，然后 suffix 只学 prefix 解释不了的任务残差。

示意：

```text
e_search_res = e_search - stopgrad(Proj_search(P_i))
e_rec_res    = e_rec    - stopgrad(Proj_rec(P_i))

S_i = Q_search(e_search_res)
R_i = Q_rec(e_rec_res)
```

这是最适合本课题的方法，因为它天然对应：

```text
stable shared prefix + refreshable task residual suffix
```

#### 方法二：Orthogonality / Decorrelation Loss

让 prefix 表示和 suffix 表示低相关：

```text
L_orth = || H_P^T H_S ||_F^2 + || H_P^T H_R ||_F^2
```

或使用 cross-covariance penalty：

```text
L_decorr = || Cov(P, S) ||_F^2 + || Cov(P, R) ||_F^2
```

优点是实现简单、容易解释。

#### 方法三：Mutual Information Minimization

最小化：

```text
I(P; S), I(P; R)
```

可以用 CLUB、MINE、HSIC 等估计器。但实现和调参复杂，未必适合作为第一版核心方案。

#### 方法四：Adversarial Task Disentanglement

让 prefix 更 task-invariant，让 suffix 更 task-specific。

示意：

```text
task_pred = C(P_i)
```

通过 gradient reversal 让 prefix 难以预测任务来源，同时让 suffix 能预测任务来源。

需要注意：prefix 不是完全无任务信息，而是应保留 search 和 rec 共同需要的信息。

#### 方法五：Prefix/Suffix Bottleneck

通过限制容量减少重复编码：

```text
prefix: 短、稳定、低频更新
suffix: 短、任务残差、高频更新
```

可结合：

- prefix-only decoding；
- suffix masking；
- codebook size 控制；
- prefix dropout；
- suffix dropout。

#### 方法六：Staged Training

一个实用流程：

1. 先用 multi-task objective 训练 shared prefix；
2. 冻结 prefix；
3. 用 prefix 表现不好的样本训练 task suffix；
4. 最后小学习率联合微调。

该流程能让 suffix 更像“补充模块”，而不是重新学习完整 item identity。

## 6. 动态更新、任务冲突诊断、抗漂移是否太杂

本阶段结论：三者可以放在同一篇文章中，但不能并列作为三个独立目标。

更合理的逻辑关系是：

```text
抗漂移：最终目标
动态更新：主要方法
任务冲突诊断：分析工具和 refresh 决策依据
```

统一问题表述：

> 生成式 Search-Recommendation 中的 Semantic ID 在动态环境下会失效，而失效来源包括行为漂移和任务冲突；因此需要一种可局部更新、可诊断的 SID 机制。

建议不要写成：

```text
We study dynamic update, task conflict diagnosis, and anti-drift.
```

而应写成：

```text
We study diagnosis-guided modular SID refresh under temporal drift for unified generative search and recommendation.
```

## 7. 数据集与 Benchmark 判断

### 7.1 Prefix-share / Joint S&R 已有 benchmark

已有相关工作主要使用：

1. MovieLens-25M + LLM-generated queries  
   用于 Spotify / RecSys 2025 LBR。

2. Amazon semi-synthetic S&R + commercial S&R logs  
   用于 GenSAR。

MovieLens 设置的优点是可复现，缺点是 search query 是 synthetic，不是真实 search log，也不适合真实 search drift。

GenSAR 的 Amazon / commercial 设置更接近 search-rec，但公开复现难度和协议复杂度更高。

### 7.2 Temporal drift 主实验数据

适合做 recommendation temporal drift 的数据集包括：

- Amazon Reviews 2023；
- EB-NeRD；
- KuaiRand；
- Amazon-M2 / KDD Cup 2023。

其中：

- Amazon Reviews 2023 适合电商推荐、长时间跨度、item metadata、冷启动和行为漂移；
- EB-NeRD 适合新闻推荐、topic drift、item freshness、短生命周期内容；
- KuaiRand 适合短期行为漂移、多反馈、曝光偏差研究；
- Amazon-M2 适合 session recommendation、locale/domain shift。

### 7.3 Search drift 的困难

公开数据中很少同时具备：

```text
真实 search query log
+ recommendation log
+ 共享 item universe
+ 时间戳
+ item metadata
```

因此更现实的实验设计是：

```text
主实验：真实 rec temporal drift
辅助实验：joint search-rec task conflict
可选实验：半合成 search/query drift
```

不要把半合成 search drift 作为唯一主贡献，否则容易被质疑真实性。

## 8. 建议的论文定位

不建议的题目方向：

```text
Dynamic Semantic IDs for Generative Recommendation
Shared Prefix and Task-Specific Suffix Semantic IDs
```

这两种表述分别容易撞：

- recommendation-only dynamic SID；
- static prefix-share / shared-specific SID。

更建议的题目方向：

```text
Drift- and Conflict-Aware Modular Semantic IDs for Unified Generative Search and Recommendation
```

或：

```text
Diagnosis-Guided Semantic ID Refresh for Dynamic Generative Search-Recommendation
```

或：

```text
Multi-Task Shared and Residual Semantic IDs for Dynamic Generative Search and Recommendation
```

核心 novelty 应该表述为：

```text
Existing multi-task SID achieves strong static performance but entangles task-specific signals,
making it brittle under temporal drift.

Existing prefix-share SID provides structural modularity but lacks principled training for
shared and task-specific components.

We propose a multi-task shared-prefix and task-residual suffix SID framework,
enabling both strong static performance and selective refresh under drift.
```

## 9. 可能的方法框架草案

### 9.1 SID 结构

```text
SID_i^search = [P_i | S_i]
SID_i^rec    = [P_i | R_i]
```

其中：

- `P_i`：multi-task shared prefix；
- `S_i`：search residual suffix；
- `R_i`：recommendation residual suffix。

### 9.2 训练目标

可能包含：

```text
L = L_gen
  + λ1 L_shared_multitask
  + λ2 L_search_residual
  + λ3 L_rec_residual
  + λ4 L_decorr
  + λ5 L_align
  + λ6 L_churn
```

其中：

- `L_gen`：生成式 retrieval next-token loss；
- `L_shared_multitask`：shared prefix 的 search/rec 多任务表示学习；
- `L_search_residual`：query-item relevance residual；
- `L_rec_residual`：collaborative residual；
- `L_decorr`：prefix/suffix 去相关；
- `L_align`：刷新后 SID 与旧 checkpoint 兼容；
- `L_churn`：减少不必要 SID 改动。

### 9.3 动态刷新

可采用：

```text
drift detection
    ↓
select item subset
    ↓
select refresh target: search suffix / rec suffix / both
    ↓
suffix refresh
    ↓
checkpoint-compatible alignment / light finetuning
```

关键是避免 full SID refresh。

## 10. 需要重点验证的实验问题

### 10.1 静态性能

验证方法不能比已有静态 baseline 差太多：

- Multi-task SID；
- Prefix-share SID；
- Separate SID；
- Fused SVD / fused concat；
- Search-only SID；
- Rec-only SID。

### 10.2 Drift 下的性能

按时间窗口评估：

```text
train on T0
evaluate on T1, T2, T3
```

比较：

- static SID；
- full refresh；
- multi-task SID refresh；
- prefix-share refresh；
- proposed modular suffix refresh。

### 10.3 SID Churn 与兼容性

报告：

- SID Churn Rate；
- Prefix Churn Rate；
- Suffix Churn Rate；
- Valid SID Rate；
- Collision Rate；
- old checkpoint performance；
- light finetuning cost。

### 10.4 任务冲突

报告：

```text
refresh rec suffix 后 search 是否下降
refresh search suffix 后 rec 是否下降
full refresh 是否造成更强 task interference
```

可定义：

```text
Task Interference Score
Refresh Benefit / Churn Cost
```

### 10.5 Prefix/Suffix 解耦诊断

建议报告：

- Prefix-only performance；
- Suffix-only performance；
- Prefix + suffix performance；
- prefix/suffix embedding covariance；
- CKA similarity；
- neighbor overlap；
- 同一 prefix bucket 内 task residual 是否分化。

## 11. 本阶段形成的核心判断

1. “共享前缀 + 任务后缀”作为静态结构不够新。
2. GenSAR 和 Spotify RecSys 2025 已经覆盖了很多 shared/specific SID 设计。
3. recommendation-only dynamic SID 已经开始变热，不能只做普通 SID refresh。
4. 目前尚未看到系统研究 dynamic SID refresh + partially shared joint search-rec SID 的工作。
5. Prefix-share 和 Multi-task 不冲突，可以组合。
6. 更有潜力的方向是：multi-task shared prefix + task-residual suffix + selective refresh。
7. 避免 prefix/suffix 信息重复是关键技术点，也可以作为区别于已有 Prefix-share 的重要贡献。
8. 实验上应把真实 rec temporal drift 作为主支撑，把 joint search-rec task conflict 作为结构价值验证。
