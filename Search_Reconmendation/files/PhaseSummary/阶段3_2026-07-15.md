# 阶段3_2026-07-15：v1 数据管线与 TF-IDF SID 实验验证

## 1. 本阶段目标

本阶段承接阶段2的方法设计，目标从“方案规划”进入“工程验证”：

```text
先构建一个可运行的 search-rec mixed generative SID 实验平台，
用 v1 TF-IDF / Hashing SID 验证数据、SID、训练、解码、评估链路是否可靠。
```

本阶段不追求最终论文效果，而是回答三个问题：

1. Search / Rec / Mixed 三种任务是否能稳定构造样本并训练。
2. `[shared prefix | task-specific suffix]` 形式的 SID 是否能被生成模型学习。
3. 当前 v1 是否足够作为 v2 论文版方法的 sanity platform。

最终结论：

```text
v1 已完成实验平台和 sanity 验证。
TF-IDF SID 本身表达能力有限，不应继续深挖 v1 效果。
下一阶段应进入 v2：learned / neural item representation + paper-level SID generation。
```

## 3. 当前输入输出定义

### 3.1 Search

Search 任务形式：

```text
input:
  <SEARCH> query text / query terms

target:
  item 的 search SID
```

例子形式：

```text
input_text:
  <SEARCH> wireless bluetooth earbuds

target_sid:
  <P1_x> <P2_y> <S1_a> <S2_b>
```

### 3.2 Recommendation

Rec 任务形式：

```text
input:
  <REC> 历史 item 的 rec SID 序列

target:
  下一个 item 的 rec SID
```

当前设置：

```text
max_history_len = 5
min_history_len = 1
```

例子形式：

```text
input_text:
  <REC> <P1_5> <P2_1> <R1_15> <R2_0>

target_sid:
  <P1_1> <P2_2> <R1_4> <R2_5>
```

因此当前 rec 是 next-item prediction，不是 session-level generation。

### 3.3 Mixed

Mixed 任务将 search 与 rec 样本合并训练：

```text
train.jsonl = train.search.jsonl + train.rec.jsonl
test.jsonl  = test.search.jsonl + test.rec.jsonl
```

模型共享同一套生成模型和 token vocabulary，通过 `<SEARCH>` / `<REC>` task token 区分任务。

## 4. v1 SID 生成方法

本阶段 v1 SID 的核心目标是构造可训练的 partially shared SID：

```text
Search SID:
  [shared prefix | search suffix]

Rec SID:
  [shared prefix | rec suffix]
```

### 4.1 表示来源

v1 使用轻量文本与统计特征，而不是 neural representation。

主要特征来源：

- title；
- category；
- brand；
- description；
- query terms；
- user co-occurrence / sequence context。

v1 中使用 TF-IDF / HashingVectorizer 风格特征构建 item 表示。

这一点是 v1 的主要限制：

```text
TF-IDF / hashing representation 偏浅，
不能充分捕捉语义、跨任务结构、时间漂移和用户行为模式。
```

因此 v1 的目标不是最终效果，而是验证实验链路。

### 4.2 balanced SID

本阶段重点调试了 balanced SID。

最终选中的 balanced SID：

```text
sid_v1_balanced_200_coarseP8_4_suf32_8
```

mapping 路径：

```text
/data/cjk/Search_Reconmendation/stage3/data/product_search_electronics/sid_v1_balanced_200_coarseP8_4_suf32_8/sid_mapping.v1.json
```

结构统计：

```text
prefix unique: 32
prefix bucket size: 6-7
search collision: 0
rec collision: 0
prefix-suffix NMI: 0.7906
```

这一版相比早期方案更合理：

- prefix 不再几乎等价于 item identity；
- search / rec suffix 无碰撞；
- prefix bucket 有一定共享粒度；
- 可以支持 mixed 训练。

### 4.3 old unbalanced SID

为了对照，构造了 old unbalanced 200-item mapping。

mapping 路径：

```text
/data/cjk/Search_Reconmendation/stage3/data/product_search_electronics/sid_v1_old_unbalanced_200_p128_32/sid_mapping.v1.json
```

它来自早期 `sid_v1_smoke_p128_32`，并限制到相同的 200 candidate items。

## 5. 训练模型与评估方式

本阶段使用轻量 tiny Transformer 生成模型，而不是最终论文模型。

训练脚本：

```text

```

主要训练设置：

```text

nhead = 4
num_layers = 2
dim_feedforward = 512
dropout = 0.05
lr = 0.001
num_beams = 10
eval_ks = 1,5,10
checkpoint_metric = item_hit_at_10
```

评估指标：

```text

```

其中本阶段主要关注：

```text

```

Mixed 评估必须看 `by_task`，否则 search 任务过强会掩盖 rec 任务表现。

## 6. 关键实验结果

### 6.1 200-test 快速验证

早期快速实验使用 capped test：

```text
search-only: 200 test
mixed:       400 test = 200 search + 200 rec
```

结果：

| SID | Setting | Search Hit@10 | Rec Hit@10 | 备注 |
|---|---:|---:|---:|---|
| balanced `coarseP8_4_suf32_8` | search-only | 0.985 | - | search 单任务很高 |
| old unbalanced `p128_32` | search-only | 0.990 | - | search 单任务也很高 |
| balanced `coarseP8_4_suf32_8` | mixed | 0.995 | 0.200 | rec 没明显被 mixed 拉低 |
| old unbalanced `p128_32` | mixed | 0.965 | 0.195 | rec 基本持平，search 略低 |
| balanced `coarseP8_4_suf32_8` | rec-only | - | 0.220 | 200-test 快速版 |
| old unbalanced `p128_32` | rec-only | - | 0.180 | 200-test 快速版 |

快速实验结论：

```text
mixed 没有导致 rec 明显坍缩。
balanced SID 在 rec-only 快速版上略优，但 mixed 下优势不明显。
```

### 6.2 完整 1000 / 2000 test

最终完整评估：

```text
search-only: 1000 test
mixed:       2000 test = 1000 search + 1000 rec
```

结果：

| Setting | SID | Overall Hit@10 | Search Hit@10 | Rec Hit@10 |
|---|---|---:|---:|---:|
| search-only, 1000 test | balanced `coarseP8_4_suf32_8` | 0.978 | 0.978 | - |
| search-only, 1000 test | old unbalanced `p128_32` | 0.973 | 0.973 | - |
| mixed, 2000 test | balanced `coarseP8_4_suf32_8` | 0.587 | 0.978 | 0.196 |
| mixed, 2000 test | old unbalanced `p128_32` | 0.583 | 0.957 | 0.209 |

完整实验结论：

1. Search 任务整体偏容易，两个 SID 都能达到很高 Hit@10。
2. Mixed 训练没有导致 rec 崩溃。
3. balanced SID 相比 old unbalanced 没有显著总体优势。
4. balanced SID 在 search 上略好，但 rec 上略低。
5. v1 已足够证明数据管线、训练、解码、评估链路可用。

## 7. 本阶段发现的问题

### 7.1 v1 SID 表达能力不足

v1 使用 TF-IDF / hashing 特征，因此 item representation 较浅。

这会限制：

- item semantic structure；
- search-rec shared structure；
- user behavior representation；
- temporal drift modeling；
- prefix / suffix 的功能分离。

因此不能把 v1 的指标视为方法上限。

### 7.2 Search 任务偏容易

Search-only Hit@10 接近 0.98，说明当前 pseudo-query / candidate setup 对 search 任务区分度有限。

后续 v2 需要考虑：

- 更真实的 pseudo-query 构造；
- 更难的 negative / candidate setting；
- 更大 item set；
- search-rec mixed 下更合理的任务冲突诊断。

### 7.3 Rec 输入信息较弱

当前 rec 输入是纯 SID history：

```text
<REC> SID_1 SID_2 ... SID_k -> next SID
```

history 长度最多 5。

这与许多生成式推荐论文中的 SID->SID 设置一致，但在小数据和短历史下学习难度较高。

### 7.4 codebook / SID 分布仍需论文版约束

本阶段已经尝试 balanced assignment，但还不是论文级方法。

v2 仍需要系统设计：

- balanced code assignment；
- prefix bucket size 控制；
- suffix collision control；
- prefix-suffix redundancy penalty；
- dynamic refresh 时的 token stability。

## 8. 是否需要继续优化 v1

当前判断：

```text
不建议继续在 TF-IDF v1 上深挖效果。
```

原因：

1. v1 已经证明工程链路可用。
2. balanced SID 没有在完整实验中显著赢 old unbalanced。
3. search 任务过容易，不适合作为主要创新判断。
4. rec 任务受短 history、小数据、浅 SID 表示共同影响。
5. 真正论文创新应来自 learned / neural item representation 和 dynamic SID 机制。

因此 v1 的角色应被固定为：

```text
v1 = sanity platform / ablation baseline / engineering scaffold
```

而不是：

```text
v1 = final method
```

## 10. v2 初始方向

v2 不应只是替换 TF-IDF 特征，而应升级为论文版方法。

核心方向：

```text
learned / neural item representation
```

建议结构：

```text
h_i^S:
  search-side item representation

h_i^R:
  recommendation-side item representation

h_i^shared:
  attention / gating fusion of h_i^S and h_i^R
```

SID 生成：

```text
shared prefix:
  generated from h_i^shared

search suffix:
  generated from search-specific residual / h_i^S

rec suffix:
  generated from rec-specific residual / h_i^R
```

后续重点问题：

1. `h_i^S` 和 `h_i^R` 如何学习；
2. search / rec 原始 embedding 空间如何对齐到共同空间；
3. shared prefix 如何避免与 suffix 信息重复；
4. balanced code assignment 如何与 neural representation 结合；
5. temporal drift 下如何判断刷新 prefix 还是 suffix；
6. 动态刷新后如何保持旧 checkpoint 兼容性。
