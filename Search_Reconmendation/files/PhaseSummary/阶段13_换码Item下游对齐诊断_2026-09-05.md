# 阶段13：换码 Item 的下游对齐诊断（2026-09-05）

## 1. 本阶段问题

阶段12的 W9 留出实验显示，Detector V3 比 SupportTopK 覆盖更多人工注入的 emerging target，但 V3-only 实际换码 item 对应的 83 条 W10 样本在所有方法上均为 0 nDCG@10。本阶段因此检验：

1. 换码 item 是否缺少 Rec 行为训练信号；
2. 是否只是 `Item2Index / Index2Item` 对新 SID 的直接对齐不足；
3. 固定总训练预算后，提高换码 item 的 alignment 权重能否转化为总体收益；
4. 任务局部 LoRA 能否避免 Rec 更新干扰 Search。

所有方法选择仅在 W6 update / W7 test 上进行，没有使用 W9/W10 调参。

## 2. 监督信号审计

V3 在 W6 选中 51 个 item，其中 33 个实际更换 Rec suffix；W9 选中 51 个，其中 36 个实际换码。

| 窗口 | 子集 | update target 中位数 | validation target 中位数 | test target 中位数 | test 零支持 item |
|---|---|---:|---:|---:|---:|
| W6/W7 | selected 51 | 60 | 10 | 6 | 3 |
| W6/W7 | recoded 33 | 51 | 10 | 6 | 3 |
| W9/W10 | selected 51 | 73 | 8 | 7 | 1 |
| W9/W10 | recoded 36 | 66.5 | 7 | 6 | 1 |

换码 item 并不缺少当前窗口的 Rec target 行为。真正稀疏的是直接 SID 对齐：在 1,800-item balanced alignment pool 中，每个 item 只获得 1 条 Rec `Item2Index` 和 1 条 Rec `Index2Item`，合计 2 条直接监督。

## 3. A1：固定预算的 Recode-aware Alignment

### 3.1 设置

- 从同一个 `CRD_W5_Fixed_s2024` checkpoint 开始；
- T5-small、1 epoch、seed 2024；
- `SeqRecWithSrcHis + PerSrcWithRecHis + Item2Index + Index2Item`；
- Search alignment 始终为同一组 1,800 个唯一 item；
- Rec alignment 总 occurrence 始终为 1,800；
- 33 个实际换码 item 分别出现 1/2/4/8 次，多出的 occurrence 通过移除普通 filler item 抵消。

### 3.2 W7 结果

| Repeat | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 | Recoded-target nDCG@10 |
|---:|---:|---:|---:|---:|---:|
| R1 | **0.0314** | **0.020111** | **0.0400** | **0.021585** | 0.062610 |
| R2 | 0.0310 | 0.019889 | 0.0386 | 0.020529 | **0.063624** |
| R4 | **0.0314** | 0.019991 | 0.0396 | 0.020857 | **0.063624** |
| R8 | **0.0314** | 0.019995 | 0.0394 | 0.020796 | **0.063624** |

R2 使 297 条 recoded-target 样本的 nDCG@10 增加 0.001014，但 R4/R8 没有进一步收益。同时，未换码 target 的 nDCG@10 从 0.017427 降为 R2 的 0.017128；虽然 Search 数据和 Search alignment 未变，Search nDCG@10 仍下降 3.4%–4.9%。

这说明重复直接对齐只能缓解局部问题；因为四个任务共享全部 T5 参数，Rec alignment 权重变化仍会引入跨任务梯度干扰。

预先设定的 gate 要求“recoded target 改善、总体 Rec 不下降、Search 相对下降不超过 1%”，R2/R4/R8 均未通过。因此没有事后选择 repeat factor，也没有扩展到 Support 或 W9，避免在已失败的机制上追加无意义对照。

## 4. A2：Task-local Rec LoRA

### 4.1 设置

以 A1-R1 为冻结 base，只训练 attention `q/v` 的 rank-8 Rec LoRA：

- trainable parameters：294,912，占全模型 0.479%；
- 5,344 条 target 或最近 5 个 Rec history 涉及换码 item 的样本；
- 4,000 条未受影响 replay；
- Rec alignment 总预算 1,800，33 个换码 item 各出现 2 次；
- Rec 推理开启 LoRA，Search 推理关闭 LoRA。

### 4.2 W7 结果

| 方法 | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 | 换码 target nDCG@10 | 未换码 target nDCG@10 |
|---|---:|---:|---:|---:|---:|---:|
| A1-R1 | **0.0314** | **0.020111** | 0.0400 | 0.021585 | 0.062610 | **0.017427** |
| Task-local Rec LoRA | 0.0310 | 0.019736 | 0.0400 | 0.021585 | 0.062610 | 0.017028 |

Search 结果 JSON 与 base 逐字节相同，因此 task routing 的隔离是有效的。但 LoRA 对所有 Rec 请求生效，换码 target 没有改善，下降全部来自未换码 target。“冻结 base + 任务局部参数”可以保护 Search，但仍不能在 Rec 内部区分应更新与应保持的请求。

## 5. 阶段结论

### 5.1 已确认

1. Detector V3 换码 item 的当前行为支持量并不稀疏；稀疏的是新 SID 与 item 之间的直接对齐。
2. 增加一次换码 item alignment 已让局部子集改善，更多重复很快饱和。
3. 全参数联合微调会把 Rec 对齐变化传导到 Search；task-local LoRA 能完全避免这个跨任务副作用。
4. 当前两种简单补强都没有通过 W6 smoke gate，不应扩展多 seed 或在 W9 调参。

### 5.2 尚未解决

核心问题不再是 detector，而是“新 SID 如何在不遗忘旧能力的情况下被下游模型接纳”。后续若继续攻这个问题，需要的是 item/SID-aware 的兼容机制，例如旧新 SID alias/bridge、可寻址的 item-local memory，或真正的 change-conditioned routing；继续调 repeat factor、replay size 或通用 LoRA 学习率不是高价值方向。

## 6. 是否进入第二个自然漂移 Benchmark

当前 controlled benchmark 的评估已可阶段性关闭，可以进入第二个包含自然 Rec drift 的 benchmark，原因是：

- detector、selective SID update、下游增量训练、多 seed、holdout 和成本统计已经形成完整管线；
- W6/W9 已经提供了“优于 Fixed，但对 SupportTopK 的优势不稳定”的清晰边界；
- 换 benchmark 可以检验这个边界是数据集特性，还是方法的普遍限制。

但第二个 benchmark 不能被用来回避 alignment 问题。正式结果应同时报告：总体 Rec/Search、实际换码 target 子集、未换码 target 子集、SID 更新与下游更新成本。如果自然漂移上仍出现“detector 选对但新 SID 学不会”，就应将 old/new SID compatibility 升级为方法的必要组件。
