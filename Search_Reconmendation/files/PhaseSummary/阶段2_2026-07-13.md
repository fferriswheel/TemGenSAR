
```text
在 unified generative search-recommendation 中，

并尽量保持旧生成模型 checkpoint 的兼容性。
```

## 2. 论文问题定义

本工作关注 unified generative search-recommendation。

每个 item 同时服务两个任务：

```text
Search:
  给定 query / user context，生成目标 item 的 search SID。

Recommendation:
  给定 user history，生成下一个 item 的 rec SID。
```

现有问题：

1. 静态 shared SID 难以适应 temporal drift。
2. recommendation-only dynamic SID 不能处理 search-rec 两个任务之间的冲突。
3. naive prefix-share 缺少动态刷新机制，也缺少 prefix / suffix 角色约束。
4. full SID refresh 容易破坏旧 checkpoint 的 token 语义和生成能力。

因此，本工作的问题可以写成：

```text
How to dynamically maintain partially shared Semantic IDs for unified
generative search and recommendation under temporal drift, while deciding
whether to refresh shared prefixes or task-specific suffixes according to
cross-task drift patterns?
```

中文表述：

```text
在时间漂移下，如何动态维护 search-rec 部分共享的 Semantic ID，
并根据 Search 与 Rec 的漂移一致性，决定刷新 shared prefix 还是 task-specific suffix。
```

## 3. 数据与任务定义

Search 数据定义为：

```text
D^S = {(q, i, y, t)}
```

其中：

- `q`：query；
- `i`：item；
- `y`：relevance / click label；
- `t`：时间戳。

Recommendation 数据定义为：

```text
D^R = {(u, i, a, t)}
```

其中：

- `u`：user；
- `i`：item；
- `a`：interaction type；
- `t`：时间戳。

时间被切分为多个窗口：

```text
T0, T1, ..., Tk
```

基本流程：

```text
T0:
  训练初始 SID tokenizer 和 generative model。

T1...Tk:
  计算 search / rec 表示漂移；
  判断刷新位置；
  局部刷新 SID；
  评估 zero-shot checkpoint compatibility 和 light finetune 后性能。
```

## 4. SID 主结构

本阶段确定主方法不把 temporal suffix 放入 canonical item SID。

主结构为：

```text
Search SID_i = [P_i | S_i]
Rec SID_i    = [P_i | R_i]
```

其中：

- `P_i`：shared prefix，表示 search 与 rec 共同需要的稳定 item 语义；
- `S_i`：search suffix，表示 query-item relevance、lexical / semantic matching 等 search-specific residual；
- `R_i`：rec suffix，表示 collaborative filtering、sequential transition、co-occurrence 等 rec-specific residual。

默认 SID token 长度设为 4：

```text
Search SID_i = [P1_i, P2_i | S1_i, S2_i]
Rec SID_i    = [P1_i, P2_i | R1_i, R2_i]
```

默认 codebook size：

```text
256 per level
```

后续消融：

```text
prefix/suffix length:
  1/3, 2/2, 3/1

codebook size:
  128, 256, 512
```

## 5. Search / Rec 表示学习

对每个 item 分别构造 search-side 和 rec-side 表示：

```text
z_i^S = f_S(item text, query-item signals, search behavior)
z_i^R = f_R(item text, user-item interactions, sequential/collaborative signals)
```

其中：

- `z_i^S` 侧重 semantic relevance；
- `z_i^R` 侧重 collaborative signals。

因为两侧原始 embedding 空间可能不同，需要投影到共同空间：

```text
h_i^S = W_S z_i^S
h_i^R = W_R z_i^R
```

`W_S, W_R` 第一版使用轻量 MLP projection：

```text
W(x) = LayerNorm(MLP(x))
```

共同空间用于：

1. 生成 shared prefix；
2. 比较 search / rec 漂移方向；
3. 判断是否刷新 shared prefix。

---

## 6. Shared Representation Fusion

本阶段确定主方法使用 gating / attention fusion，而不是简单 mean pooling。

定义 gate：

```text
α_i = sigmoid(w^T [h_i^S ; h_i^R ; h_i^S ⊙ h_i^R ; |h_i^S - h_i^R|])
```

然后融合得到 shared representation：

```text
h_i^shared = α_i h_i^S + (1 - α_i) h_i^R
```

解释：

```text
如果 search 语义更可靠，shared 表示偏向 search；
如果 rec 协同信号更稳定，shared 表示偏向 rec；
如果二者一致，gate 得到折中表示。
```

第一版采用 scalar gate，原因是：

1. 更容易解释；
2. 比 dimension-wise gate 更稳定；
3. 方法复杂度可控。

消融设置：

```text
mean fusion
dimension-wise gate
attention fusion
```

shared prefix 由融合表示量化得到：

```text
P_i = Q_P(h_i^shared)
```

## 7. Task-residual Suffix

为了避免 prefix 和 suffix 重复编码同样信息，本阶段确定 suffix 不直接从 `z_i^S / z_i^R` 量化，而是从 residual 表示量化。

先用 prefix 重构或投影回任务空间：

```text
\hat{z}_i^S = g_S(P_i)
\hat{z}_i^R = g_R(P_i)
```

计算任务残差：

```text
r_i^S = z_i^S - stopgrad(\hat{z}_i^S)
r_i^R = z_i^R - stopgrad(\hat{z}_i^R)
```

再量化：

```text
S_i = Q_S(r_i^S)
R_i = Q_R(r_i^R)
```

最终：

```text
Search SID_i = [P_i | S_i]
Rec SID_i    = [P_i | R_i]
```

`stopgrad` 的作用是：

```text
避免 suffix 训练反向破坏 prefix 的公共语义。
```

这一设计是区别于 naive prefix-share 的关键。

## 8. 训练目标

总训练目标暂定为：

```text
L = L_search_gen
  + L_rec_gen
  + λ1 L_item_align
  + λ2 L_neighbor_align
  + λ3 L_residual
  + λ4 L_decorr
  + λ5 L_commit
```

其中：

### 8.1 Generative Loss

Search 生成目标：

```text
query / context -> [P_i | S_i]
```

Recommendation 生成目标：

```text
user history -> [P_i | R_i]
```

两者均使用 next-token negative log-likelihood。

### 8.2 Item-level Alignment

同一个 item 的 search / rec 表示在共同空间中靠近：

```text
L_item_align = -log exp(sim(h_i^S, h_i^R)/τ)
               / Σ_j exp(sim(h_i^S, h_j^R)/τ)
```

### 8.3 Neighbor-level Alignment

保持 search / rec 两侧的 item neighborhood 结构一致：

```text
L_neighbor = Σ_{i,j} || sim(h_i^S, h_j^S) - sim(h_i^R, h_j^R) ||^2
```

### 8.4 Residual / Decorrelation Loss

`L_residual` 鼓励 prefix 解释公共部分，suffix 解释任务残差。

`L_decorr` 约束 prefix 与 suffix 表示低相关：

```text
L_decorr = ||Cov(P, S)||_F^2 + ||Cov(P, R)||_F^2
```

### 8.5 Commitment Loss

`L_commit` 是 RQ-VAE / residual quantization 中常规的 codebook commitment loss。

## 9. 时间信息处理

本阶段确定：

```text
时间信息不作为 canonical item SID 的一部分。
```

原因：

1. 同一个 item 在不同时间会产生多个 temporal SID；
2. next-item prediction 时未来交互时间不一定已知；
3. search 和 rec 的时间语义不同；
4. temporal suffix 会增加 candidate deduplication 和 checkpoint compatibility 难度。

主方法中，时间作为 input context：

```text
Search input:
  <SEARCH> query tokens + time token -> [P_i | S_i]

Rec input:
  <REC> user history + gap/time token -> [P_i | R_i]
```

可使用的时间 token：

```text
absolute time bucket
relative time gap bucket
window index
```

Temporal suffix 作为 ablation：

```text
Search SID_i = [P_i | S_i | T_i]
Rec SID_i    = [P_i | R_i | T_i]
```

## 10. Drift Diagnosis

在时间窗口 `t-1` 和 `t` 之间，计算：

```text
Δ_i^S = h_{i,t}^S - h_{i,t-1}^S
Δ_i^R = h_{i,t}^R - h_{i,t-1}^R
```

漂移强度：

```text
D_i^S = ||Δ_i^S||
D_i^R = ||Δ_i^R||
```

方向一致性：

```text
A_i = cos(Δ_i^S, Δ_i^R)
```

邻域漂移一致性：

```text
v_i^S(j) = sim(h_{i,t}^S, h_{j,t}^S) - sim(h_{i,t-1}^S, h_{j,t-1}^S)
v_i^R(j) = sim(h_{i,t}^R, h_{j,t}^R) - sim(h_{i,t-1}^R, h_{j,t-1}^R)
```

```text
A_i^nbr = cos(v_i^S, v_i^R)
```

综合一致性：

```text
C_i = α A_i + β A_i^nbr
```

本阶段决定：

```text
gradient agreement 暂不放入主算法，只作为分析指标。
```

原因是 gradient-level diagnosis 成本更高，会使主方法显得过于复杂。

## 11. Selective Refresh Rule

刷新规则如下：

| Search drift | Rec drift | 一致性 | 更新策略 |
| --- | --- | --- | --- |
| 低 | 低 | - | 保持 `P_i, S_i, R_i` 不变 |
| 高 | 低 | - | 保持 `P_i, R_i`，刷新 `S_i` |
| 低 | 高 | - | 保持 `P_i, S_i`，刷新 `R_i` |
| 高 | 高 | 高 | shared prefix refresh candidate，并视情况重算 suffix residual |
| 高 | 高 | 低或负 | 保持 `P_i`，分别刷新 `S_i` 和 `R_i` |

prefix refresh 采用保守策略：

```text
不做任意 item-level prefix 更新，
而是按 prefix bucket / cluster 做更新。
```

具体规则：

```text
如果同一个 prefix bucket 中足够多 item 都发生 aligned drift，
才允许刷新该 bucket 的 shared prefix。
```

这样可以减少：

- prefix churn；
- token 语义抖动；
- 旧 checkpoint 失效风险。

## 12. Checkpoint-compatible SID Refresh

本阶段确定需要借鉴 stale SID 工作中的 token alignment 思路。

refresh 后不能直接使用新 token 编号，而应进行 old-new token alignment：

```text
old code tokens <-> new code tokens
```

alignment 分开做：

```text
prefix codebook alignment
search suffix codebook alignment
rec suffix codebook alignment
```

目标：

```text
让语义接近的新 token 尽量复用旧 token label。
```

refresh pipeline：

```text
1. 在新时间窗口生成 raw new SID。
2. 根据旧 SID / 新 SID 的 item overlap 和 code embedding 相似度做 token alignment。
3. 得到 checkpoint-compatible aligned SID。
4. 更新 legal SID trie。
5. warm-start 旧 generative model。
6. zero-shot evaluate。
7. light finetune。
```

核心区别：

```text
已有 stale SID 工作主要做 full collaborative SID refresh；
我们做 modular refresh，并区分 prefix / search suffix / rec suffix。
```

## 18. 论文贡献点草案

贡献点可以暂定为：

```text
1. We formulate dynamic maintenance of partially shared Semantic IDs
   for unified generative search and recommendation under temporal drift.

2. We propose a modular SID framework with gated shared-prefix fusion
   and task-residual suffix quantization, separating common item semantics
   from search- and recommendation-specific residuals.

3. We introduce a drift diagnosis and selective refresh mechanism that
   updates shared prefixes only under aligned cross-task drift, while

```

中文版本：

```text

   在 temporal drift 下的动态维护问题。

2. 提出 gated shared prefix + task-residual suffix 的模块化 SID 结构，
   将共同 item 语义与 search / rec 任务残差解耦。

3. 提出基于漂移诊断的选择性刷新机制：
   只有跨任务同向漂移时才刷新 shared prefix；
   任务单侧漂移或冲突漂移时刷新 task-specific suffix。
```

## 19. 本阶段形成的核心判断

1. Stage 2 的方法主线已经可以固定为 drift-aware partially shared SID。
2. 主 SID 结构为 `[shared prefix | task-specific suffix]`。
3. temporal signal 不进入 canonical SID，只作为 input context。
4. `h_i^shared` 主方法使用 gating fusion，mean fusion 作为 baseline / ablation。
5. suffix 采用 residual quantization，避免 prefix / suffix 信息重复。
6. common space 同时服务 shared prefix learning 和 drift diagnosis。
7. drift diagnosis 第一版使用 drift magnitude、drift direction cosine 和 neighbor drift agreement。
8. gradient agreement 暂不进入主算法，只作为分析指标。
9. prefix refresh 应保守，优先采用 prefix bucket / cluster-level refresh。
10. refresh 后需要做 prefix / search suffix / rec suffix 分模块 token alignment。
11. 数据路线先从 GenSAR / Amazon Product Search Electronics 跑通 S&R pipeline。
12. temporal drift 主实验迁移到 Amazon Reviews 2023 Electronics。
13. SID 初始超参采用 4 tokens、每层 codebook size 256，即 `[P1, P2 | S1, S2]` 和 `[P1, P2 | R1, R2]`。
