# 方法索引_2026-07-21：Search-Rec Shared SID 方法汇总

本文档用于统一目前实验中各版本的指代，避免后续讨论时混淆。

第 1-11 节主要记录早期 200-item sanity benchmark：

```text
data_dir:
/data/cjk/Search_Reconmendation/stage3/data/product_search_electronics

SID structure:
Search SID = [P1, P2 | S1, S2]
Rec SID    = [P1, P2 | R1, R2]

prefix codebook sizes = [8, 4]
suffix codebook sizes = [32, 8]
downstream train / valid / test = 16000 / 2000 / 2000
valid evaluation uses max 500 examples
```

第 12 节改用 GenSAR-Lite-5K，并以统一的 GenSAR 2-task、3-seed、1000-test 协议报告结果；两组数字不能直接横向比较。

第 15 节进一步扩展到分层采样的 GenSAR-Lite-20K；其训练样本数和候选 item 空间均与 5K 不同，因此只能在 20K 内部公平比较。

## 1. 总览表

| 方法 | 简称 | 核心思想 | 当前结论 |
|---|---|---|---|
| M0 | v1 TF-IDF SID | TF-IDF / HashingVectorizer 构造 shared prefix + task suffix | 工程链路已跑通，但表示能力有限 |
| M1 | Neural RQ SID | 用神经网络表示替代 TF-IDF，shared/task 表示进入 RQ-VAE | 效果接近 v1，collision 中等 |
| M2 | Balanced Neural RQ | M1 + balanced assignment | 略提升，说明均衡分配有用 |
| M3 | Adapter-Residual | 固定 shared prefix，task adapter 产生 `z_task0`，suffix 量化 `z_task0 - q_shared` | 可行，但不是最优 |
| M4 | Adapter-State | 固定 shared prefix，task adapter 产生 `z_task0`，suffix 直接量化 `z_task0` | 比 M3 稍好，是早期较强版本 |
| M5 | Prefix-Locked Continuation | prefix RQ-VAE 冻结，task adapter 在 prefix 基础上延续量化 suffix | 稳定、可解释，是重要中间版本 |
| M6a | TextEnc-Adapter-PLC | frozen text encoder + PLC + adapter | M5 的 text encoder 版本，效果较好 |
| M6b | TextEnc-LoRA-PLC | frozen text encoder + PLC + LoRA | search 强，但整体不如 M6a |
| M7a | TextEnc-Fusion-Adapter-PLC | common/task embedding 分开编码后 gating fusion，adapter task encoder | 中等，低于 M6a |
| M7b | TextEnc-Fusion-LoRA-PLC | M7a 的 LoRA 版本 | raw 指标最高，但 collision 很高 |
| M7b-Unique | M7b + uniqueness-aware assignment | 在生成阶段保证 full SID unique | 更公平，但 rec 明显下降 |
| M8a | Task-Signal Suffix Target | suffix 只重构 task signal，decoder 只看 suffix | valid 略升，test 未超过 M7b-Unique |
| M8b | M8a + In-Bucket Contrast | 加同 prefix 内 quantized suffix contrast | SID 统计对 rec 更差，未跑完整下游 |
| M8c | M8b + Transition Rec Target | rec target 改为 directed next-item transition | rec collision / rank 没改善，未跑完整下游 |
| M7b-v3c | Directed-Behavior-CG | aligned LoRA delta + directed Item2Vec + training/export CG-Sinkhorn | collision 低，但三 seed 下游未全面超过 native |
| M7b-v3d | Neighbor-CG | v3c 改回 neighbor Rec signal | 当前下游最强候选，但 export code 改写率约 45% |
| M7b-v4 | In-Prefix Differentiable Discrimination | 完整 SID collision + instance contrast + var/cov + gate floor | raw collision 和方差显著降低，但均值低于 v3d |
| M7b-v5 | Adaptive Collision + Topology Distillation | v4 判别约束自适应启用，并蒸馏 v3d 的同-prefix语义拓扑 | v5-B 是当前不依赖 post-hoc 的主候选 |

## 2. M0 / v1：TF-IDF SID Baseline

### 方法

M0 是最早的工程 sanity 版本，不使用 neural representation。

输入信息包括：

- title；
- category；
- brand；
- description；
- query terms；
- user co-occurrence / sequence context。

表示方式主要是：

```text
TF-IDF / HashingVectorizer -> clustering / balanced assignment -> SID
```

SID 结构：

```text
Search SID = [shared prefix | search suffix]
Rec SID    = [shared prefix | rec suffix]
```

最终较稳定的版本：

```text
sid_v1_balanced_200_coarseP8_4_suf32_8
```

### 结果

```text
collision:
  search = 0
  rec    = 0

downstream:
  H@10 overall = 0.603
  nDCG@10      = 0.4384
  search H@10  = 0.997
  rec H@10     = 0.209
```

### 结论

M0 证明数据、SID 构造、下游生成模型、beam search、Recall/nDCG 评估链路是可跑通的。

但 TF-IDF / hashing 表示太浅，不适合作为论文主方法。

## 5. M5：Prefix-Locked Continuation

目录：

```text
sid_v2_prefix_locked_continuation_balanced_assign_200_p8_4_suf32_8
```

### 方法

M5 是一个重要中间版本。

核心思想：

```text
先训练 shared RQ-VAE 得到 prefix；
冻结 shared prefix codebook；
task adapter 只在 prefix 后继续生成 suffix；
保证 shared prefix 不被 task 微调破坏。
```

结构：

```text
x_common -> shared encoder / RQ -> prefix [P1, P2]

x_common + x_task -> task adapter
-> continuation latent
-> suffix [S1, S2] or [R1, R2]
```

### 结果

```text
collision:
  search = 0.24
  rec    = 0.215

downstream:
  H@10 overall = 0.6205
  nDCG@10      = 0.4653
  search H@10  = 0.996
  rec H@10     = 0.245
```

### 结论

M5 比 M3/M4 更贴合我们的论文动机：

```text
shared prefix 稳定；
task suffix 可独立学习和更新；
Search / Rec 共用前缀但保留任务差异。
```

后续 M6/M7/M8 都是在 M5 的思路上继续升级。

## 7. M7a / M7b：Text Encoder Fusion PLC

M7 是目前最重要的一组结构实验。

### 共同设计

M7 不再把 common/task 简单拼接成文本，而是分开构造 embedding：

```text
x_common:
  TextEncoder(title + category + brand + description + item_text + item_id)

x_search_signal:
  query embeddings weighted by query frequency

x_rec_signal:
  neighbor item common embeddings weighted by co-occurrence frequency
```

然后做 gating fusion：

```text
x_task_fused = GatedFusion(x_common, x_task_signal)
```

task target：

```text
x_search_target = normalize(x_common + 0.5 * x_search_signal)
x_rec_target    = normalize(x_common + 0.5 * x_rec_signal)
```

suffix 训练目标：

```text
reconstruct x_task_target
```

loss：

```text
L = L_recon
  + commit_weight * L_commit
  + balance_weight * L_balance
  + orth_weight * L_orth
  + anchor_weight * L_anchor
  + residual_norm_weight * L_residual_norm
```

其中：

```text
L_recon = MSE(decoder(q_shared + q_task), x_task_target)
```

### M7a：Adapter Fusion PLC

目录：

```text
sid_v2_m7a_text_encoder_fusion_plc_adapter_balanced_200_p8_4_suf32_8
```

结果：

```text
collision:
  search = 0.47
  rec    = 0.495

downstream:
  H@10 overall = 0.609
  nDCG@10      = 0.4546
  search H@10  = 0.994
  rec H@10     = 0.224
```

### M7b：LoRA Fusion PLC

目录：

```text
sid_v2_m7b_text_encoder_fusion_plc_lora_balanced_200_p8_4_suf32_8
```

结构：

```text
shared encoder + LoRA_search / LoRA_rec
```

结果：

```text
collision:
  search = 0.76
  rec    = 0.74

downstream:
  H@10 overall = 0.662
  nDCG@10      = 0.4998
  search H@10  = 1.000
  rec H@10     = 0.324
```

### M7b 的问题

M7b raw 指标最高，但 collision 很高。

因为 evaluation 中：

```text
generated SID -> SID-to-item lookup
```

如果多个 item 共用同一个 SID，会造成 item hit 被放大。

所以 M7b raw 不能作为公平最终版本，只能说明：

```text
LoRA Fusion PLC 的语义结构容易学，
但 full SID uniqueness 很差。
```

## 10. 当前最重要的判断

### 10.1 raw M7b 指标不能直接作为最终结论

M7b raw：

```text
H@10 overall = 0.662
rec H@10 = 0.324
```

但 collision 很高：

```text
search collision = 0.76
rec collision = 0.74
```

因此该结果有明显 lookup inflation。

### 10.2 只做 unique assignment 不够

M7b-Unique / M8a-Unique 都能把 collision 降到 0。

但 rec H@10 只有：

```text
M7b-Unique = 0.189
M8a-Unique = 0.177
```

说明问题不是单纯 collision，而是：

```text
suffix 在同 prefix bucket 内没有学到足够强的 item-level / task-level discrimination。
```

### 10.3 M8a/b/c 的弱约束不够

M8 的三个方向：

```text
task_signal target
in-bucket contrast
transition rec target
```

都没有实质性解决 rec suffix 的可学习性。

尤其 rec 侧仍然容易出现：

```text
raw collision 高；
unique assignment 改动大；
下游生成 rec SID 困难。
```

## 11. 下一步建议

后续不建议继续只做：

```text
post-hoc reassignment
弱 residual repulsion
简单 suffix reconstruction target 替换
```

更值得尝试的是更强的 prefix-conditioned item discrimination：

```text
在同一个 prefix bucket 内，
让 suffix 直接承担 item classification / contrastive retrieval / transition discrimination。
```

候选方向：

1. `M9a`: prefix-conditioned item classification loss  
   对同 prefix bucket 内 item 做分类，直接约束 suffix 可区分 item。

2. `M9b`: transition-aware contrastive suffix  
   rec suffix 不只重构 next-item embedding，而是通过 InfoNCE 区分真实 next item 与同 prefix 负样本。

3. `M9c`: dual objective  
   保留 reconstruction loss，同时加入：

```text
L = L_recon + lambda * L_inbucket_item_discrimination
```

当前判断：

```text
M7b-Unique 是目前更公平的 baseline；
M8a 是可记录的失败/弱改进尝试；
下一步应从 stronger discriminative suffix objective 入手。
```

## 12. M7b-v3：对 M7b collision 与表示能力的定向改进

### 12.1 共同结构

M7b-v3 保留 M7b 的核心创新点：

```text
固定 shared RQ-VAE 与 shared codebook
Enc_task = Enc_shared + LoRA_task
x_task_aug = x_common + gated task signal
delta_task = Enc_task(x_task_aug) - Enc_shared(x_common)
SID_task = [fixed shared prefix | RQ(delta_task)]
```

本轮修正了三个实现问题：

1. 训练和导出始终使用同一套 fixed shared prefix，prefix changed rate 为 0。
2. suffix 重构目标拆成 task target 与完整表示目标，避免仅靠弱 residual reconstruction。
3. Rec signal 改为由时间有向交互 `item_t -> item_(t+1)` 训练的 directed Item2Vec，而不是无向邻居平均。

directed Item2Vec 使用 5000 个 item、650878 个有向 pair、128 维表示；signal effective rank 为 81.83。

### 12.2 三个递进版本

| 版本 | Rec signal | collision 处理 | Search raw item collision | Rec raw item collision |
|---|---|---|---:|---:|
| M7b-v3a | 无向 sequence neighbor | 无 | 45.36% | 37.42% |
| M7b-v3b | directed Item2Vec | 无 | 44.48% | 18.04% |
| M7b-v3c | directed Item2Vec | prefix-conditional CG-Sinkhorn | 39.50% | 12.04% |

v3b 说明真正的有向行为表示显著改善了 Rec suffix；但 Search collision 仍主要来自弱 query coverage 和同 prefix 内区分不足。

### 12.3 M7b-v3c 的 CG-Sinkhorn

训练时仅在同 prefix、且完整 SID 已碰撞的 group 中，对最后一层 suffix code 计算 Sinkhorn soft assignment loss。导出时再做一轮同样受 prefix 限制的 reassignment。

最终统计：

| Task | unique SID | item collision | duplicate fraction | max bucket |
|---|---:|---:|---:|---:|
| Search | 4860 / 5000 | 5.30% | 2.80% | 3 |
| Rec | 4964 / 5000 | 1.42% | 0.72% | 3 |

需要保留的限制：

```text
Search 有 1945 / 5000（38.90%）个末层 code 在导出 refinement 中被改写；
Rec 有 599 / 5000（11.98%）个末层 code 被改写。
```

因此 v3c 已把 collision 控制到与 GenSAR-native 相近的量级，但 Search 的低 collision 仍较依赖一次受约束的导出调整，不能表述成完全由端到端训练自然消除。

### 12.4 统一协议后的 3-seed 结果

此前记录的单 seed 表存在协议不一致：旧 seed 2024 使用 `num_negs=199` 做验证和 checkpoint 选择，后续运行使用 `num_negs=99`。因此“v3c 四项全面超过 native”的旧结论撤销，不能用于论文。

重新统一设置：GenSAR-Lite-5K、T5-small、每任务 5000 条训练、`SeqRecWithSrcHis + PerSrcWithRecHis`、3 epochs、beam=10、`num_negs=99`、1000 条测试。结果为 seeds 2024/2025/2026 的 `mean +/- sample std`。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| M7b-v3c | **0.1547 +/- 0.0100** | 0.0661 +/- 0.0017 | 0.1473 +/- 0.0509 | 0.0929 +/- 0.0401 |
| GenSAR-native | 0.1433 +/- 0.0276 | **0.0730 +/- 0.0146** | **0.1913 +/- 0.1200** | **0.1038 +/- 0.0732** |

修正后的判断：

```text
M7b-v3c 的 Rec H@10 较高且方差更小；
Rec nDCG@10 和两个 Search 均值尚未超过 GenSAR-native；
两种 SID 的 Search 下游训练方差都很大，GenSAR-native 尤其明显。
```

### 12.5 三项 3-seed 消融

所有消融只改变一个 SID 生成因素，下游协议与 12.4 完全一致。

| SID 版本 | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| full v3c | 0.1547 +/- 0.0100 | 0.0661 +/- 0.0017 | 0.1473 +/- 0.0509 | 0.0929 +/- 0.0401 |
| **去掉 directed behavior，改回 neighbor** | **0.1657 +/- 0.0119** | **0.0713 +/- 0.0057** | 0.2030 +/- 0.0541 | **0.1262 +/- 0.0368** |
| 去掉 training CG-Sinkhorn | 0.1377 +/- 0.0075 | 0.0581 +/- 0.0033 | 0.1567 +/- 0.0592 | 0.0641 +/- 0.0321 |
| 去掉 export refinement | 0.1497 +/- 0.0137 | 0.0656 +/- 0.0053 | **0.2053 +/- 0.0721** | 0.1178 +/- 0.0460 |

结论一：directed Item2Vec 不是当前有效组件。

```text
它把 Rec raw item collision 从 45.56% 降至 12.04%，
但四项下游均值全部下降。
```

说明“更接近 next-item transition 的连续表示”不等于“更容易被生成模型作为离散 SID 学习”。当前 directed signal 可能编码了过多局部转移细节，也可能使 suffix token 的序列规律更难学习。

结论二：training CG-Sinkhorn 应保留。

去掉它后，Rec 两项和 Search nDCG 明显下降；它不仅控制 collision，也改善了 suffix 的生成排序质量。

结论三：强 export refinement 不应作为最终方案。

```text
它小幅改善 Rec；
但 Search H@10 从 0.2053 降至 0.1473，Search nDCG 也下降；
full v3c 的 Search code changed rate 为 38.90%。
```

这表明大量 post-hoc code 改写会破坏训练阶段形成的 Search 语义邻近结构。

### 12.6 当前主线：M7b-v3d（Neighbor-CG）

把最强消融版本记为 `M7b-v3d / Neighbor-CG`：

```text
fixed shared prefix
+ common/task LoRA delta
+ neighbor-based Rec signal
+ training prefix-conditional CG-Sinkhorn
+ one-round export refinement
```

它相对 GenSAR-native 的三 seed 均值：

```text
Rec H@10:       0.1657 vs 0.1433
Rec nDCG@10:    0.0713 vs 0.0730
Search H@10:    0.2030 vs 0.1913
Search nDCG@10: 0.1262 vs 0.1038
```

但它还不是论文最终版本：Search/Rec 的 export changed rate 分别为 46.66%/44.74%，最终 duplicate fraction 均约 3%。下一轮应把目标改成：保留 neighbor signal 与 training CG-Sinkhorn，同时通过更强的 in-prefix differentiable discrimination 降低 raw collision 和 export changed rate，避免依赖大规模 post-hoc reassignment。

## 13. M7b-v4：In-Prefix Differentiable Discrimination

### 13.1 结构

v4 保留 v3d 的 fixed shared prefix、LoRA task delta 和 neighbor Rec signal，但将 LoRA rank 从 8 提高到 32，并在训练阶段加入：

```text
L_inprefix_contrast：同 prefix item 的 instance discrimination
L_full_sid_collision：两层 straight-through assignment 的完整 suffix collision
L_assignment_confidence：降低单 item assignment entropy
L_variance + L_covariance：缓解 suffix latent 低秩
L_gate_floor：防止通过关闭 task gate 来降低 collision
```

完整 loss：

```text
L = L_recon + L_commit + L_balance
  + lambda_sk * L_conditional_sinkhorn
  + lambda_ctr * L_inprefix_contrast
  + lambda_col * L_full_sid_collision
  + lambda_conf * L_assignment_confidence
  + lambda_var * L_variance
  + lambda_cov * L_covariance
  + lambda_gate * L_gate_floor
```

正式版本不使用 export refinement。

### 13.2 SID 结果

| 指标 | v3d raw | v4 raw |
|---|---:|---:|
| Search duplicate fraction | 32.82% | **4.76%** |
| Rec duplicate fraction | 30.86% | **8.46%** |
| Search item collision | 47.54% | **9.02%** |
| Rec item collision | 45.56% | **15.38%** |
| Search effective rank | 5.78 | **8.71** |
| Rec effective rank | 4.27 | **9.21** |
| Search export changed | 46.66% | **0%** |
| Rec export changed | 44.74% | **0%** |

task gate：

```text
Search = 1.00
Rec    = 0.57
```

因此 v4 没有通过关闭 Rec task signal 来规避 collision。

### 13.3 统一 3-seed 下游结果

协议与 12.4 完全一致，均为 `mean +/- sample std`。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| M7b-v4 raw | 0.1393 +/- 0.0163 | 0.0665 +/- 0.0098 | 0.1900 +/- 0.0212 | 0.0924 +/- 0.0087 |
| M7b-v3d | **0.1657 +/- 0.0119** | 0.0713 +/- 0.0057 | **0.2030 +/- 0.0541** | **0.1262 +/- 0.0368** |
| GenSAR-native | 0.1433 +/- 0.0276 | **0.0730 +/- 0.0146** | 0.1913 +/- 0.1200 | 0.1038 +/- 0.0732 |

### 13.4 结论

v4 成功解决了主要工程目标：raw collision 大幅下降、完全取消 post-hoc 改写、Search 下游方差显著降低。但四项下游均值没有超过 v3d，说明强 instance discrimination 在拆分碰撞 item 的同时，也破坏了有利于生成和排序的语义邻近结构。

因此：

```text
v3d 仍是效果上限；
v4 是低 collision、低方差的结构基线；
下一版需要在二者之间做受控折中，而不是继续无条件增强 repulsion。
```

后续更合理的方向是 collision-targeted schedule：先按 reconstruction 学习语义结构，只在 duplicate fraction 高于目标阈值时逐步增加 collision loss；达到 5%-10% 后停止继续排斥，并加入 pairwise semantic topology distillation，约束 v4 保留 v3d/target space 的局部相似度排序。

---

## 14. M7b-v5：Adaptive Collision + Topology Distillation

### 14.1 动机与结构

v4 在整个训练过程中始终施加强 instance discrimination，虽然显著降低了 collision，但也破坏了下游有用的语义邻近结构。v5 保留 fixed shared prefix、LoRA task delta、neighbor Rec signal 和 v4 的可微判别项，但做两项修改。

第一，使用 collision-targeted adaptive schedule。前 10 epochs 令判别权重 `a=0`，先学习 task reconstruction 和局部拓扑；之后每轮根据 Search/Rec 中更高的 raw duplicate fraction 更新：

```text
d_e = max(d_search, d_rec)
a_(e+1) = clip(a_e + eta * (d_e - target), 0, 1)
```

`a` 只缩放以下容易破坏语义结构的判别项：

```text
L_inprefix_contrast
L_full_sid_collision
L_assignment_confidence
L_variance
L_covariance
```

第二，加入同 prefix topology distillation。以效果较强的 v3d raw task delta 为 teacher，在每个 shared-prefix bucket 内匹配 item 两两 cosine similarity：

```text
L_topology = MSE(cos(delta_student_i, delta_student_j),
                 cos(delta_teacher_i, delta_teacher_j))
```

该项在 warmup 和 collision-active 阶段都生效。正式版本仍然不做 export refinement、unique reassignment 或其他 post-hoc 改码。

### 14.2 两个受控版本

| 版本 | duplicate target | topology weight | Search raw duplicate | Rec raw duplicate | Search/Rec topology MSE |
|---|---:|---:|---:|---:|---:|
| v5-A | 8% | 1 | 8.50% | 11.26% | 0.0948 / 0.0922 |
| v5-B | 10% | 2 | 13.22% | 10.84% | **0.0611 / 0.0799** |

更完整的 SID 表示统计：

| 版本 | Search item collision | Rec item collision | Search effective rank | Rec effective rank | export changed |
|---|---:|---:|---:|---:|---:|
| v3d raw | 47.54% | 45.56% | 5.78 | 4.27 | 后续约 45% |
| v4 raw | **9.02%** | **15.38%** | 8.71 | 9.21 | 0% |
| v5-A raw | 15.48% | 19.90% | 11.45 | **15.43** | 0% |
| v5-B raw | 22.20% | 18.90% | 10.59 | 12.14 | 0% |

v5-B 有意允许适量 collision，以更强 topology constraint 保留语义结构；其 raw collision 仍远低于 v3d，并且不依赖导出时改码。

### 14.3 统一 3-seed 下游结果

协议与 12.4 完全一致：GenSAR-Lite-5K、T5-small、每任务 5000 条训练、2 tasks、3 epochs、beam=10、`num_negs=99`、每任务 1000 条测试。结果为 seeds 2024/2025/2026 的 `mean +/- sample std`。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| v5-A raw | 0.1557 +/- 0.0146 | **0.0733 +/- 0.0031** | 0.1177 +/- 0.0411 | 0.0602 +/- 0.0201 |
| **v5-B raw** | **0.1593 +/- 0.0110** | 0.0708 +/- 0.0050 | 0.1753 +/- 0.0430 | **0.1291 +/- 0.0253** |
| v3d | 0.1657 +/- 0.0119 | 0.0713 +/- 0.0057 | 0.2030 +/- 0.0541 | 0.1262 +/- 0.0368 |
| v4 raw | 0.1393 +/- 0.0163 | 0.0665 +/- 0.0098 | 0.1900 +/- 0.0212 | 0.0924 +/- 0.0087 |
| GenSAR-native | 0.1433 +/- 0.0276 | 0.0730 +/- 0.0146 | 0.1913 +/- 0.1200 | 0.1038 +/- 0.0732 |

### 14.4 当前结论

v5-A 表明只把 collision 控制在更低区间并不足以保住 Search 结构：Rec 恢复，但 Search 明显下降。把 topology weight 从 1 提高到 2 后，v5-B 的 Search nDCG@10 从 0.0602 恢复到 0.1291，同时 Rec 指标基本保持。

当前主线判断：

```text
效果上限参考：v3d，但约 45% SID 需要 post-hoc 改写；
低 collision 基线：v4，但下游均值偏低；
论文主候选：v5-B，在 raw SID、0% export changed 下取得最平衡结果。
```

v5-B 尚未全面超过 v3d：Rec H@10 和 Search H@10 分别低 0.0064 和 0.0277；但 Search nDCG@10 略高 0.0029，四项均超过 v4 中的三项，仅 Search H@10 低于 v4。下一轮不应继续统一加大 collision loss，更合理的是为 Search/Rec 使用独立 controller/target，并研究 Search topology teacher 或 query-conditioned hard negatives。

## 15. GenSAR-Lite-20K 规模扩展实验

### 15.1 数据构造

从同时满足 Product Search qrels 与 Amazon Electronics 5-core reviews 条件的 62,851 个候选 item 中，按活跃度 score 排名分成 head/middle/tail 三等份，再按 40%/40%/20% 抽取 8,000/8,000/4,000 个 item。用户过滤后去掉一个只剩 Rec 信号的 item，最终保留 19,999 个严格 Search-Rec overlap item。

```text
items                 = 19,999
users                 = 149,025
Search interactions   = 470,454
Rec interactions      = 589,626
Search per-item p50   = 10
Rec per-item p50      = 13
```

相比 5K benchmark 的 Search/Rec per-item p50=82/103，20K 包含明显更多中尾部 item。

### 15.2 Codebook 规模消融

两种设置都使用相同 E5 384-d common/search/rec 表示、相同 v3d teacher 和 v5-B 训练配置。

| v5-B codebook | 有效 prefix | 平均 prefix bucket | Search duplicate | Rec duplicate | Search/Rec topology MSE |
|---|---:|---:|---:|---:|---:|
| `[64,64 | 64,64]` | 2,667 | 7.50 | 11.02% | 9.67% | 0.0549 / 0.0416 |
| **`[128,128 | 128,128]`** | **5,626** | **3.55** | **5.83%** | **4.05%** | **0.0043 / 0.0058** |

64 版本虽然最终接近 10% collision target，但 controller 长期接近满权重，且 topology 偏移明显更大；因此 20K 正式配置采用 128×128。

### 15.3 GenSAR-native 与 v5-B SID

GenSAR-native 使用同一份 E5 task-augmented embeddings，训练官方 shared/semantic/collaborative RQ-VAE：

```text
shared codebooks        = [128, 128]
semantic codebooks      = [128, 128]
collaborative codebooks = [128, 128]
best raw average duplicate = 7.50%
```

官方 `generate_indices.py` 再执行最多 20 轮 collision-group Sinkhorn，导出后：

```text
Search duplicate = 0.375%
Rec duplicate    = 0.295%
```

v5-B 直接导出训练产生的 raw SID，不执行 Sinkhorn、unique reassignment 或其他 post-hoc 改码：

```text
Search duplicate = 5.83%
Rec duplicate    = 4.05%
export changed   = 0%
```

### 15.4 统一 3-seed 下游结果

协议：GenSAR 2 tasks、T5-small、每任务 20,000 train、3 epochs、1,000 validation/test、beam=10、`num_negs=99`。结果为 seeds 2024/2025/2026 的 `mean +/- sample std`。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR-native p128 | 0.1583 +/- 0.0074 | 0.0794 +/- 0.0055 | 0.1073 +/- 0.0396 | 0.0498 +/- 0.0214 |
| **M7b-v5-B p128 raw** | **0.1950 +/- 0.0060** | **0.1003 +/- 0.0069** | **0.3090 +/- 0.0345** | **0.2019 +/- 0.0121** |

绝对提升：

```text
Rec H@10       +0.0367
Rec nDCG@10    +0.0209
Search H@10    +0.2017
Search nDCG@10 +0.1521
```

### 15.5 当前判断与必要验证

v5-B 在更大、更长尾的数据上没有退化，三 seed 的四项均值均超过 GenSAR-native，并且方差可控。这支持 shared prefix + task-specific LoRA delta + adaptive collision + topology distillation 的组合具有规模扩展潜力。

但 Search 提升幅度很大，不能在完成以下验证前直接作为论文最终结论：

1. 在 Search/Rec target SID 均唯一的 test subset 上重新评估，排除 v5-B 约 4%-6% raw collision 带来的候选合并收益。
2. 报告按 head/middle/tail 分层的 H@10/nDCG@10，确认提升不是只来自某一活跃度层。
3. 增加 `v3d-p128 raw` 下游消融，区分收益来自 128 codebook/teacher，还是 v5 adaptive + topology 本身。
4. 将 controller 的全量 duplicate 统计改为固定分层样本估计，再进入约 62K 全量 overlap item，避免训练开销线性放大。

## 16. GenSAR faithful-core baseline 与 M7b-v5-B（旧表示）对照

### 16.1 目的与协议

此前的 GenSAR-native 属于简化版：没有真正由行为任务训练的 collaborative embedding，负采样和数据时间切分也与 GenSAR 原流程存在差异。本轮建立更严格的 faithful-core baseline，用来回答“只替换 SID，M7b 是否仍优于 GenSAR”这一问题。

数据与表示：

```text
items                         = 19,999
task-overlap users            = 148,318
deduplicated Search events    = 446,756
Rec events                    = 588,164
Search/Rec split              = per-user chronological
rec history                   = strictly earlier events only
semantic embedding            = BGE-base-en-v1.5, 768-d
collaborative embedding       = UniSAR-faithful, 64-d
GenSAR codebooks              = [256,256 | 256,256]
```

UniSAR-faithful 不是原论文的官方 checkpoint，而是在当前数据上训练的功能等价近似：包含 Search/Rec scenario encoder、mixed encoder、cross-attention、alignment/relevance 对比目标和 MMoE 联合行为目标。它用于提供由真实 Search/Rec 行为训练得到的 item collaborative embedding。

下游控制协议对三组 SID 完全一致，唯一变量是 SID 文件：

```text
tasks              = SeqRecWithSrcHis + PerSrcWithRecHis
backbone           = T5-small
train              = 20,000 samples per task
validation/test    = 1,000 samples per task
epochs             = 3
Search negatives   = BM25 top-999
Rec negatives      = random 999
beam size          = 10
seed               = 2024
```

### 16.2 SID collision

| SID | Search duplicate | Rec duplicate | 处理方式 |
|---|---:|---:|---|
| GenSAR faithful-core p256 | 0.460% | 0.220% | 官方 collision-group Sinkhorn |
| M7b-v5-B p256 raw（旧表示） | 2.555% | 2.215% | 不做 post-hoc |
| M7b-v5-B p256 + CG-Sinkhorn（旧表示） | 0.105% | 0.060% | 与 GenSAR 同类的 collision-group Sinkhorn |

### 16.3 公平下游结果

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| **GenSAR faithful-core p256** | **0.077** | **0.0481** | 0.079 | **0.0453** |
| M7b-v5-B p256 raw（旧表示） | 0.055 | 0.0241 | 0.066 | 0.0336 |
| M7b-v5-B p256 + CG-Sinkhorn（旧表示） | 0.056 | 0.0278 | **0.081** | 0.0353 |

CG-Sinkhorn 将 M7b 的 collision 降到低于 GenSAR，并使 Search H@10 从 0.066 提升到 0.081，但 Rec 只从 0.055 变为 0.056，且 Search nDCG@10 仍低于 GenSAR。由此可见，高 collision 不是 M7b 当前落后的主要原因；post-hoc 去重只能修复重复 SID，不能修复码空间的全局语义、行为邻域和排序结构。

### 16.4 当前结论

这里评估的是已经完成 adaptive collision、in-prefix discrimination 和 topology distillation 的 M7b-v5-B，但其输入仍是旧版 E5 common/search 表示与文本化 co-occurrence rec signal；它尚未接入本轮新训练的 BGE 和 UniSAR-faithful 表示。因此，这个实验说明“旧表示下的最新 M7b-v5-B”弱于 faithful-core baseline，不能视为对下一版 representation-enhanced M7b 的评估。

在这个更接近 GenSAR 的单 seed、2-task 控制实验中，GenSAR faithful-core 是当前更强的基线。M7b 下一步不应继续主要调 collision loss，而应优先改 representation：

1. 保留 M7b 的 shared prefix、冻结 prefix 与 task-specific LoRA suffix，这是与 GenSAR 的核心结构差异。
2. common/search 文本底座改为与 baseline 对齐的 BGE 表示，避免 encoder 质量成为混杂变量。
3. rec task view 引入 UniSAR-faithful 行为表示，不再只依赖文本化 co-occurrence 邻居。
4. shared prefix 同时保留跨任务公共语义与行为邻域；suffix 再用 LoRA 学习相对 shared state 的任务增量。
5. 训练目标增加 neighborhood/topology preservation，并继续将 CG-Sinkhorn 仅作为低比例导出修复，不把它当作表示学习替代品。

本节不是 GenSAR 论文完整复现：尚未加入 Item2Index、Index2Item、QGen、Doc2Query 四个辅助任务，也未采用论文的完整训练轮数与 beam 设置。当前协议的价值是控制变量地比较两种 SID；后续 full-task 实验应继续保持“相同数据、相同任务、相同超参，只替换 SID”。

## 17. M7b-v6：BGE-UniSAR Representation-Enhanced LoRA PLC

### 17.1 方法

v6 保留 v5-B 的 frozen shared prefix、task-specific LoRA、adaptive collision 和 topology preservation，但将旧 E5/neighbor 表示替换为与 faithful-core baseline 对齐的强表示：

```text
x_common       = BGE(item title + description), 768-d
x_search       = BGE(weighted pseudo-query set), 768-d
x_rec          = UniSAR-faithful item behavior embedding, 64-d
shared prefix  = RQ-VAE(x_common), [256, 256]
search suffix  = bounded LoRA delta(x_common, x_search), [256, 256]
rec suffix     = bounded LoRA delta(x_common, x_rec), [256, 256]
topology       = directly preserve search/rec representation neighborhoods
```

shared RQ-VAE 重新训练 50 epochs；冻结 shared encoder/codebook 后训练 LoRA suffix 30 epochs。下游仍为完全相同的单 seed 2-task 协议。

### 17.2 SID 与 prefix 结构

| SID | prefix unique | 平均 prefix bucket | Search duplicate | Rec duplicate |
|---|---:|---:|---:|---:|
| GenSAR faithful-core | 1,357 | 14.74 | 0.460% | 0.220% |
| v6 balanced raw | 5,936 | 3.37 | 3.095% | 4.945% |
| v6 balanced + CG | 5,936 | 3.37 | 0.290% | 0.160% |
| v6 argmin raw | 2,286 | 8.75 | 13.511% | 22.326% |
| v6 argmin + CG | 2,286 | 8.75 | 2.815% | 2.945% |

旧 `balanced` 导出会对每层独立执行全局等容量分配，使第二层 code 与第一层缺少明确的条件层级，prefix 组合膨胀。`argmin` 与 RQ-VAE 训练时的量化一致，prefix 更粗，但会暴露更高 collision。

### 17.3 下游结果

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| **GenSAR faithful-core p256** | **0.077** | **0.0481** | **0.079** | **0.0453** |
| M7b-v5-B raw（旧表示） | 0.055 | 0.0241 | 0.066 | 0.0336 |
| v6 balanced raw | 0.050 | 0.0378 | 0.040 | 0.0292 |
| v6 balanced + CG | 0.049 | 0.0371 | 0.053 | 0.0324 |
| v6 argmin + CG | 0.069 | 0.0477 | 0.014 | 0.0047 |

### 17.4 结论

强 embedding 显著提高了 v6 delta 的 effective rank，但没有自动改善整体下游效果。CG 再次证明 collision 不是主瓶颈。argmin prefix 使 Rec nDCG@10 几乎恢复到 GenSAR 水平，却导致 Search 崩溃，说明当前 shared prefix 的组织对两个任务并不兼容。

当前主要问题是 suffix target 的 item-level discrimination 不足：Search view 来自约 550 个聚合 pseudo-query，Rec view 又经过 bounded delta 压缩；而 GenSAR 的 semantic/collaborative suffix 直接继续量化 item-specific latent。下一版不应再只替换 encoder，而应修改结构：shared prefix 从 semantic 与 behavior 两个 view 的可学习交集产生；task suffix 同时重构 item-specific task latent 和相对 shared 的增量，并采用 conditional/hierarchical balancing，避免逐层全局 balanced assignment 破坏 RQ 层级。

## 18. M7b-v7：Anchored Cross-View Shared Prefix

### 18.1 方法

v7 保留“稳定 prefix + 可独立更新的 task suffix”这一核心设定。部署时 prefix 仍只依赖稳定的 `title + description`，行为信息只在初始 shared RQ-VAE 训练阶段作为辅助监督，不作为日后重算 prefix 的输入：

```text
x_common   = BGE(title + description), 768-d
x_search   = BGE(weighted pseudo-query set), 768-d
x_behavior = UniSAR-faithful item behavior embedding, 64-d

z_shared = Enc_semantic(x_common)
q_shared = RQ_prefix(z_shared)

L_shared = 10 MSE(Dec_sem(q_shared), x_common)
         + 1 Cos(Dec_sem(q_shared), x_common)
         + 5 MSE(Dec_beh(q_shared), x_behavior)
         + 0.5 Cos(Dec_beh(q_shared), x_behavior)
         + 0.1 InfoNCE(z_shared, Proj_beh(x_behavior))
         + L_commit + L_balance
```

shared encoder、prefix codebook 和两个 shared decoder 训练后全部冻结。两个 suffix 分别学习 shared quantized state 未能重构的 task residual：

```text
r_search = x_common   - Dec_sem(q_shared)
r_rec    = x_behavior - Dec_beh(q_shared)

delta_search = LoRA_search(x_common, x_search)
delta_rec    = LoRA_rec(x_common, x_behavior)

suffix_search = RQ_search(delta_search), [256, 256]
suffix_rec    = RQ_rec(delta_rec),       [256, 256]
```

suffix loss 延续 v5/v6 的 residual reconstruction、full-view reconstruction、topology preservation、in-prefix discrimination、adaptive collision 和 code usage 约束。导出时使用 collision-group Sinkhorn，只在相同 prefix 的碰撞组内调整最后一层 suffix code。

相对 v6 的唯一主要结构变化是：v6 的 shared prefix 只重构 BGE semantic view；v7 的 prefix 输入仍是 BGE，但训练时同时重构 semantic 与 behavior view，并增加跨视图对齐。

### 18.2 SID 统计

```text
items                  = 19,999
codebooks              = [256, 256 | 256, 256]
prefix assignment      = argmin
prefix unique          = 1,884
mean prefix bucket     = 10.62
prefix level-1 usage   = 59 / 256
prefix level-2 usage   = 112 / 256
```

| assignment | Search duplicate | Rec duplicate | Search collided items | Rec collided items |
|---|---:|---:|---:|---:|
| raw | 23.366% | 29.516% | 37.092% | 43.752% |
| collision-group Sinkhorn | 0.620% | 0.210% | 1.045% | 0.415% |

Sinkhorn 分别改变了 39.17% 的 Search suffix 和 44.87% 的 Rec suffix。最终 collision 已接近 GenSAR faithful-core，但改派比例过高，说明 uniqueness 主要由导出修复得到，而不是 representation 自然可分。

### 18.3 公平下游结果

下游沿用第 16 节完全相同的单 seed 2-task 协议：同一数据切分、T5-small、每任务 20,000 条训练样本、每任务 1,000 条验证/测试样本、3 epochs、999 negatives、beam 10；唯一替换项是 SID 文件。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| **GenSAR faithful-core p256** | 0.077 | **0.0481** | **0.079** | **0.0453** |
| M7b-v6 balanced + CG | 0.049 | 0.0371 | 0.053 | 0.0324 |
| M7b-v6 argmin + CG | 0.069 | 0.0477 | 0.014 | 0.0047 |
| M7b-v7 anchored cross-view + CG | **0.080** | 0.0456 | 0.036 | 0.0186 |

### 18.4 结论

v7 对 Rec 有效：Rec H@10 比 GenSAR 高 0.003，且相对 v6 argmin 从 0.069 提升到 0.080；但 Rec nDCG@10 仍略低于 GenSAR。Search 虽比 v6 argmin 恢复，但仍显著低于 GenSAR 和 v6 balanced。

本轮不支持“直接把 semantic 与 behavior reconstruction 同时压入同一个 prefix RQ-VAE”作为最终方案。主要证据是 prefix code usage 收缩、raw suffix collision 很高，以及约四成 suffix 依赖 post-hoc 改派。双视图监督提高了 prefix 对行为结构的承载，因而改善 Rec；同时它改变了原本由文本语义组织的 shared topology，使 Search 的粗粒度路由变差。

下一轮应保留 stable semantic anchor，不让 behavior reconstruction 直接拉动全部 shared latent。更合适的控制变量是将跨视图信息限制在一个受约束的小残差或 shared/private decomposition 中，并对 prefix 增加层级 usage/variance 约束；在 raw duplicate 与改派比例明显下降前，不应继续单纯提高 collision loss。

## 19. M7b-v8：Frozen Semantic Anchor + Shared/Private Behavior Bridge

### 19.1 方法

v8 用严格控制变量验证“冻结语义锚点 + shared/private 分解”。它直接加载 v6 已训练好的纯语义 shared RQ-VAE，确保 prefix 不受 behavior view 影响：

```text
x_common = BGE(title + description)
z_shared = Enc_shared(x_common)
q_shared = RQ_prefix(z_shared)
prefix   = argmin RQ codes
```

随后冻结 shared encoder、decoder 和 prefix codebook。单独训练 behavior bridge，仅学习由离散语义 prefix 可以预测的行为公共成分：

```text
b_shared = Bridge_beh(stopgrad(q_shared))
L_bridge = 5 MSE(b_shared, x_behavior)
         + 0.5 Cos(b_shared, x_behavior)
         + 0.001 ||b_shared||^2

r_search = x_common   - Dec_sem(q_shared)
r_rec    = x_behavior - b_shared
```

Search/Rec suffix 继续使用 task-specific LoRA、RQ quantization、residual/full-view reconstruction 和 topology preservation。与 v7 相比，collision controller 的 gain 从 2.0 降至 0.15，避免约束突然拉满；导出 Sinkhorn 从 20 轮限制为 5 轮，并同时保留 raw SID 做下游对照。

### 19.2 表示与 SID 统计

behavior bridge 的结果：

```text
behavior reconstruction MSE    = 0.00450
behavior cosine similarity     = 0.8434
behavior variance explained    = 16.45%
```

这说明稳定语义 prefix 确实包含一部分行为公共结构，但大部分 item-specific 行为信息仍保留在 Rec private residual 中。

v8 完整重现了 v6 argmin semantic prefix：

```text
prefix unique          = 2,286
mean prefix bucket     = 8.75
max prefix bucket      = 498
prefix level-1 usage   = 201 / 256
prefix level-2 usage   = 214 / 256
```

| assignment | Search duplicate | Rec duplicate | Search collided items | Rec collided items |
|---|---:|---:|---:|---:|
| raw | 21.201% | 34.122% | 32.137% | 46.407% |
| 5-round group Sinkhorn | 2.780% | 3.695% | 4.650% | 6.330% |

5 轮修复仍改变了 32.33% 的 Search suffix 和 46.63% 的 Rec suffix。与 v7 相同，collision 下降主要来自大比例重新分配，而不是 raw representation 自然可分。

### 19.3 公平下游结果

raw 与 refined5 均使用第 16 节相同的单 seed 2-task 协议，唯一变量为 SID 文件。

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| **GenSAR faithful-core p256** | **0.077** | **0.0481** | **0.079** | **0.0453** |
| M7b-v7 anchored cross-view + CG | 0.080 | 0.0456 | 0.036 | 0.0186 |
| M7b-v8 frozen anchor raw | 0.065 | 0.0467 | 0.026 | 0.0107 |
| M7b-v8 frozen anchor refined5 | 0.056 | 0.0405 | 0.024 | 0.0126 |

### 19.4 结论与诊断

v8 证明了两点：

1. 冻结 semantic anchor 可以彻底避免 v7 的 prefix code usage 收缩，并保持日后只更新单个 task suffix 的能力。
2. 仅增加 behavior bridge 不足以改善最终 SID；raw Rec nDCG@10 接近 GenSAR，但 Rec H@10 和两个 Search 指标均明显落后。大比例 Sinkhorn 改派会进一步伤害 Rec，不能作为补救手段。

当前主要瓶颈已定位到 suffix latent construction，而不是 shared prefix。现有 suffix latent 为：

```text
delta_t = Enc_shared+LoRA_t(augment(x_common, x_task))
        - Enc_shared(x_common)
```

两个相近 encoder 输出相减后，初始 delta norm 极小；训练中 task gate 很快饱和到接近 1，但 Search target 仍只是 semantic reconstruction residual，并没有显式要求 suffix 保留 query-item relevance。Rec 虽然重构 behavior private residual，但低秩差分、bounded norm 和 RQ quantization 共同压缩了组内区分信息。因此 codebook 全局 usage 很高，最终 SID 在同一 prefix 内仍大量重合。

下一版不应继续调整 bridge 或提高 collision 权重。更直接的结构改进是：保持 frozen prefix 不变，把 suffix latent 改成由 `[x_common, x_task]` 产生的 direct private low-rank adapter，不再做两个 encoder state 相减；Search 端加入 query-item contrastive/relevance target，Rec 端直接保持 private behavior topology。uniqueness 约束只应作为每个 prefix 内的小权重正则，而不是后期 controller 主导目标。

## 20. M7b-v9：Direct Private Low-Rank Suffix + Query-Item Contrast

### 20.1 方法

v9 保持 v8 的 frozen semantic prefix 与 frozen behavior bridge 不变，只替换 suffix latent construction。它不再计算两个 encoder state 的差，而是直接从 shared latent 与 task view 产生 private latent：

```text
h_task = Proj_task(x_task)
u_task = [z_shared; h_task; z_shared * h_task; |z_shared - h_task|]
z_private^t = LN(W_up^t GELU(W_down^t u_task))

rank(W_down/W_up) = 32
suffix_t = RQ_t(z_private^t), [256, 256]
```

Search reconstruction target 显式加入聚合 query 信息：

```text
v_search = normalize(x_common + 0.5 * x_search)
r_search = v_search - Dec_sem(q_shared)
```

并增加对称 query-item InfoNCE：

```text
L_query-item = InfoNCE(search_full_recon, x_search)
```

Rec 仍重构 behavior private residual。其他目标包括 full-view reconstruction、in-prefix topology、shared/private cross-covariance、低权重 full-SID uniqueness、commitment 和 code usage balance。本轮不做 post-hoc Sinkhorn，直接评估 raw SID。

### 20.2 表示与 SID 统计

direct adapter 修复了 v8 的小 delta 问题：

| latent | norm mean | effective rank |
|---|---:|---:|
| shared | 2.43 | 12.56 |
| Search private | 19.49 | 18.58 |
| Rec private | 15.47 | 21.15 |

但 Search query supervision 产生了新的 prototype collapse：

```text
items                   = 19,999
unique Search queries   = 754
Search suffix usage     = 148/256, 86/256
Rec suffix usage        = 232/256, 241/256
```

| SID | duplicate | collided items | max bucket |
|---|---:|---:|---:|
| Search raw | 64.063% | 74.149% | 324 |
| Rec raw | 36.312% | 47.897% | 81 |

query-item loss 从 4.168 降至 2.635，说明 relevance objective 确实被优化；但大量 item 共享相同或高度相似的聚合 query，模型因而将它们压向少量 query prototype。Search 第二层 codebook 只使用 86 个 code，证明高 collision 不是容量不足，而是目标本身缺少 intra-query item discrimination。

### 20.3 公平下游结果

| SID | Rec H@10 | Rec nDCG@10 | Search H@10 | Search nDCG@10 |
|---|---:|---:|---:|---:|
| GenSAR faithful-core p256 | **0.077** | **0.0481** | 0.079 | 0.0453 |
| M7b-v7 anchored cross-view | 0.080 | 0.0456 | 0.036 | 0.0186 |
| M7b-v8 frozen anchor raw | 0.065 | 0.0467 | 0.026 | 0.0107 |
| M7b-v9 direct private raw | 0.066 | 0.0458 | **0.088** | **0.0527** |

v9 是当前第一次在相同下游协议中同时超过 GenSAR 的两个 Search 指标：H@10 提高 0.009，nDCG@10 提高 0.0074。它验证了显式 query-item relevance target 比仅重构 semantic residual 更适合 Search suffix。

但该结果不能直接作为“超过 GenSAR”的论文结论。Search duplicate 高达 64.1%，相同 SID 可能造成候选合并或命中放宽，从而抬高指标。必须在 collision 可比的 SID 或 unique-target test subset 上复验，才能确定真实提升。

### 20.4 下一步诊断

v9 将 Search relevance 与 item identity 都压在同一个 private latent 中，两个目标存在冲突：

```text
query relevance：共享 query 的 item 应接近
item identity：  共享 query/prefix 的 item 必须可区分
```

下一版应将 Search private latent 分成两个受控子空间：

```text
z_search = [z_relevance | z_item]

z_relevance <- query-item contrastive loss
z_item      <- common residual + within-prefix/within-query item discrimination
```

对比学习只作用于 relevance head，不直接把完整 suffix latent 拉向 query prototype；同时使用单条 query-item event 或 multi-positive contrastive，而不是只使用 item-level 聚合 query。RQ suffix 量化组合后的 private representation，并在同一 prefix、同一 query prototype 内加入条件区分目标。这样可以保留 v9 的 Search relevance 收益，同时恢复 item-level uniqueness。
